# wsm-077 SDK Gate.and2 / Gate.ok；XrplLatch

## objective

wasm v0 rejects `bitAnd` / `bitOr`, so entries cannot use `&&` / `||`.
SDK names that still extract as nested `if`:

- `Gate.u64Max` (named def, not `~~~(0)` in an entry body)
- `Gate.and2` / `Gate.and3` (nested `if`, not `Bool.and`)
- `Gate.ok v` (`v ≤ u64Max`) to sequence `flush*` / `storeOwner`

`XrplLatch` is HoldEsc credit/latch/unlatch as else-if guards
(`if !cond then .error`), not a then-pyramid. Sequential `flush*` stay
later guards so effects keep source order. Not Rust `?`.

Zero wasm params. Not `Sdk.Payments`. Not `Sdk.Map`.
Public still host -22 and tefBAD_AUTH.

digest `d65b586272018aed` (`Examples.XrplLatch`). Registry count 46.

Strategy: [xrpl-local.md](../analysis/xrpl-local.md).

## 不做什么

- 不在 wasm v0 开 `&&` / `bitAnd`
- 不把顺序 `flush*` 收成一个 AND（会打乱 persist Owner）
- 不开公开门面
