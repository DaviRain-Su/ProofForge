# l5-019 exact first Phoenix trader registration

## objective

按 Sokoban 0.3.0 的账户内 allocator 与 red-black tree 布局，实现 128-seat trader tree
从 canonical fresh empty state 到单个黑色根节点的第一次注册。成功边界不能留下 detached
allocator node，也不使用 SVM heap、Map、node copy 或持久 pointer。

## invariants

- 输入账户必须是 84,944-byte `(512,512,128)` body shape，trader header 必须是
  `root=0, padding=0, size=0, bump=1, free=1`
- 节点是 exact 144 bytes：packed left/right、packed parent/color、32-byte Pubkey、四个
  TraderState u64 balance 和八个 reserved u64；入口覆盖全部 18 个 words，不依赖旧 slot bytes
- 第一次 bump allocation 原子发布 `root=1, size=1, bump=2, free=2`；slot 1 是黑根、
  links/parent 为零、key 为四个输入 limb、TraderState/padding 全零
- guarded `Except` success branch 中的 21 个 ignored external-account writes 必须全部保留；
  state projection 不能吞掉 target effects
- non-fresh/错误 profile 以 `overflow` (`Custom(0x1001)`) 拒绝；readonly 或 wrong-owner
  store 以 `Custom(1)` 拒绝；所有失败保持账户 bytes 不变

## verification

- Lean IR 门精确计数 21 个 write effects，并覆盖 header cursor/size/root、18 个 node words
  与 guarded state continuation
- Mollusk 从预填 stale bytes 的 slot 开始，注册后逐 byte 等于 canonical expected account；
  `bodyEntryCount=1` 且 complete `traderTreeValid=1`
- nonempty、readonly、wrong owner、错误 seat profile 均原子失败；profile suite 13/13
- digest `e6a7a4e2393cc64f`；assembly 3,759,660 B；ELF 1,209,400 B；IDL 3,721 B
- Surfpool 1.5.0 用 1,196 个 Loader write + deploy + authority transactions 完成本地部署，
  并核对 exact 1,209,445-byte ProgramData；不用 `solana-test-validator`
- 全量 194-job Lean、50 个 SVM build、Mollusk 211/211 与 Anvil 12/12 回归通过

## non-goals

- 不实现第二个/一般 key 插入、free-list reuse、rotation/delete fixup 或 order-tree mutation
- 不开放 runtime account shape、remaining accounts、动态容量或完整 Phoenix-v1 instruction ABI
- 不声明公网部署，也不把 transient bump heap 当 persistent allocator
