# R5-014 — Integrate the bounded EVM ERC-1155 core

## Goal

Provide a reusable single-id ERC-1155-shaped balance and operator policy using the existing typed
hashed-map and UInt256 components, without claiming unbounded batches, receiver callbacks, or full
standard parity.

## Delivered contract

- `Evm.Sdk.Erc1155.Balances` is one compile-time `AddressPairMap256` from `(owner, tokenKey)` to a
  UInt256 balance. `Operators` is one disjoint `AddressPairMap` approval-flag namespace.
- The current map-key envelope accepts token ids only when the top UInt256 limb is zero. Every
  authorization and write predicate checks `canEncode` before `tokenKey` truncation. The checked
  SDK `Balances.balanceOf` facade owns the same pre-read gate; the lower
  `balanceOfEncoded` helper remains explicit about its precondition.
- Checked credit/mint reject UInt256 wrap; debit/burn reject underflow; transfer checks destination
  overflow and treats equal source/destination as a no-op after the debit gate.
- MultiToken owns immutable-minter and application error/event policy. CraftToken independently
  owns open mint, per-id capped supply, and supply accounting in a third typed namespace.
- No Runtime leaf, map kind, Ops/IR/Component/Emit recipe, selector/topic/offset constant, runtime
  allocator, hidden storage write, or protocol-specific emitter was added.

## Evidence

- The focused Lean target passes 164 jobs and pins the 192-bit envelope, disjoint namespace bases,
  alias rejection for every mutation/authorization predicate, the SDK-owned checked view gate, and
  consumer digests: MultiToken `1b6452b87efd2019`; CraftToken `5e5565fbbc6d9de2`.
- Structural extraction checks prove that the balance read remains behind the inlined SDK branch,
  CraftToken's named `maxPerId` remains the literal-limbed UInt256 operand of a packed comparison,
  and an unmarked irreducible Bool helper fails extraction instead of host-folding to `true`.
- solc 0.8.34 builds deployment bytecode of 8,847 bytes and 9,325 bytes respectively.
- Dedicated Anvil matrices cover alias rejection across views/auth/writes, credit overflow, debit
  underflow, authorization grant/revoke, same-address no-op, cross-owner movement, zero addresses,
  cap failure, burn/supply accounting, and post-revert state preservation.
- The integrated registry and aggregate Anvil runner build and run both consumers through the normal
  CLI path: 28/28 Anvil contracts pass and no one-off assembly driver remains.
- Because the hardening is target-neutral, Phoenix's source-level `expired` predicate now opts in
  explicitly with `@[pf_inline]`; the corrected Phoenix digest is `2dfc5d8abbd4a2e0`. All 57 SVM
  programs build, locked Mollusk passes 349/349, and Surfpool 1.5.0 deploys the exact 3,411,080-byte
  Loader-v3 ELF in 3,371 write transactions.

## Explicit boundary and follow-up

Batch transfer/balance/mint/burn, ERC1155Receiver callbacks, metadata URI, standard typed ERC-1155
events, unbounded inputs, and ids at or above `2^192` remain fail closed.

The extractor now unfolds a marked helper before nested component discovery, preserving helper-owned
control flow, and reduces UInt256 constructor projections after unfolding marked named constants.
Bool decoding unfolds only marked `@[pf_inline]` helpers: arbitrary host/runtime Bool definitions
cannot silently become host constants. These are generic extraction contracts rather than
ERC-1155-specific Ops, IR, or Emit cases.
