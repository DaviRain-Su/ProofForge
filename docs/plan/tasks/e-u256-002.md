# E-U256-002 — typed unsigned UInt256 comparisons

## Goal

Complete the unsigned comparison part of the EVM wide-word runtime contract without adding
relation-specific main-emitter recipes or asking source contracts to compare four limbs manually.

## Delivered contract

- `Evm.WideWord.Comparison` names `eq`, `lt`, `le`, `gt`, and `ge` without numeric operation tags.
- `WideWord.Query.compare256` carries eight fixed `UInt64` limbs through the existing
  `Component.wideWord` bridge; it has no storage, LOG, CALL, or allocation effect.
- `WideWord.Emit` packs each operand once and is the sole Yul relation interpreter.
- `Evm.Sdk.UInt256` exposes `eq`/`lt`/`le`/`gt`/`ge`; the established `atLeast` API and legacy
  `.ge256` canonical spelling remain intact so existing Token/Capped IR and artifacts do not drift.

This slice does not change default `UInt64` arithmetic and does not implement signed comparison,
bitwise operations, shifts, division, or modulo.

## Fail-closed and resource boundary

- Every comparison requires exactly two statically shaped `UInt256` values (eight limbs).
- Wrong component arity fails before Yul emission.
- The emitter uses only three temporary Yul words after normal operand materialization; there is no
  runtime buffer, storage handle, or allocator.

## Evidence

- Focused Lean build: 132 jobs (`Tests.WideSpec` + the full EVM build-spec registry gate).
- All 20 registered EVM contracts compile with solc 0.8.34.
- Anvil 20/20 passes; Wide covers equality/inequality and ordering across 64- and 192-bit limbs.
- The other 19 contracts retain byte-identical Yul/bytecode/ABI artifacts; only Wide changes to
  digest `6dc6f4b1aa89d707` and emits 12,898 bytes of Yul.
- Ownership and whitespace gates pass.
