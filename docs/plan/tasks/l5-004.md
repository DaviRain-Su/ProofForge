# l5-004 Token-2022 program id 切片

## objective

同一套 classic Token recipe，`programIx` 指向 Token-2022 账户。指令 0–24 字节不变。

带 transfer hook / transfer fee 的 mint fail-closed，直到 remaining accounts 和 TLV 读开了。没有 Token v3 程序。

规划：[analysis/token-2022.md](../analysis/token-2022.md)

## path

`Svm/Ops.lean`, `Svm/Runtime.lean`, `Extract.lean`, `Svm/Emit.lean`, `Examples/Token2022.lean`

## verification

- 独立例子把 `TransferChecked` 打到 Token-2022
- Token classic 例子 digest 不回退
- hook / fee mint 在 CPI 前因非 base `data_len` 失败，账户不发生变化

## result

- `CpiMeta.expectedDataLen` 是通用的 target-owned CPI 账户形状约束；发射器在调用前检查
  account header，不包含 Token-2022 特判。
- `token2022TransferChecked` 要求 source/destination 恰为 165B、mint 恰为 82B；因此当前
  classic-compatible slice 保守拒绝全部 TLV extension。
- 抽取器不再逐个列举 CPI recipe 名；所有 `ProofForge.Svm.Runtime` wrapper 统一递归展开到
  `invoke` / `invokeSigned` / `invokeSignedSeeds`，新增 wrapper 不再改白名单。
- Mollusk 真实执行 Token-2022 base `TransferChecked`；transfer-fee 和 enabled transfer-hook
  mint 使用 extension-aware builders，均以 `Custom(1)` 原子失败。
