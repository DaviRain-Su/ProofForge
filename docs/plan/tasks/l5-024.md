# l5-024 general bounded Phoenix trader insertion

## objective

用一个通用 fixed-capacity account effect 取代按第六、第七次继续展开的特例，在最小
128-seat Phoenix profile 上精确复现 Sokoban 0.3.0 的 allocator 与 red-black insertion。
持久状态只保留账户内 one-based node index，不把 Solana transient bump heap 当作持久树。

## invariants

- account、root/links/parent/key base、stride 与 capacity 都是编译期常量；本切片固定
  `acc1`, words `8310/8314/8315/8316`, stride 18, capacity 128
- store 前验证 writable、current-program owner、完整 RB tree、allocator header、live/free
  partition 与 key ordering；duplicate/full/malformed 在任何写入前失败
- search/fixup 深度有固定上限；rotation 只更新账户内 index/link/parent/color，不构造
  `Map`/`HashMap`、detached node、heap tree copy 或 persistent raw pointer
- bump path 与 free-list path 都完整清零并初始化一个 144-byte slot；free reuse 消耗
  one-based free head 而不推进 bump boundary
- key 按 Rust `[u8; 32]` lexicographic order 比较；duplicate 不采用 Sokoban map replace
  语义，而按 Phoenix trader registration 约束原子拒绝
- IDL 从 instruction effect 推导额外账户 writable flag，`registerTrader128.acc1` 不再被
  错误标成 readonly

- `lib-sokoban = 0.3.0` differential test 以 128-key permutation 填满全部 seat，每次插入后
  比较完整 18,464 account bytes，并验证 full/duplicate 原子失败
- 从官方 Sokoban 删除后的 free-head 状态起步，精确比较 free-slot reuse，并覆盖
  readonly、wrong owner、malformed 的完整账户 bytes 不变

- Phoenix profile Mollusk 22/22；全量 194-job Lean、50 个 SVM build、Mollusk 220/220、
