# R5-005 — EVM bounded payment facade adoption

## Goal

Make the contract-facing EVM SDK, rather than Runtime/ClosedCall/NativeFx source boundaries, the
stable owner that applications use for existing closed ETH, ERC-20, WETH, and fixed-router calls.

## Delivered contract

- `Evm.Sdk.Payments` owns the `Ether`, `ERC20`, `WETH`, and `UniswapV2` namespaces. The public names
  retain their prior types and erase through `pf_inline` to the existing target Runtime leaves.
- `Context.selfLow` exposes the existing scalar `ADDRESS` leaf without making applications select
  a Runtime name or reconstruct it from a three-limb Address.
- Vault consumes SDK Storage and bounded payment names; TipJar consumes SDK Context/Ether/Event;
  Ownable consumes SDK Address/Context/Immutable/Revert/Event/Storage. All three application
  modules import only `ProofForge.Evm.Sdk`.

The Runtime, `Component.closedCall` / `Component.nativeFx`, `CallResult`, payable plan, and emitters
remain the only owners of CALL/STATICCALL success, exact/empty-or-nonzero returndata, call-value,
LOG, and revert semantics. No selector, topic, error code, map geometry, or calldata recipe is
copied into the SDK or applications.

## Fail-closed boundary

The component exposes only the already modeled closed calls. Arbitrary calldata/callee selection,
unbounded returndata, `delegatecall`, CREATE/CREATE2, code-existence policy, revert bubbling, and
pull-payment/multicall remain unavailable. The facade does not imply reentrancy protection; a guard
still requires provable lock-write → external-CALL → clear effect ordering.

## Evidence

- Focused SDK/application/extraction/build suites pass and retain TipJar `754276e8063a7d08`, Vault
  `a3ea1b5b2a69c0e3`, and Ownable `ce6397521bd115fa` canonical IR digests.
- All nine TipJar/Vault/Ownable Yul, ABI, and deployment-bytecode artifacts are byte-identical to
  the pre-adoption baseline.
- No EVM Runtime/Ops/IR/Component/Emit/Extract file changes. Anvil is not repeated because the
  executed deployment bytecode is byte-identical.
