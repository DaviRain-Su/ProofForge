# R3-005 — SVM non-seeded System facade completion

## Goal

Complete the fixed-account, non-seeded System Program source surface in `Svm.Sdk.System` without
adding a second instruction representation or teaching extraction/emission any operation name.

## Delivered contract

- `assign` changes external account 0 to the current program owner under fixed signer/writable
  geometry.
- `allocate` allocates a scalar `space` value on external account 0 under the same geometry.
- `advanceNonce` fixes nonce/recent-blockhashes/authority/System account ordering and privileges.
- SysAlloc and Nonce consume only these SDK names. Together with R3-004's `transfer` and
  `createAccount`, the non-seeded System wrappers now have one source owner.

Every function is `pf_inline` and delegates to the existing Runtime wrapper. There is no new
descriptor, Ops/IR/Component/Emit case, Extract change, account table, allocator, or pointer.
Seed-derived System instructions remain separate because their current Runtime surface hardcodes
the `"vault"` seed and is not yet an honest generic SDK contract.

## Evidence

- Focused SDK/example/spec and the existing SysAlloc/Nonce tests pass; extracted IR matches the
  canonical registry digests.
- SysAlloc and Nonce produce six assembly/ELF/IDL artifacts byte-identical to the pre-facade
  baseline. No other program or shared lowering file changes.
- The aggregate gate contains 287 jobs after importing the focused spec. Machine artifacts are
  unchanged, so Mollusk and Surfpool are not repeated; Surfpool remains the only deployment
  qualification environment.
