# R5-020 — Shared checked wide-to-UInt64 casts

Date: 2026-08-31
Status: done

## Goal

Provide allocation-free checked narrowing from the shared `UInt128` and `UInt256` values to
`UInt64`, with OpenZeppelin SafeCast-style explicit failure but without misclassifying pure limb
policy as an EVM opcode, Runtime leaf, storage operation, or EVM-only SDK component.

## Delivered contract

- `Core.SafeCast.UInt128.toUInt64` accepts exactly values whose discarded `w1` is zero.
  `Core.SafeCast.UInt256.toUInt64` accepts exactly values whose `w1 ||| w2 ||| w3` is zero. Every
  discarded bit therefore dominates access to the successful low-limb result.
- Both helpers are ordinary `@[pf_inline]` Lean returning `Except ε UInt64`; the caller supplies
  its typed error. They allocate no buffer, write no state, emit no terminal, and add no Runtime,
  Ops, IR, Component, Extract, or Emit case. Both target SDK umbrellas expose the same shared
  source helper while retaining separate ABI/storage/account bindings.
- `EvmSafeCastAccumulator` is a permissionless UInt256 consumer with distinct `amountTooWide` and
  checked-add `sumOverflow` policy. `EvmSafeCastConfig` independently applies owner authorization,
  UInt128 narrowing, and zero rejection before replacing one UInt64 field. Application policy and
  literal state writes remain under `Examples`.
- This slice deliberately publishes only the required UInt64 target. Signed casts, wide-to-wide
  downcasts, UInt32/16/8 targets, saturating casts, and a common arithmetic-error vocabulary remain
  separate consumer-driven work rather than speculative API surface.

## Evidence

- Focused Lean host truth tables cover zero, exact UInt64 max, the first discarded limb, and each
  farther UInt256 limb. Extraction guards prove the low limb is bound only inside a branch whose
  condition references every discarded limb, pin both state layouts/ABIs/digests, and reject an
  unexpected target component on the pure accumulator path.
- EvmSafeCastAccumulator digest is `6ce227535c3ff7e9`; Yul is 4,232 bytes and deployment bytecode
  is 421 bytes. EvmSafeCastConfig digest is `84871272081c4609`; Yul is 7,570 bytes and deployment
  bytecode is 1,206 bytes.
- Dedicated Anvil matrices cover zero, exact max, just-overflow, every discarded UInt256 limb,
  independent checked-add overflow, owner ordering, application-specific zero policy, and raw
  storage atomicity after every rejected transaction. Both contracts are part of the 40-contract
  clean EVM manifest and aggregate Anvil gate; the aggregate Lean gate passes 406 jobs.

## Boundary

The helper is shared value policy, not a claim that SVM and EVM have one physical integer or error
ABI. EVM consumers use canonical Solidity `uint128`/`uint256` calldata and named reverts; future
SVM consumers must use their independently qualified Borsh/entry/return contract. No hidden
allocation, pointer, dynamic Map, unchecked truncation, or target-specific magic number is exposed.
