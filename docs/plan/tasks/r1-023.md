# R1-023 — Preserve static wide result frames after effects

Date: 2026-08-31
Status: done

## Goal

Make compiler-owned fixed wide values use the generic boundary-frame contract even when SVM
component effects precede their construction, and reject any Extract-to-CFG result-frame mismatch
instead of silently serializing only the first limb.

## Delivered contract

- Shared `UInt128` and `UInt256` are registered through the existing representation-free
  `@[pf_boundary]` mechanism. Their constructors therefore reuse generic static field projection:
  no UInt128 Runtime leaf, Ops/IR constructor, component, or Emit recipe was added.
- An effect-prefixed constructed `UInt128` now ends in two explicit scalar returns; `UInt256` ends
  in four. Core CFG joins each frame into `returnU64s`, and the SVM return-data adapter publishes
  exactly 16 or 32 little-endian bytes.
- `Svm.IR.Method.toCFG` validates every successful non-init exit against `retCount`. A truncated
  scalar tuple or a residual `returnState` in a getter fails compilation; the backend never guesses
  omitted leaves from neighboring locals because component continuations may reuse local indexes.
- Fixed-width dynamic array elements, nested dynamic results, recursive values, and unbounded
  containers remain unsupported. This slice changes static scalar result framing only.

## Evidence

- `Tests.SvmWideReturnSpec` independently composes existing `Transient.Record64` component effects
  into constructed UInt128 and UInt256 results. It pins source Ops, projected CFG leaves, 8/16/32
  byte return-data emission, a normal scalar return, truncated-frame rejection, and rejection of
  the former implicit `returnState local0` shape.
- `lake build Tests.SvmWideReturnSpec` passes 176 jobs; the full `lake build Tests` gate passes 407
  jobs. Ownership, no-sorry, and whitespace checks pass.

## Boundary

`@[pf_boundary]` describes a finite logical source value, not a shared SVM/EVM wire layout. SVM
still owns return-data serialization and EVM still owns ABI encoding. No pointer, heap allocation,
dynamic Map/Array, storage write, or application-specific policy is introduced.
