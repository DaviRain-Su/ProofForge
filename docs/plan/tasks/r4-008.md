# R4-008 — Stabilize full-width EVM environment component boundary

## Goal

Move the existing full-width gas/base-fee/randomness/gas-limit lowering behind the generic EVM
Component query bridge, so future environment capabilities extend one target-owned module rather
than adding another top-level Ops/IR/main-Emit constructor.

## Delivered contract

- `Evm.Environment.Query` owns `gasLeft256`, `baseFee256`, `prevRandao256`, and `gasLimit256` with
  a checked four-limb result contract and zero operands.
- `Evm.Environment.Emit` is the sole component interpreter. It captures each EVM word once,
  records it in the generic wide-value cache, and projects four allocation-free UInt64 limbs.
- Extract now lowers the existing `Runtime` / `Sdk.Context` source facades to
  `Val.ext (.component (.environment ...))`; EVM Ops, IR, CFG, and the main emitter only traverse
  their existing generic Component bridge.
- The old top-level value constructors and emission cases remain temporarily as legacy Golden /
  compatibility input, but production source extraction no longer creates them.
- The component preserves the old canonical strings and cache keys. EvmCtx and TipJar IR digests,
  Yul, ABI, and bytecode remain byte-for-byte unchanged.

This slice adds no opcode capability, storage, call, allocation, pointer, or application policy.
It establishes the stable ownership boundary for later bounded `coinbase` / `blockhash` / code
queries.
