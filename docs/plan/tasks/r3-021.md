# R3-021 — Isolate two same-kind transient handles

## Goal

Remove the one-active-handle-per-container-kind ceiling without exposing pointers, introducing an
unbounded allocator, or copying Vector64 and Bytes lifecycle assembly.

## Delivered contract

- `Transient.Vector64.bounded` and `.boundedAlt` select compile-time slots 0 and 1. The same pair is
  available as `Transient.Bytes.bounded` and `.boundedAlt`.
- `Svm.Sdk.Transient` owns one erased handle-word contract: the low 32 bits carry bounded payload
  capacity and the upper field carries a statically validated slot. Slot 0 preserves the historical
  plain-capacity encoding; slots at or above 2 and zero payloads fail component validation.
- `Svm.Transient.Emit` owns one 32-byte metadata-bank stride. Each slot has private pointer, length,
  capacity, and active cells; every `begin` obtains a separate bounded allocation from the same
  official-shaped downward bump heap.
- Push/get/set/pop/truncate/clear/finish and active/capacity checks select only the source handle's
  slot. Finishing one slot does not reclaim heap memory or invalidate the other slot.
- Vector64 and Bytes retain distinct element semantics and error vocabularies. No Runtime leaf,
  top-level Ops/IR/main-emitter recipe, source-visible address, account-state pointer, realloc, or
  reclaiming free was added.

## Evidence

- `Examples.TransientPair` is an independent non-Phoenix consumer registered at target-IR digest
  `899815d9f910e597`; assembly is 98,699 bytes and linked ELF is 31,520 bytes.
- Focused Lean builds cover distinct erased words, slots 0/1, disjoint metadata cells, malformed
  slot/payload rejection, effect order, and unchanged MemoryOps digest `96f938c65992b93a`.
- Focused Mollusk passes 36/36 across TransientPair 7/7, MemoryOps 15/15, and AccountView 14/14.
  Runtime checks cover two same-kind vector payloads, two same-kind byte payloads, all four handles
  in one invocation, lifecycle isolation, inactive alternate slots, and cross-slot heap OOM.
- The worker's complete locked Mollusk suite passed 347/347 before coordinator aggregation; the
  integrating branch separately rebuilt the registered consumer and focused runtime matrix.

Two slots per kind are the current explicit resource ceiling. Generic POD elements, record writers,
more manifest-bounded slots, insert/remove-at/iteration, and persistent pointers remain fail closed.
Surfpool remains the only deployment qualification environment; this SDK slice adds no Test
Validator path.
