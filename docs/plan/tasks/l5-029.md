# l5-029 account-resident storage backend boundary

## objective

在 source operation 与 sBPF emitter 之间增加 target-owned `Svm.AccountStorage` 层，承载
固定容量账户存储的静态 geometry、索引规则、effect summary 和后端例程。先把
`accDataWordSetAt` 迁入该层，证明以后扩展 allocator、tree/map、queue 与 extraction routine
时，不必继续增加顶层 SVM IR constructor 或修改主 emitter 的底层 store 逻辑。

## invariants

- persistent region 只有编译期固定 account/base/stride/capacity；索引基数显式选择
  zero-based 或 one-based，Phoenix/Sokoban 后续使用 one-based index 与 `0` sentinel
- storage call 只携带 scalar values；不表示 heap object、raw pointer、copied node、runtime
  capacity 或 detached tree
- `Call` 自己拥有 value map/traversal、well-formedness、canonical digest spelling、minimum
  account count 与 transitive read/write effects；generic extraction/IR/IDL plumbing 不枚举具体
  storage routine
- `AccountStorage.Emit` 自己拥有 authorization、index normalization、bounds 与 store
  assembly；主 `Svm.Emit` 只提供 walked-account frame/value-loader callback 并 dispatch 一次
- source `accDataWordSetAt` spelling 与 canonical digest 保持兼容；迁移不得改变既有 ELF、
  IDL 或 runtime semantics
- writable IDL 由 `EffectSummary.writes` 推导，不再为 word-store 增加 constructor 白名单

## verification

- guards 覆盖 zero/one-based geometry、account effects、source→target projection 与既有
  Phoenix fixed-stride writes
- `PhoenixV1Profile` canonical digest 保持 `e9966de4a1795a47`；assembly 4,652,144 B、
  ELF 1,489,088 B、IDL 7,613 B
- `lake build Tests` 196 jobs、50 个 SVM build、Mollusk 230/230 与 Anvil 12/12 全绿
- Surfpool 1.5.0 用 1,472 个 Loader write + deploy + authority transactions 完成本地部署，
  并核对 exact 1,489,133-byte ProgramData；不用 `solana-test-validator`

## next migration

先把 `accDataParentPathValid` 迁成返回 scalar 的 bounded storage routine，验证固定上界循环
也能只通过 generic bridge；再收拢 shared RB validation/search/allocator/rotation/transplant/
fixup。业务级 order reduction/deposit/placement 保留 semantic action，但由这些 reusable
storage routines 组合，不再新增一整段 bespoke emitter。

## non-goals

- 本切片不声称现有 RB insert/remove/deposit 已经迁移；它们仍是下一批 acceptance slices
- 不把 Rust transient bump heap 用作 Phoenix account allocator，也不开放普通 `HashMap`
- 不改变 Phoenix wire ABI、matching/placement 行为、remaining accounts 或 Token-2022
  extension semantics
