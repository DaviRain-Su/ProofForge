# l5-006 Sokoban 节点 + 定长 Vector

## objective

官方红黑树节点摊成 `Vector Node n`。`Node` 是用户 structure，物理顺序跟 Sokoban 一致：left / right / parent / color / key / value。`SENTINEL = 0`，地址 1-based。

除布局和 `nodes[0].value` 外，本切片随后补齐动态叶读写、两节点 insert smoke、
Sokoban 对齐的 N=4 bump/free-list allocator，以及完整左右旋。allocator 使用一过尾
标记 5，release 后按 LIFO 地址复用；旋转统一接收 1-based 地址，并维护 root、祖父边、
inner child parent 和升降节点的双向 parent/child 关系。

## path

`Extract.lean`, `Examples/Tree.lean`, `Golden.lean`

## verification

- `#pf_build Examples.Tree` 槽含 `nodes_0_value` … `nodes_3_value`
- `getHead` 抽出 `nodes_0_value`
- `allocNode` / `releaseNode` 对同一动态元素的六个叶子正确 writeback
- 连续分配地址 1..4；释放 1、2 后按 2、1 顺序复用
- root / non-root、inner child 非空和左右两个方向的旋转都保持双向链接
- 每条旋转执行路径最多 6 次动态叶写；拒绝 payload 读取造成的指数重复写
- allocator 的静态 `size/bumpIndex/freeHead` 与动态节点写在同一 commit 中保留
- root write 的 IR 值必须仍引用入口 `.arg 0/1`，拒绝 inline helper 参数偏移
- 真实源账户为 232 bytes，assembly 小于 300 KB 且无重复 label
- Nested dest 跟 `book_size`；Pair / Phoenix digest 不回退
