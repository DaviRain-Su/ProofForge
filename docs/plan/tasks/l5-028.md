# l5-028 fixed-capacity Phoenix trader deposit

## objective

为最小官方 Phoenix-v1 profile 增加 trader get-or-register deposit primitive。按官方
`TraderState` 的 12-word / 96-byte 布局，在账户内 128-seat Sokoban tree 中查找 32-byte
Pubkey：已有 trader 原子累加 quote/base free lots，不存在时注册 canonical zeroed state
并初始化两个 free balance。持久结构不使用 heap Map、raw pointer 或 copied tree。

## invariants

- account、root/links/parent/key base、18-word stride 与 128 capacity 均为编译期常量；
  运行时只携带四个 Pubkey limbs 和 quote/base lots
- node 的 links/parent/key 固定在 `+0/+1/+2..+5`；`TraderState` 固定在 `+6..+17`，
  quote/base free 分别是 state words 1/3，其余 locked/reserved words 保持 canonical
- writable、current-program owner、data length 与完整 tree/free-list partition 在第一次
  store 前验证；existing lookup 在 capacity check 前完成，因此满树仍可向已有 trader
  deposit，而满树新 key 返回 full
- 已有 trader 的 quote/base checked-add 都在任一 store 前完成；任一 overflow 不得留下
  单边 balance 更新
- 新 slot 先完整清零，再写 key 与 free balances并执行通用 RB insertion/fixup；allocator
  继续使用 one-based index，`0` 只作 sentinel
- effect 在 extraction、target projection、CFG mapping/canonicalization、static geometry、
  writable IDL 与 legacy fail-closed 路径中保持显式；源码入口不展开 topology writes
- emitter 只保留有界 scalar index 与临时 account-derived pointer，不创建 persistent
  pointer、detached node、heap tree 或无界容器

## verification

- Lean guard 钉住 exact `8310/8314/8315/8316` geometry、stride 18、capacity 128、零个
  展开 `accDataWordSetAt`、writable IDL 与 emitter 双 checked-add-before-store 形状
- 测试直接依赖 `lib-sokoban = 0.3.0`：128 个 trader 逐个 get-or-register 并在每个
  allocator size 重复 deposit；每次比较完整 18,464 tree bytes 并调用官方
  `is_valid_red_black_tree()`
- 满载 existing-key 成功、absent-key full，以及 quote/base overflow、readonly、wrong owner
  与 malformed topology 均验证原子性
- digest `e9966de4a1795a47`；assembly 4,652,382 B；ELF 1,489,088 B；IDL 7,613 B
- Surfpool 1.5.0 用 1,472 个 Loader write + deploy + authority transactions 完成本地部署，
  并核对 exact 1,489,133-byte ProgramData；不用 `solana-test-validator`
- 全量 194-job Lean、50 个 SVM build、Mollusk 230/230 与 Anvil 12/12 回归通过

  ownership 或无界 transient container
