# R5-001 — Establish reusable EVM access policy

## Goal

Move owner, pause, and two-step ownership policy out of protocol-shaped contracts and into the
public `Evm.Sdk` surface. The component must compose existing Address, Context, Revert, and static
state lowering without adding an Access opcode, policy IR node, hidden storage write, selector,
slot magic number, or Emit recipe.

This is the Access foundation of R5, not completion of the EVM SDK. Bounded roles depend on static
storage declarations; a sound reentrancy guard depends on the typed external-call result contract.
Asset ledgers and NFT shapes remain later slices.

## Delivered contract

`Evm.Sdk.Access` provides:

- reusable owner and running gates plus the existing closed Unauthorized/Paused terminals;
- canonical running/paused flag values;
- `Access.Ownership`, a fixed single-pending Address with nominate, cancel, consume, and query
  operations;
- explicit replacement values: the consumer owns and writes its owner, paused, and pending fields.

The sole pending address is ordinary static state: three EVM words in the current Address binding.
Replacing a nomination invalidates the previous nominee; accepting or cancelling clears all three
limbs. There is no hashed nomination map, loop, allocation, runtime-selected slot, or hidden write.

The public `ProofForge.Evm.Sdk` module is now an umbrella over `Sdk.Base` and `Sdk.Access`.
Applications import `ProofForge`, not Access internals or target Ops/IR/Emit modules.

## Consumers and regression hardening

- `Examples.Evm.TwoStepCounter` composes owner/running gates, two-step ownership, pause, and checked
  counter policy.
- `Examples.Evm.Credits` independently composes the same Access component with a typed UInt256 credit
  map and claim flow.
- Both Anvil matrices nominate A, replace A with B, prove A cannot accept, let B accept, and verify
  the pending address is cleared.
- IR guards require transfer to store every candidate Address limb and accept to store the owner
  while clearing every pending limb to zero.

The slice also fixes two generic extraction holes exposed by ordinary SDK composition:

1. a direct one-field update of a declared multi-field State is emitted as a real store, without an
   artificial always-true comparison in source;
2. wide aggregate diffing compares complete leaf paths, so `candidate.w0` is not mistaken for the
   unchanged `ownership_w0` field. Scalar nested-state normalization keeps its established path
   rule.

Pair's digest changes on both targets, and Nested's digest changes on SVM, because their previously
omitted direct stores are now present. No target operation or emitter case was added.

## Resource and fail-closed boundary

- Access gates and nomination operations are O(1).
- Ownership occupies exactly one fixed Address and has no dynamic storage namespace.
- Zero nominees fail through the existing ZeroAddress terminal; unauthorized and paused paths use
  the existing closed error set and leave state unchanged.
- Roles, reentrancy, arbitrary external calls, proxies/delegatecall, and asset standards are not
  implied by this slice.
