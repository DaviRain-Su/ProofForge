# R3-026 — Persistent bounded SVM bit set

Date: 2026-08-30
Status: done

## Goal

Bind the shared packed `BoundedBitSet` policy to fixed Solana account words as a reusable SVM SDK
component, without adding a bit-set opcode, Runtime leaf, IR variant, Component case, emitter
recipe, allocator, or persistent pointer.

## Delivered contract

- `Core.Collections.BoundedBitSet` now owns the target-neutral bounds, word-index, mask,
  contains, insert, remove, and toggle word laws. Existing EVM `StorageBitmap` and the new SVM
  binding delegate to that single policy while retaining separate physical storage descriptors.
- `Svm.Sdk.StorageBitSet.BitSet` binds a compile-time bit capacity to exactly
  `(bits + 63) / 64` consecutive one-based `UInt64` fields in one program-owned account. The
  descriptor and capacity erase during extraction; no runtime length, heap object, pointer, or
  slot allocator enters account state.
- `contains`, `insert`, `remove`, and `toggle` check `index < bitCapacity` before computing the
  selected word. Each in-range operation reads at most one word and each mutation writes at most
  that word. An out-of-range index performs no account access and cannot alias a lower or partial
  final-word bit. Bulk clear and enumeration remain unavailable because they require an explicit
  capacity-bounded application policy.
- `Examples.FeatureBits` independently chooses idempotent enable/disable and resulting-membership
  toggle policy at capacity 128. `Examples.ClaimBits` chooses one-time claim/replay policy at
  capacity 130, exercising a partial final word. Protocol policy and named errors remain in
  `Examples`; current SVM named source errors still share generic `Custom(1)` on chain.
- Closed compile-time Nat division is now evaluated by the generic static descriptor extractor,
  allowing word count to derive from bit capacity instead of requiring callers to repeat a magic
  physical count. This changes no runtime operation or target effect.

## Evidence

- Focused Lean guards cover exact capacities/word counts, descriptor validity, all 63/64 and
  128/129 boundaries, shared packed-word truth tables, and both extracted programs.
- Focused Mollusk passes 3/3. It covers cross-word and partial-final-word membership, idempotent
  enable, disable/toggle, replay/OOB rollback, non-aliasing OOB access, and fail-closed short
  storage accounts.

- Surfpool 1.5.0 deployed the exact FeatureBits ELF through 13 ordinary Loader-v3 write

## Boundary

V1 stores only packed Bool membership addressed by a checked UInt64 index. It does not provide
enumeration, a live-count header, set algebra, dynamic capacity, account initialization/versioning,
runtime-selected account geometry, or a persistent heap collection. A reusable enumerable Set is
a separate bounded account-layout contract, not an excuse to add a container emitter case.
