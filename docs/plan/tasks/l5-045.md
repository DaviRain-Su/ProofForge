# l5-045 — bounded Borsh option entry plans

Status: **done**

## Scope

Add a reusable target-owned entry-adapter plan for variable-length Borsh payloads whose
optional scalar fields have compile-time-known widths. Keep codec policy out of generic
Ops/IR and component emitters, reject every non-canonical wire spelling, and prove the
adapter against a raw sBPF probe before using it for Phoenix `CancelUpTo`.

## Delivered

- Added `@[pf_svm_raw_borsh_options tag accountCount programAccount prefixParamCount
  [option widths]]`. The extractor projects it as `svm.raw.v2` metadata and checks the
  method shape: fixed scalar prefix followed by one `(presence, value)` pair per option.
- Extended the entry-adapter plan with static option widths and derived fixed-parameter,
  minimum-length, and maximum-length geometry. Route overlap checks now cover the complete
  generated instruction-length interval rather than one fixed length.
- Centralized variable-wire emission in `ProofForge/Svm/EntryAdapter/Emit.lean`:
  - finite `[minDataLen, maxDataLen]` route gate;
  - a bounded cursor with a payload-end check before each `Some` read;
  - only Borsh discriminants `0` and `1` accepted;
  - canonical zeroed presence/value locals for `None`;
  - exact final cursor consumption, rejecting trailing bytes.
- Made current-program executable-account authentication locate the program key from the
  actual serialized instruction length. Fixed and variable entry plans therefore share
  one authentication path without adding a generic codec Op.
- Added the `RawEntry` tag-8 probe with wire
  `tag || side:u8 || Option<u64> || Option<u32> || Option<u32>`. Runtime coverage exercises
  all eight presence combinations, each invalid discriminant, every truncated `Some`
  payload, and trailing bytes.

The stable boundary remains:

```text
source annotation -> bounded EntryAdapter.RawEntry plan -> adapter-owned emitter -> sBPF
```

Generic executable Ops, CFG, and the main emitter still expose only the existing component
bridge; protocol-specific codecs do not become user-selectable low-level instructions.
