# l5-002 Phoenix bounded N=4 IOC / TIF / 费用结算

## objective

Phoenix ask-side IOC 按红黑树中序的四个固定档做 price-time FIFO 扫描，同时覆盖
slot/time TIF、跨档整单/部分成交和聚合 UInt64 费用结算。

本切片交付固定 N=4 的规范红黑拓扑见证、中序跨档扫描、严格 `<` TIF、过期解锁、
余额和 `unclaimedFees` 记账，以及非零成交的 Token `TransferChecked` CPI。链上用
state-carrying bounded fold，不按四档展开控制流。

## path

`Projects/Phoenix.lean`, `Tests/PhoenixSpec.lean`, `Golden.lean`

## verification

- 第一档超限或无流动性成功返回 0
- slot/time deadline 相等有效，当前值严格更大才过期
- 过期档取消并继续；整档成交继续，部分成交停止
- quote/base locked/free 和 `unclaimedFees` 与聚合上取整一致
- loop body 保留动态 `sizes` store，循环后才 commit/return
- `#pf_build Projects.Phoenix` 绿

## 非目标

动态红黑树 allocator/旋转、bid book、trader tree、u128 client id、self-trade、
seat lifecycle 和事件批次仍属于完整 Phoenix-v1 账户实现，不在 bounded N=4 内。
