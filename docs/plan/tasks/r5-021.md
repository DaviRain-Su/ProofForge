# R5-021 — Checked wide-to-UInt32 casts

Date: 2026-08-31
Status: done

## Goal

Extend the shared allocation-free SafeCast boundary from UInt64 to UInt32 and make fixed scalar
`Except` results use one generic Extract bind path, without adding a target opcode, runtime effect,
storage operation, or width-specific lowering recipe.

## Delivered contract

- `Core.SafeCast.UInt128.toUInt32` first requires `w1 == 0`; `UInt256.toUInt32` first requires
  `w1 ||| w2 ||| w3 == 0`. Both then require `w0 < 2^32` before the explicit narrowing conversion.
  The first non-representable value is named once at the shared policy boundary rather than copied
  into applications. Both helpers return the caller's typed error and perform no allocation,
  terminal, effect, or state write.
- Extract's `Except` do-bind continuation now uses the shared `isScalarResult` classification
  instead of recognizing only `UInt64`. This enables fixed `UInt8/16/32/64`, Bool, and registered
  scalar/newtype results through the same checked monadic path. Ordinary let/state/effect
  normalization remains unchanged, so existing SVM programs and Phoenix keep their canonical IR.
  The change adds no Ops, IR, CFG, Component, Runtime, or Emit case and does not invent a dynamic
  integer representation.
- Existing consumers were extended rather than adding single-use fixtures.
  `EvmSafeCastAccumulator.setCheckpoint` is permissionless UInt256→UInt32 replacement with distinct
  width and zero-policy errors. `EvmSafeCastConfig.setWindow` independently orders owner
  authorization, UInt128 narrowing, zero policy, and its literal UInt32 state write. Existing
  UInt64 methods remain available and preserve their independent arithmetic/application policy.
- This slice deliberately does not publish UInt16/UInt8 or signed casts without a consumer.
  Saturating casts, wide-to-wide downcasts, and a common arithmetic-error vocabulary remain
  separate consumer-driven work.

## Evidence

- Focused Lean host truth tables cover zero, exact UInt32 max, the first low-limb overflow, and
  every upper limb. Extraction guards prove every upper-limb test and the exact `w0 < 2^32` gate
  dominate the narrowed local bind, and pin both updated state layouts, ABI, and IR digests. The
  focused gate passes 179 jobs; the aggregate Lean gate passes 411 jobs. `Tests.BuildSpec` also
  confirms PhoenixV1Profile retains canonical digest `af159cb894745102` after the bind boundary is
  kept narrow.
- `EvmSafeCastAccumulator` digest is `73c4372a4ba073f1`; Yul is 6,512 bytes and deployment bytecode
  is 838 bytes. `EvmSafeCastConfig` digest is `cf772a9876147a45`; Yul is 12,073 bytes and deployment
  bytecode is 1,856 bytes.
- Dedicated Anvil matrices cover both UInt64 and UInt32 exact boundaries, low-word `2^32`
  overflow, every upper limb, authorization/application-policy ordering, and raw-storage atomicity
  after rejected transactions. The clean EVM build validates all 40 registered contracts against
  the actual artifact manifest, and aggregate Anvil runs 40/40 with no skips.

## Boundary

The cast helper and fixed-scalar bind classification are target-neutral language/SDK policy, not a
claim that SVM and EVM share ABI, storage, account, or error representation. EVM consumers use
canonical Solidity wide calldata and named errors; a future SVM consumer must use its separately
qualified entry/result plan. No heap value, pointer, dynamic Map, unchecked truncation, or numeric
width sentinel is exposed to contract applications.
