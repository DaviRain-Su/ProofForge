# R3-015 — shared transient-container lifecycle emitter

Date: 2026-08-29
Status: done

## Goal

Remove the duplicated allocator/handle-lifetime assembly from the source-visible SVM transient
vector and byte buffer without changing either component's API, IR, errors, emitted assembly, or
runtime behavior.

## Delivered

- `Svm.Transient.Emit.Lifecycle` names one target-owned pointer/length/capacity/active metadata
  frame together with its active marker and OOM/state terminal errors.
- One shared interpreter now emits official-shaped downward bump allocation, active/capacity
  validation, logical clear, and non-reclaiming finish.
- `TransientVec.Emit` and `TransientBytes.Emit` retain only element-specific behavior: u64/byte
  indexing, range checks, fixed-width append, and component-specific bounds errors.
- Both components still lower through the generic `Component` bridge. No top-level Ops, SVM IR,
  CFG, main-emitter, source API, pointer-valued source term, or persistent account representation
  was added.

## Resource and failure contract

- The concrete component still supplies compile-time `FixedVec` geometry and disjoint stack cells.
- The shared begin path rejects malformed fixed-vector descriptors before assembly and propagates
  each component's existing runtime OOM code.
- Every operation still checks the exact active marker and source-handle capacity before touching
  payload memory.
- `clear` retains the allocation; `finish` invalidates metadata but does not reclaim the Solana
  bump heap.
