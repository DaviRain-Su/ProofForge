# R4-014 — Add an exact EVM calldata-length observation

## Goal

Expose Solidity `msg.data.length` through the stable Environment Component boundary without
turning raw calldata, a memory pointer, or an unchecked byte reader into a source value.

## Delivered contract

- `Evm.Sdk.Context.calldataSize : UInt64` exposes the exact `CALLDATASIZE` result within
  ProofForge's protocol-bounded UInt64 resource envelope.
- The zero-operand Environment query is read-only and allocation-free. It emits one
  `calldatasize()` observation for the source method and creates no storage, memory, log, or call
  effect.
- Extraction lowers both direct returns and nested scalar use through `Component.environment`.
  Generic Ops, target IR, CFG, and the main EVM emitter gain no calldata-specific constructor.
- This slice does not expose calldata bytes. Canonical typed ABI decoders remain the only ordinary
  source route for calldata contents; a future raw-byte view still requires an explicit capacity,
  range gate, and copy/lifetime contract.

## Evidence

  `Tests.EvmCtxSpec` pins the SDK delegation.
- The EvmCtx Anvil gate verifies that a zero-argument ABI call observes exactly four selector
  bytes.
