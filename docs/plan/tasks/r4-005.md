# R4-005 — Ordered static UInt64 storage effect

## Goal

Provide the real EVM effect needed when a static value must become visible before an external CALL.
Ordinary immutable Lean `State` writeback happens only at successful method completion and cannot
soundly model a reentrancy lock.

## Delivered contract

- `Evm.StaticStorage.Call.storeU64` is an ordered target component effect. Generic EVM Ops, IR, CFG,
  and the main emitter continue to cross the existing `Component.Call` bridge once.
- `Storage.Static.Handle UInt64.storeNow` is the contract-facing API. Applications supply a typed
  compile-time handle; they never supply a slot number.
- Extraction reduces compiler-erased handle projections to a static field name. An empty/dynamic
  name fails operation well-formedness. Emission resolves the name against the concrete program
  slots and rejects unknown fields or any width other than 8 bytes.
- The component is deliberately distinct from ordinary `.storeField`, so immediate effects do not
  alter final State-write detection or method result semantics. Lexical traversal preserves
  `store entered → closed CALL → store not-entered`.

`Examples.Evm.EvmOrderedStorage` is the minimal integration consumer. This slice does not publish a
ReentrancyGuard policy or claim that arbitrary calls are available; that policy is the next SDK
slice and will compose this effect with the existing closed-call surfaces.

## Resource and rollback boundary

The handle contains compile-time descriptor data only. There is no runtime slot allocator, raw
slot API, heap object, dynamic map, hidden final-state write, or new top-level Ops/IR/main-emitter
case. EVM transaction semantics roll an entered write back if the intervening CALL reverts.

## Evidence

- Focused component tests pin effect summary, canonical form, schema resolver failures, and
  byte-exact `sstore` emission.
- Extraction pins the ordered component sequence and proves it is not classified as final State
  writeback. `EvmOrderedStorage` canonical IR digest is `c37f9c0a33352f4`.
- The contract assembles with solc 0.8.34. Its Anvil gate verifies immediate persistence,
  store/CALL/restore, and rollback of the entered write after a failed CALL.
