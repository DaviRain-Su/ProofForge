# R5-016 — Persistent bounded EVM storage ring queue

## Goal

Bind the shared bounded FIFO law to ordinary EVM static storage as a reusable fixed-capacity
UInt64 circular queue, without adding a Runtime leaf, Ops/IR/Component variant, emitter recipe,
runtime allocator, pointer, or application-specific compiler rule.

## Delivered contract

- `Evm.Sdk.StorageRing.Descriptor` derives one consecutive physical layout from a fixed payload
  vector followed by disjoint `head` and `live` slots. Positive compile-time capacity and exact
  UInt64 slot geometry are validated before extraction.
- Runtime policy rejects zero capacity, `head >= capacity`, `live > capacity`, and a nonzero head
  on an empty queue. Full enqueue, empty peek/dequeue, and live-range OOB are explicit failures.
- `absIndex = (head + offset) % capacity` gives O(1) wraparound. Enqueue/dequeue decisions are
  evaluated before the consumer's literal state update, so rejected operations issue no partial
  payload or metadata store. Draining and clear restore canonical `head = live = 0`; stale payload
  slots remain physically present but unreachable.
- The abstraction is ordinary Lean SDK policy over existing static-vector extraction. It owns
  geometry and transitions rather than introducing another low-level instruction vocabulary.

## Evidence

- `EvmRingMailbox` is an owner-gated, reject-at-full capacity-4 consumer. Digest
  `5f2a66d9732449cd`; Yul 27,009 bytes; bytecode 3,934 bytes; bytecode-file SHA-256
  `1652a7e198446376dfbe13d8b2d90d20446b5b906266b966c39f516b5d7efe3a`.
- `EvmRingHistory` is an independent permissionless capacity-3 dequeue/clear/reuse consumer.
  Digest `51b492f52021f6ec`; Yul 16,114 bytes; bytecode 2,225 bytes; bytecode-file SHA-256
  `f63331983a0d0b7149678906c8795981a988560f19f0161a660ffb475ac328af`.
- Focused Lean pins descriptor geometry, host FIFO truth tables, malformed-state rejection,
  wraparound, extraction layout, dynamic vector load/store paths, and typed ABI errors. Dedicated
  Anvil matrices pin FIFO order, wraparound slot reuse, full/empty/OOB/authorization failures,
  direct malformed-storage injection, atomic rejection, and stale-slot unreachability.

The v1 queue stores UInt64 elements in ordinary static slots. Wider/typed elements, iteration,
bulk zeroing, dynamic capacity, packed metadata, and transient EVM memory queues remain fail
closed. This is a policy component, not a Solidity-compatible unbounded dynamic array.
