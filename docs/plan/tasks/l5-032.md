# l5-032 Pubkey RB-tree account-storage query

## objective

把 registered-trader four-word Pubkey red-black-tree + allocator partition validator 从顶层
SVM value kind 和主 emitter 迁入 `Svm.AccountStorage.Query`，并抽出 FIFO/Pubkey layout
共同的 fixed-capacity topology。

## invariants

- `RbTree` 只描述编译期固定的 links 与 packed parent/color `Field`；二者必须共享
  one-based fixed-capacity region，`0` 只作 null sentinel
- `Key4RbTree` 在共同 topology 上声明连续四字 key region；first/last key field 必须同形，
  且 last word 固定为 first word + 3，capacity 固定且不超过 8321
- FIFO 与 Pubkey query 共用 64-edge traversal bound；Pubkey complete validator 使用 frame
  底部 fixed 8321-bit bitmap 和 64-entry stack，不分配 runtime collection
- query 自己拥有四参数 arity、read-only effects、geometry validation、account walk、minimum
  account 与 canonical spelling；source helper 仍保留 `accDataRbTreeKey4Valid`
- complete preflight 原位检查 root/size/bump/free envelope、child↔parent reciprocity、color、
  black height、Rust `[u8; 32]` byte-lexicographic ordering、cycle/duplicate 与 live/free exact
  partition
- trader insert/remove/deposit 不复制 validator，也不调用主 emitter 私有函数，而是组合
  `AccountStorage.Emit.emitQuery`
- 主 `loadVal` 仍只有一个 `.accountStorage query` case；generic extraction traversal、field
  collection、canonicalization 和 account inference 不新增 Pubkey validator 特判
- 不分配 heap `Map`/visited collection，不复制 node，不开放 runtime geometry、detached
  persistent node 或 persistent pointer

- guards 覆盖 query arity、shared one-based geometry、连续四字 key、read-only effects、
  canonical spelling、malformed operand count 与 8321 capacity bound
- source digest 保持 `e9966de4a1795a47`；assembly 4,652,144 B、ELF 1,489,088 B、
  IDL 7,613 B 均保持不变
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 230/230、Anvil 12/12
  全绿；Surfpool 1.5.0 以 1,472 个 Loader write transactions 部署并核对 exact
  1,489,133-byte ProgramData
