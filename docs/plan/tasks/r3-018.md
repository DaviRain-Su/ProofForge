# R3-018 — Add checked transient byte-buffer pop

## Goal

Extend the invocation-local bounded byte writer toward Rust `Vec<u8>` parity without implying
reclaiming allocation, persistent pointers, or unbounded growth on Solana's program heap.

## Delivered contract

- `Svm.Sdk.Transient.Bytes.pop : UInt64` removes and returns the former final live byte.
- Pop first applies the shared active-marker and exact compile-time-capacity gate. Empty buffers
  terminate with the existing bounds code `0x1212` before length or payload is touched.
- A successful pop decrements logical length and reads the old trailing byte in place. It does not
  clear stale payload, allocate, free, reallocate, expose the native address, or reclaim bump space.
- Extraction lowers the source leaf only through `Component.transientBytes`; no top-level Ops/IR
  or main-emitter constructor was added.

## Evidence

- `Tests.SvmTransientBytesSpec` pins zero arity, canonical identity, Component ownership,
  begin→push→push→pop→finish ordering, direct empty-pop ordering, and the assembly error gate.
- `runtime-tests/solana/tests/memory_ops.rs` verifies exact LIFO byte return and `Custom(0x1212)`
  for empty pop under Mollusk; the complete MemoryOps binary passed 13/13 tests.
- MemoryOps target IR digest: `9a5da5482923cd69`.
- Emitted sBPF assembly: 132,214 bytes. Linked ELF: 44,496 bytes, SHA-256
  `955d144fab63226101a68132483029de59889548a13db2ed45321b76d773010b`.

Multiple simultaneous same-type buffers, generic POD elements, insert/remove-at, and iteration
remain separate bounded-resource contracts rather than implicit consequences of this operation.
