# wsm-026 用户 ContractData（存储 Owner = caller）

## objective

今天 `loadAccount` 把存储 Owner 写成合约账户（Bedrock `sfOwner` / AlphaNet
`tx_field(sfAccount)` 的 **合约调用者当数据主人** 其实已经是 caller——
但读写的仍是 **同一块** JSON，所有用户挤在一起）。

Uniswap 式余额要的是：**每用户一块** `ContractData`，`Owner` = 用户 AccountID，
槽名仍是编译期 `"bal"`。不是 keccak map，不是 wasm heap。

AlphaNet 探针（`probe-owner.sh`，合约 `rJWhEixTESXu39MJ2uGjLQLsFENYYpPii3`）：

| 写到谁 | 结果 |
|---|---|
| `tx_field(sfAccount)` = caller | **绿**：`bal=1` 挂在 caller 的 ContractData 下 |
| `home_le_field(sfContractAccount)` = 合约 | **拒**：`tecBYTECODE_REJECTED` / VM **-22** |

所以今天的存储 Owner **已经是 caller**。换到合约账户被 host 拒绝。
「每用户一块、Owner=任意用户」还没有第二条路：第二把钥匙才能给别人账户写。

下一刀不是 wasm allocator，也不是 `Sdk.Map`。可选：

1. 单用户积分账本（caller 自己的 `"bal"`）——现在就能做 Example
2. nested JSON / 编译期 key 表仍挂在 caller 下
3. 等 host 允许合约当 Owner，或 `emit_built_txn` 给别人建 ContractData

## 不做什么

- 不做 wasm bump allocator
- 不抄 EVM `mapping(address => uint)`
- 不开 `Sdk.Map` 空名

## verification

- 探针 WAT：写 `"bal"=1` 到 caller 20B；`account_objects(caller)` 能读到
- 失败（host 拒非合约 Owner）→ 记入 xrpl-next，改 nested JSON 方案
