# L5-055 — Reusable consume-in-place storage policy and partial maker fills

## Goal

Extend the bounded Phoenix Limit slice without adding a Phoenix operation or another protocol
branch to the main emitter. Put the reusable zero-remove/nonzero-update policy at the fixed-account
storage boundary, and make absence of protocol return data an explicit generic entry contract.

## Delivered

- Added `AccountStorage.Call.rbMapSetWordOrRemove` and
  `Source.setWordOrRemoveOrderedPair`. Given a key, the one-based index returned from the same
  validated map view, and a new field value, the component removes the fixed record when the value
  is zero or updates the existing slot when it is nonzero. The component emitter composes the
  existing remove backend and fixed-record word writer; callers retain no pointer across effects.
- Phoenix's `Book.setSizeOrRemove` is a policy-level use of that generic component. A taker that
  exhausts its base budget against a larger maker now reduces the maker size in the exact same
  account-resident slot. An exact-size maker still follows the existing bounded remove/free-list
  path. Bid and ask directions both update maker/taker balances, aggregate taker fee, market
  sequence, Fill remaining size, and FillSummary amounts.
- Added a generic runtime-optional packed-return contract. A handler returns one canonical
  presence scalar plus a fixed-width payload: zero exits successfully without calling
  `sol_set_return_data`, one serializes the payload, and every other value fails closed. The wire
  schema is `svm.raw.v5`; RawEntry exercises absent, present, and invalid presence values.
- Corrected the first Limit slice to official Phoenix behavior: a fully matched Limit with no
  posted remainder leaves return data unset. The previous slice's four-byte empty Borsh vector is
  retained only as historical documentation in L5-054.
- No persistent heap `Map`/`Vec`, detached tree, runtime storage geometry, persistent pointer, or
  unbounded traversal was introduced. Phoenix layout, crossing, fee, event, and wire policy remain
  in `Examples`; the generic SDK owns fixed-stride storage and entry return mechanics.

The reusable boundary is:

```text
Phoenix matching policy (Examples)
        │ key + one-based slot + remaining scalar
        ▼
AccountStorage zero-remove / nonzero-update component
        │
        ├── zero ─────▶ validated ordered-map removal + one-based free list
        └── nonzero ──▶ bounds-checked fixed-record word write
```

## Next

Keep the generic component and optional-return boundaries fixed. Extend `match_limit=Some(1)` so
an exactly consumed maker may be followed by a noncrossing taker remainder posted to the taker's
own fixed book slot, returning one official FIFO order id. Then add bounded multi-maker traversal
and aggregate fees as a separate slice. Unsupported remainder, capacity/eviction, TIF, self-trade,
and soft-funds policies remain fail closed until their complete transitions are covered.
