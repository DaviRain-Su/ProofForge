# R4-013 — Add a fixed EVM call-selector view

## Goal

Expose Solidity `msg.sig` through the reusable Environment and FixedBytes boundaries without
turning arbitrary calldata or a memory pointer into a source value.

## Delivered contract

- `Evm.Sdk.Context.selector : Bytes4` uses the shared allocation-free `FixedBytes 4` carrier and
  therefore preserves source byte order and Solidity ABI `bytes4` metadata. It is not a numeric
  UInt32/UInt64 convenience view.
- The Environment interpreter observes `calldataload(0)` once and projects bytes 0..3 with the same
  fixed-byte packer used by `Address.codeHash`; ordinary selector dispatch already rejects calls
  shorter than four bytes before an entry can run.
- Extract now preserves a one-limb target query as an already-physical scalar when binding a
  one-limb fixed-width source result. It no longer invents a nonexistent `w0` field below that
  component query.
- The slice adds no top-level Ops/IR/main Emit constructor, allocation, storage, call, arbitrary
  calldata view, or target pointer.

- The EvmCtx Anvil gate compares `selector()` with the exact Keccak selector of `selector()`.

A future `msg.data` API requires an explicit bounded calldata contract and is not implied here.
