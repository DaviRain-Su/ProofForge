# R2-004 — SVM-RT-3 bounded Token-2022 TLV envelope

## Goal

Replace the Token-2022 `TransferChecked` exact-length shortcut with a target-owned account-data
policy that understands the pinned official state-with-extensions envelope and remains
allocation-free in generated sBPF.

## Official layout and delivered contract

The layout is pinned from the exact crates in `runtime-tests/solana/Cargo.lock`:

- `spl-token-interface-2.0.0/src/state.rs` fixes Mint=82, Account=165 and Multisig=355 bytes;
- `spl-token-2022-interface-3.1.1/src/extension/mod.rs` fixes the extension-form type byte at
  absolute offset 165, TLV start at 166, zero mint padding at 82..164, and little-endian
  `u16 type || u16 length || value` entries;
- the same official iterator accepts region end, fewer than two trailing bytes, or type 0 as its
  end form, and rejects missing lengths or bodies beyond `data_len`;
- `solana-zero-copy-1.2.0/src/unaligned.rs` confirms the `U16` little-endian representation.

`Svm.Cpi.TokenTlv` owns one closed policy and typed plan for Mint/Account base geometry. Its host
reference semantics use a bounded forward cursor, wrap-checked arithmetic, a scalar header count,
and one UInt64 duplicate bitmap for all 28 pinned non-end extension ordinals. The byte-provider
closure and test arrays exist only in host/reference gates; generated target state has no
`Array`, `List`, `Map`, heap object or persistent pointer.

`Svm.Cpi.TokenTlv.Emit` is the sole target interpreter. This first closed specialization accepts
classic 82/165-byte state and extension-form state containing only official end/padding forms.
Because no non-end extension is supported yet, a proved specialization rejects the first nonzero
type immediately and needs no runtime loop or duplicate bitmap. Main `Svm.Emit` only dispatches
typed account-data policies; it does not own Token-2022 offsets or add a protocol recipe opcode.

## Failure policy

- Multisig-length ambiguity, short base spans, nonzero mint padding and wrong account type reject
  before CPI.
- Truncated/malformed non-end headers, official unsupported extensions and unknown ordinals reject
  atomically before persistent writes or CPI.
- Transfer-fee, transfer-hook and every other real extension remain unsupported until their full
  official account requirements and transfer semantics are modeled. No extension is treated as
  harmless merely because its bytes parse.
- Exact-length policies remain available for unrelated CPI consumers and are mutually exclusive
  with the typed TLV policy.

## Evidence

- Focused Lean gates cover classic state, padding/end forms, multiple bounded headers in the host
  cursor, body OOB, duplicate, header-count, malformed, unknown and arithmetic boundaries.
- Token-2022 Mollusk passes 8/8: base and padding-only success plus fee, hook, malformed,
  truncated and unknown-extension atomic rejection.
- Aggregate Lean passes 277 jobs; locked single-threaded Mollusk passes 308/308.
- All 54 registered SVM programs build; all 53 programs other than Token2022 retain byte-identical
  assembly/ELF/IDL against the pre-slice baseline. Token2022 changes intentionally and has digest
  `d3b11a73adabded8`.
- Ownership and whitespace gates pass. This runtime-only slice does not run a Surfpool deployment;
  Surfpool 1.5.0 remains the deployment qualification environment, never `solana-test-validator`.

## Remaining work

- extension-specific policies such as transfer-fee and transfer-hook must be opened separately,
  with their exact account/CPI semantics and the same bounded cursor contract;
- R3 invocation-local bounded Vec/byte-writer/codec-buffer APIs remain separate from persistent
  account storage and from this read-only preflight.
