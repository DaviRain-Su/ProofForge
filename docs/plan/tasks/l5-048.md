# L5-048 — Compose strict Phoenix-v1 PostOnly placement

## Goal

Implement the smallest official tag 3 `PlaceLimitOrderWithFreeFunds` slice on the stable
EntryAdapter/Component/AccountStorage boundary. Keep all persistent order-book state in account
bytes and add no Phoenix, Queue, Map, or allocator instruction to generic Ops, IR, CFG, or the main
emitter.

## Delivered

- Added the exact 40-byte official wire for `OrderPacket::PostOnly`:
  `03 || 00 || side:u8 || price:u64 || base_lots:u64 || client_id:u128 || reject_post_only:bool ||
  01 || 00 || 00 || 00`. The strict slice accepts both canonical reject booleans, requires
  deposited funds, rejects time-in-force values and silent insufficient-funds behavior, and fails
  closed on every unsupported variant, flag, length, or trailing byte.
- Authenticated the official five-account prefix: executable current program, readonly log PDA,
  writable Phoenix market, readonly signer trader, and readonly approved seat. The 128-byte seat
  must be Phoenix-owned, have the official discriminator and approval status, embed the exact market
  and trader keys, and be the canonical `PDA("seat", market, trader)`.
- Composed the existing complete trader/bid/ask allocator and RB-tree validation, one-based trader
  lookup, FIFO duplicate lookup/insertion, one-based balance fields, fixed account-word writes, and
  bounded recorder. No node pointer or dynamic container survives the operation; `0` remains the
  null sentinel.
- Restricted matching behavior deliberately: market status must be Active or PostOnly, the opposite
  book must be empty, and the selected 512-order book must have capacity. This prevents matching,
  repricing, expiry cleanup, and eviction from being approximated by this slice.
- Reused `quoteLotsReleased512At` as the shared checked quote-lot geometry. Bids move exact
  `(tick_size * price * base_lots) / base_lots_per_base_unit` collateral from quote free to locked;
  asks move exact base lots from base free to locked. Zero collateral, overflow, and insufficient
  funds fail before any durable write or audit.
- Kept the two Phoenix sequence domains independent. The order key consumes word 106 (bitwise
  complement for bids, unchanged for asks) and increments it once; the audit header captures the
  pre-increment market sequence from word 34 and increments that word independently.
- Emitted the exact 43-byte Place audit record after the 93-byte Phoenix header, preserving the
  little-endian u128 client id as two u64 limbs. This slice returns the encoded sequence scalar;
  Phoenix's official 16-byte `(price, sequence)` return remains the next reusable effectful-tuple
  language slice rather than a Phoenix-specific return opcode.

The stable boundary remains:

```text
source semantics -> EntryAdapter protocol plan -> bounded Component Query/Call
                 -> component-owned validation/effects/emitter -> AccountStorage -> sBPF
```
