# l5-036 Source-level bounded RB map find

## objective

把 `l5-035` 的 Key4/FIFO account-storage lookup 通过薄 Runtime/source intrinsic 暴露给
contract source，并在 PhoenixV1Profile 上组成
`complete validator → bounded find → one-based index/0`，证明新增业务能力不再修改顶层
Ops/IR 或主 Emit。

## invariants

- `accDataRbTreeKey4Find` 与 `accDataRbTreeOrderFind` 的 account/root/links/parent/key/stride/
  capacity/bid 全部必须在 extraction 时为常量；runtime 只能提供 key words
- extractor 直接构造 `AccountStorage.Query.key4FindOneBased` / `fifoFindOneBased` 并复用其
  `wellFormed` gate；dynamic geometry、越界 capacity 与非 0/1 bid 均 fail closed
- Runtime helper 返回 one-based slot index，missing 返回 `0`；不返回 account pointer、node
  copy 或 detached allocation
- Phoenix read methods 在 search 前调用既有 complete tree/free-list validator；malformed
  topology 返回 `0`，不会把局部可达 key 当成可信业务状态
- `findTrader128` 使用 `[u8;32]` byte order，`findBid512` 使用降序 FIFO，`findAsk512`
  使用升序 FIFO；三者 IDL account metas 都保持 read-only
- 主 `Svm.Emit.loadVal`、顶层 `Svm.OpExt` 与 `Svm.IR.Op` 不增加 case；source value 直接落入
  generic account-storage query bridge

## implementation

- `Svm.Runtime`、`Svm.Ops` 与 `Extract.Ops` 增加两个薄 helper；`Extract.asVal` 只解析静态
  descriptor 与 dynamic key operands
- PhoenixV1Profile 增加 `findTrader128`、`findBid512`、`findAsk512` 三个 read-only method，
  分别复用完整 Pubkey/FIFO validator 与同一 bounded search backend
- generic test query walker 检查 extracted method 确实包含 validator + find composition；
  assembly guard 检查三个 static layout 都到达共同 `rb_find` routine

## verification

- Mollusk 覆盖 trader/bid/ask found 与 missing、Key4 byte order、bid/ask ordering，以及
  malformed self-cycle 被 validator 转成 `0`；返回值是 exact one-based slot index
- source digest `b37d4fce03b21ff4`；assembly 5,638,878 B；ELF 1,799,856 B；IDL
  8,370 B，三个 find account metas 都是 read-only
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 231/231、Anvil 12/12 与
  Surfpool 1.5.0 Loader-v3 smoke 全绿

## next migration

用 `findTrader128` / `findBid512` / `findAsk512` 的同一 source-level primitives 实现最小
official ReduceOrder：先查 trader 与 order，读取固定 field，完成所有 checked arithmetic
preflight，再选择 partial quantity write 或 full `rbMapRemove`，最后更新 collateral。

## non-goals

- 本切片不实现 official Phoenix instruction tag 4/5、wire decoder、event 或 collateral write
- 不允许省略 complete validator 后把局部 search 当作完整结构证明
- 不增加 heap Map、runtime-selected layout、persistent pointer 或 unbounded traversal
