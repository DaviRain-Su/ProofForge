# l5-012 Phoenix-v1 constant-memory bid-root neighborhood

## objective

在不分配 `Vec`、`Box`、`HashMap`、`BTreeMap` 或 SVM Map 的前提下，从候选 market
account 原位读取 bid root 及两个直接 child。这个切片建立跨节点读取与关系验证边界，
但不把局部检查冒充完整红黑树证明。

## invariants

- root 必须是 black、parent=0，且 sequence 高位标记为 bid
- left/right child 为 null 或位于 `1..bump_index-1` 与 compiled capacity 内
- 非空 child 不能等于 root，parent 必须回指 root，color 只能是 black/red
- child 自身 left/right 也必须是 null 或位于 allocator live-index envelope
- Phoenix bid comparator 为 price 降序、stored sequence 降序：left key 严格先于 root，
  root 严格先于 right
- null/非法 child 的实际读取 slot 被夹到静态区域 slot 0；判断仍使用原 index，因此非法
  关系返回 0，同时不会在形成 account data pointer 前发生下溢或越界

## path

`Examples/Svm/PhoenixV1Profile.lean`, `Tests/PhoenixV1ProfileSpec.lean`,
`runtime-tests/solana/tests/phoenix_v1_profile.rs`

## verification

- 12 个官方 profile 都从各自 compiled-capacity 分支验证单 root neighborhood
- Mollusk 从 root index 2 原位读取 left/root/right 三个 slot；正确 parent/color/order 返回 1
- 错 parent、非法 color、反向 left ordering 返回 0
- digest `7952977f008911a8`，assembly 2,171,011 B，ELF 716,344 B

## non-goals

- 不遍历 grandchildren、完整 bid/ask/trader tree 或 free list
- 不证明全树 cycle/duplicate absence、全局 ordering、red rule、black height 或 live/free partition
- 不写节点/allocator，不开放 runtime base/stride/capacity 或 remaining accounts
- 不宣称完整 Phoenix-v1 账户/指令兼容，也不把 Mollusk 称作部署
