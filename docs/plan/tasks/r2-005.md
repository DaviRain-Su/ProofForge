# R2-005 — Checked SVM program-memory spans

## Goal

Bind Solana's four official program-memory host functions without exposing a native pointer,
unbounded slice, heap collection, or persistent allocation to source programs.

## Delivered contract

- `Svm.Memory.Span` describes one compile-time `account/offset/length` interval inside the 10 MiB
  account-data envelope. Zero-length, out-of-envelope, mismatched-length, and over-account-limit
  shapes fail extraction/component validation.
- `Svm.Sdk.Memory` exposes `copyNonoverlapping`, `move`, `set`, and `compareI32Bits`. The component
  bridge owns span effects and canonical identity; no new top-level SVM operation, IR constructor,
  or main-emitter recipe was added.
- Emission checks each span against the invocation's actual `data_len`. A destination additionally
  requires writable metadata and current-program ownership before the backend forms a transient
  pointer and calls exactly one of `sol_memcpy_`, `sol_memmove_`, `sol_memcmp_`, or `sol_memset_`.
- `copyNonoverlapping` rejects static overlap, while `move` permits overlap. `compareI32Bits`
  preserves the official first-different-byte `i32` result as a zero-extended 32-bit bit pattern;
  it does not invent `-1/0/1` semantics or claim source signed arithmetic.

The `MemoryOps` application exercises all four contracts. `AccountView.comparePrefixes`
independently consumes the compare facade, demonstrating that the component is not tied to one
fixture or to Phoenix.

## Lifetime and failure boundary

The span is compile-time geometry, not a slice header. Any native address exists only in registers
across the immediately following host call and cannot enter account state, Core values, or the
public SDK. This slice does not implement a source-visible heap `Vec`, persistent vector growth,
dynamic account selection, zero-length operations, or arbitrary pointer arithmetic. Invocation-
local bounded byte/vector mutation and explicit allocator OOM propagation remain separate R3 work.

## Evidence

- Focused Lean guards pin span geometry, non-overlap policy, component lowering, fixed account walk,
  and all four syscall symbols.
- Mollusk verifies exact memcpy/memmove/memcmp/memset behavior, negative `i32` result bits, short
  accounts, readonly destinations, and wrong-owner atomic rejection. The independent AccountView
  runtime gate verifies the same compare contract through a second application.
- The aggregate gates pass with 326 Lean jobs, all 56 registered SVM programs in the artifact
  manifest, and all 322 Mollusk tests.
- `MemoryOps` digest is `68d44a2ea3fa00fb` with a 7,384-byte ELF. `AccountView` digest is
  `fc1803fc9f140a95` with a 15,376-byte ELF.
- Surfpool 1.5.0 Loader-v3 qualification remains the deployment gate; no test-validator path was
  introduced.
