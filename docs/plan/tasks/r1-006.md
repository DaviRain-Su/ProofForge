# R1-006 — Bind canonical static aggregate ABI on EVM

## Goal

Lower the same shared logical static schemas used by R1-005 into an independently EVM-owned ABI
plan. Records and products must keep canonical tuple selector types, literal vectors must keep
fixed-array types, and each static scalar leaf must occupy one checked 32-byte ABI word. Core must
not learn ABI geometry, and SVM must not inherit EVM word or padding rules.

This is the **EVM static aggregate adapter slice**. Enum/option tag policy, dynamic bounded tails,
and aggregate storage layout remain explicit later work rather than being guessed by Emit.

## Delivered

- `Core.Codec.resolveSourceProjection` resolves Extract's compatibility field spellings against
  authoritative typed static paths. Targets supply only their own fixed-part counts and suffix
  vocabulary; ambiguous flattened names fail closed.
- `Core.Target.rewriteOpsValues` provides one reusable root-first, fallible traversal for common
  value trees, nested control flow, and target-owned component payloads. SVM and EVM adapters now
  define only their boundary projection rewrite instead of each duplicating the common AST walk.
- `Evm.Codec` owns canonical schema spelling and static ABI leaves: record/product become tuples,
  literal vectors become fixed arrays, and every scalar leaf occupies one ABI word. Unit,
  zero-length arrays, enum/option without a target policy, and bounded dynamic arrays fail closed.
- EVM IR separates logical ABI parameter count and selector schema from physical word count. It
  rewrites aggregate field/index projections after target projection, shifts the implicit State
  argument by the physical word count, and validates aggregate result source-part metadata.
- EVM Emit enforces exact aggregate calldata size and applies the existing Bool, narrow integer,
  address, and fixed-bytes canonical word guards to every flattened leaf. Static aggregate returns
  are packed one logical leaf per word, including wide integers, fixed bytes, and addresses.
- ABI JSON preserves logical tuples, record component names, nested components, fixed-array
  suffixes, and tuple output shape. It does not expose the internal flattened word list.
- `Examples.EvmCtx.aggregate` is a normal Lean nested record/product/`Vector UInt16 3` fixture.
  The canonical selector type is
  `aggregate((uint64,(uint8,bool)),(uint32,uint64),uint16[3])`; eight physical words return one
  `(uint64,bool)` tuple.

The ownership path is:

```text
Core logical StaticLeaf path
             │
             ▼
Evm.Codec tuple/fixed-array ABI policy
             │ one canonical word per scalar leaf
             ▼
       EVM CFG + Yul Emit
```

No aggregate object is dynamically allocated. No ABI word/padding rule enters Core, no Borsh
width enters EVM, and no application/protocol name or aggregate recipe enters Ops/Component/Emit.

## Next

R1 closes only after the remaining tagged/dynamic schema policies are assigned explicitly rather
than inferred accidentally. SVM may bind Borsh option/enum tags and bounded lengths; EVM must use
standard ABI shapes or a named SDK policy. Neither target may copy the other's physical encoding.
