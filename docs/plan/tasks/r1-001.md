# R1-001 — Typed codec metadata and EVM scalar adapter

## Goal

Stop making EVM emission infer language types from the historical `1/2/4/8/20/32/33` carrier
widths. Establish a bounded, target-neutral codec descriptor; carry typed parameter/return metadata
from extraction through Core and both target IRs; make the EVM ABI adapter the single owner of ABI
scalar names, calldata guards, and the legacy-width compatibility boundary.

This is the first R1 slice, not the completed aggregate-codec work. It deliberately does not claim
that SVM RawEntry can already decode every `FixedBytes`, tuple, enum, or bounded array descriptor.

## Delivered

- `Core.Codec` defines logical bool/uint/address/fixed-bytes scalars and unit/scalar/tuple/record/
  enum/option/fixed-array/bounded-array shapes. Validation rejects malformed widths, empty or
  duplicate names, zero/over-capacity arrays, excessive depth, descriptor nodes, and logical leaves.
- Extracted methods now carry `paramTypes` and `retTypes` in addition to legacy widths. Core target
  projection and SVM/EVM lowering preserve the metadata. Legacy fixtures continue through one
  explicit EVM compatibility resolver; incomplete metadata fails closed.
- `Evm.Codec` owns ABI names, 32-byte word guard classes, scalar carrier classification, EVM masks,
  and the historical width sentinels. Generic `Crypto.Keccak` no longer contains EVM width policy.
- EVM selectors, constructor/entry guards, wide projection/return handling, and ABI JSON consume
  typed scalar metadata. Production `Evm.Emit` no longer compares parameter or return widths to
  ABI sentinel numbers.
- Existing canonical digests continue to include the established selectors and compatibility widths,
  so this metadata migration does not churn current artifacts. Typed metadata is authoritative when
  present; old Golden/Legacy inputs are restored at the target boundary.

The ownership path is now:

```text
Lean boundary type
      │ Extract
      ▼
Core.Codec.Scalar / Schema
      │ preserved by Core.Target
      ├── SVM IR metadata ──▶ R1 Borsh adapter (next)
      └── EVM.Codec ────────▶ selector / guard / ABI / EVM carrier
```

Codec descriptors describe logical wire shape only. They do not contain SVM account geometry, EVM
storage slots, native pointers, heap allocation, or protocol validation.

## Verification

- `Tests.CoreCodecSpec` covers valid and malformed descriptors, bounded resource accounting, enum
  unit variants, scalar ABI mapping, fixed-bytes padding classification, typed-over-legacy priority,
  and incomplete-metadata rejection.
- `python3 scripts/check_ownership.py` and `git diff --check` pass.
- `lake build Tests` passes 236 jobs; `lake build` passes 97 jobs.
- All 51 SVM programs build and the locked Mollusk inventory passes 285/285. The SVM ELF outputs are
  unchanged by this metadata-only migration, so the previous Surfpool 1.5.0 deployment evidence was
  not repeated.
- All 15 EVM programs build and the Anvil suite passes 15/15.
- Ownership, whitespace, changed-Markdown link, and production `Evm.Emit` legacy-width static guards
  pass.
- Existing EVM selectors, canonical digests, and runtime behavior remain covered by
  `Tests.NormalizationSpec`, all EVM build guards, and Anvil.

## Next

Add target-neutral source values (`FixedBytes n`, `UInt128`, shared `UInt256`) and derive complete
codec shapes rather than only scalar method metadata. Bind the same logical fixture to exact-cursor
SVM Borsh and EVM ABI aggregate plans. Keep account/storage layout separate and reject recursive,
dynamic, or over-budget shapes before target emission.
