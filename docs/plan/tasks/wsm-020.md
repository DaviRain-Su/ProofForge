# wsm-020 NEAR lossless AccountId foundation

## Objective

Replace the authorization-unsafe “first eight UTF-8 bytes” identity facade with a lossless,
bounded representation suitable for private callbacks, transfers, map keys, and future
cross-contract receivers.

`Runtime.AccountId` is nine scalar leaves: byte length plus eight little-endian `UInt64` words for
the NEAR protocol's 64-byte maximum. Context host calls already return validated account IDs;
future user-input and storage decoders must validate syntax before constructing the same type.

## Delivered

- `Context.caller` and `Context.self` return complete `AccountId` values.
- `callerLo` / `selfLo` retain the explicitly truncated legacy projection; they are not identities.
- `AccountId.eq` compares length and all eight words as ordinary nested scalar conditions.
- `Access.isSelfCall` provides the callback/private-method authentication predicate without a new
  Runtime effect or host import.
- The emitter reads `predecessor_account_id` / `current_account_id` once per used identity, checks
  the host register is at most 64 bytes, clears a dedicated 64-byte buffer, then reads length and
  all words. Separate buffers prevent stale suffix bytes from aliasing between identities.
- Every predecessor leaf remains forbidden in views; current-account leaves remain view-safe.
- The old `predecessor` / `currentAccountId` Runtime constants remain canonical w0 leaves, so
  callers that explicitly select `callerLo` / `selfLo` preserve their IR spelling.

## Not included

- No user-supplied AccountId decoder or syntax validation.
- No arbitrary bytes/String ABI, JSON, Borsh, Promise, transfer, callback result, or collection.
- No claim that the scalar ASCII-key state layout matches `near-sdk-rs` `STATE` or `store::*`.

## Verification

- Source equality distinguishes length and the last word.
- Exact Runtime names project to NEAR-owned leaves; foreign targets still reject them.
- A view using `Context.caller.length` fails closed at emit.
- WAT anchors pin register length checks, dedicated zeroing at offsets 64/128, and all locals.
- near-sandbox checks `test.near` as length 9, w0=`test.nea`, zero-padded w1=`r`, then verifies a
  direct transaction passes full predecessor/current-account equality.
