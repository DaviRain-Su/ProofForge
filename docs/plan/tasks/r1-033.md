# R1-033 — Shared bounded byte and string lexicographic ordering

Date: 2026-09-01
Status: done

## Goal

Give both targets one reusable allocation-free ordering policy for bounded bytes and strings,
comparable to Rust slice ordering and the explicit byte-order policy Solidity applications usually
build themselves, without introducing a container opcode or target emitter recipe.

## Delivered contract

- `Core.Value.LexOrder` names `less`, `equal`, and `greater` as source policy rather than exposing
  magic public result tags. `BoundedBytes.compareLex?` rejects an over-capacity frame and returns the
  typed ordering; `isLexLess` is the single-scan Bool projection used by contracts.
- The compile-time bounded scan compares unsigned active bytes. The first difference decides; equal
  prefixes use shorter-first ordering; equal values are not strictly less. Inactive fixed-frame
  slots do not affect the result, and capacities are never coerced implicitly.
- `BoundedString` reuses the byte implementation through its compiler-erased view. Strict UTF-8
  remains a constructor/codec invariant, with no Unicode normalization or locale collation.
- SVM `RawEntry` tags 29/30 and EVM `EvmBounded` independently choose Bool public policy while
  retaining canonical Borsh and standard-ABI boundaries.

## Boundary

This is unsigned active-byte lexicographic policy, not hashing, substring/search, concatenation,
Unicode normalization/collation, allocation, persistence, or a shared wire layout. Direct contract
methods choose Bool rather than adding a new tagged boundary ABI. No Runtime/Ops/IR/CFG/Component/
Emit case, pointer, allocator, or target-specific comparison primitive was added.
