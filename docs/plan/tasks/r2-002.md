# R2-002 — SVM-RT-2a bounded scratch and instruction layout

## Goal

Move CPI stack geometry out of individual emitter recipes and into one reusable target-owned plan.
The contract must make capacity, alignment, non-overlap, OOM, and invocation-only lifetime explicit
without exposing a runtime pointer or pretending that transient stack/heap bytes are persistent
Solana account storage.

This is the layout foundation of SRT-2, not completion of return data, runtime-selected instruction
payloads, or Token-2022 semantics.

## Delivered contract

`Svm.Scratch` provides:

- fixed `Bank` descriptors with an explicit invocation-only lifetime and disjoint stack intervals;
- aligned `Plan.alloc` with compile-time malformed-bank, empty/duplicate-name, invalid-alignment,
  and capacity errors;
- typed `Allocation` results, so emitters consume returned `Region` handles rather than partial
  string lookup or repeated numeric offsets;
- a typed `InstructionPlan` for Solana C `AccountMeta`, instruction descriptor, aligned payload,
  and `AccountInfo` regions; Loader ABI sizes are named once;
- `Heap.alignUp`, paired with the existing official-shaped downward bump allocator model.

The ordinary `Svm.Emit` invoke path and dynamic signed self-CPI sink now consume this plan. Their
Ops/IR/component identity is unchanged. No queue, map, allocator, Phoenix instruction, or source
feature became a new opcode/emitter recipe.

## Resource and failure boundary

- CPI scratch remains the existing 1,024-byte bank rooted at `r10-2048`.
- The scalar `[0,1024)`, CPI `[1024,2048)`, and deep `[2048,4096)` depth banks are checked as
  disjoint compile-time geometry.
- Regions grow monotonically with power-of-two alignment. A region that would exceed capacity is
  rejected before assembly is emitted; no out-of-bank pointer is formed.
- Plans contain only names and `Nat` byte counts. They contain no native address, account offset,
  heap object, `Array`/`Map` payload, or value that can cross an invocation.
- Runtime heap OOM remains the existing `Heap.allocate = none` / `Custom(1)` path. This layout plan
  does not turn the heap into persistent storage.

## Evidence

- Focused scratch/emitter regression: 115 Lean jobs.
- Full aggregate regression: 266 Lean jobs.
- All registered SVM programs were emitted before and after the refactor; assembly was
  byte-identical after excluding generated random keypair JSON files.
- `scripts/check_ownership.py` and `git diff --check` pass.

## Remaining SRT-2/R3 work

- typed bounded return-data staging and canonical return policies;
- broader multi-seed/PDA/CPI meta composition over this same plan;
- source-facing invocation-local Vec/byte-writer/codec-buffer SDK over the bounded heap;
- no pointer persistence, runtime-selected persistent geometry, or unbounded container support.
