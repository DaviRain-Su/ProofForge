# l5-035 Bounded account-storage RB map find

## objective

在 target-owned `AccountStorage.Query` 增加可复用的 Key4/FIFO RB-tree lookup，返回
one-based node index，未找到返回 `0`。上层可以组合
`mapFind → readWordOneBased → checked business preflight → writeWord/rbMapRemove`，不再为
每个 Phoenix 指令增加顶层 Ops/IR/Emit 特判。

## invariants

- root、account、links/key fields、stride、capacity、index base 与 key ordering 都是编译期
  descriptor；runtime 只提供 2-word FIFO key 或 4-word Key4 key
- 每次 dereference 前检查 index 在 `1..capacity`；`0` 只表示 missing/null sentinel；搜索
  最多执行统一的 64 层 traversal，cycle 或过深输入 fail closed
- Key4 对每个 little-endian storage word 执行 `be64`，保持 `[u8; 32]` byte-lexicographic
  ordering；FIFO ask 按 price/sequence 升序，bid 按 price/sequence 降序
- account 0 与 walked external account 共用同一 search routine；两条路径都先检查覆盖 root、
  links 与最后 key field 的 exact minimum data length，再形成调用期 transient pointer
- query 只能声明 read-only access；effect/account inference、arity 与 canonical spelling 由
  `AccountStorage.Query` 自己拥有
- 搜索只保存 current index 与 depth 两个 scalar，不分配 bitmap/heap/Map，不复制 node，
  不保存 detached node 或 persistent pointer；完整 topology/allocator invariant 仍由既有
  validator query 负责

## implementation

- `FifoRbTree.oneBased` 与 `Key4RbTree.oneBased` 成为 validator、find query 和 mutable
  `RbMap` 共同使用的 layout constructor，移除三处重复 region/tree 构造
- `Query.fifoFind` / `Query.key4Find` 提供 2/4 operand arity、read effects、well-formed gate 与
  `rbof` / `rb4f` canonical spelling
- storage emitter 的一个 `emitRbFind` routine 复用 data-length、bounded traversal、child
  selection、found/missing 与 malformed-account handling；主 `Svm.Emit.loadVal` 不增加 case

## verification

- guards 覆盖 FIFO/Key4 arity、canonical form、read-only effects、account 0/external account、
  root overlap、capacity bound、mutable-access rejection、bid descending 与 Key4 byte ordering
- isolated Key4 与 FIFO query programs 经真实 `sbpf build` 组装为 3,720 B / 3,480 B ELF，
  证明新 emitter 指令可被本地 toolchain 接受
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 230/230、Anvil 12/12
  与 Surfpool Loader-v3 smoke 全绿；未引用新 query 的 PhoenixV1Profile source digest 与
  assembly/ELF/IDL 保持不变

## next migration

增加薄的 Runtime/source intrinsic decoder，把 Key4/FIFO find 暴露给 contract source；随后
用它实现 Phoenix-v1 ReduceOrder 的 trader/order lookup、checked collateral preflight、partial
quantity write 与 full removal，并在 Mollusk 覆盖 found/missing/wrong-trader/overflow 路径。

## non-goals

- 本切片不改变 Phoenix wire ABI，不实现 ReduceOrder 或 collateral mutation
- find 不替代 complete RB-tree/free-list validator，也不把全树读入 transient container
- 不开放 runtime-selected account、root offset、stride、capacity、raw pointer 或 unbounded walk
