# L5-043 — Bounded invocation-local audit recorder

## Goal

Implement reusable audit batching behind the stable `Svm.Component.Call` bridge. The recorder must
support Phoenix's 93-byte header and 35-byte Reduce records, flush before Solana's inner-instruction
limit, emit a header-only batch when empty, and share the official Rust SDK allocator cursor without
exposing a heap or persistent pointer to source code.

## Delivered

- Added component-owned `BatchRecorder.begin/append/finish` calls. Static `Config` owns the log
  account, raw self-entry tag and authority seed, maximum byte length, header/count geometry, and
  maximum records. Compile-time-shaped words support little-endian u8/u16/u32/u64, ASCII, current
  program id, and checked account keys.
- Added a dynamic signed self-CPI sink behind `Component.Emit`. It serializes one readonly signer
  meta for the log PDA, `[authoritySeed, bump]`, current program id, the invocation's walked account
  infos, and a component-owned payload pointer/length. The generic main emitter still has only its
  existing `.component` dispatch.
- Allocated the payload with the official SDK protocol at `0x300000000`: the first word is the
  shared cursor, zero starts at the fixed 32 KiB SDK end, allocation bumps downward, aligns to 8,
  and fails closed without committing the cursor on OOM. Deallocation remains a no-op. Although an
  Agave transaction may map a larger heap frame, generated SDK-compatible code does not assume more
  than 32 KiB.
- Kept recorder metadata in fixed invocation stack cells 416..448. Scalar-local planning now asks
  component calls for their maximum scratch cell, so programs without the recorder preserve the
  previous 408-byte component boundary instead of paying a global layout change.
- Added generic component capabilities for CPI detection and raw self-entry declarations. IR
  account walking, prelude selection, and raw tag-15 routing discover those capabilities without
  enumerating recorder constructors.
- Extended extraction with irreducible source stubs and a bounded static word decoder. Ignored
  recorder calls are preserved as ordered SVM effects; malformed geometry or payloads fail closed.
- Migrated Phoenix tag 4/5 audit emission to begin/conditional append/finish. The 92-byte source
  header plus component-owned tag is 93 bytes; a Reduce record is 35 bytes. Thirty-two records use
  1,213 bytes, while the 33rd append flushes first because `93 + 33 × 35 = 1,248 > 1,246`.
  `finish` always flushes, including an empty header-only batch. Event indexes remain explicit
  source operands and are not derived from the recorder's batch-local count.

Persistent Phoenix/Sokoban data is unchanged: trees and allocators remain fixed account bytes with
one-based indexes and `0` sentinels. The transient payload address never enters source values or
account storage.

## Verification

- Component guards cover config/payload geometry, metadata/effects/canonical spelling, raw
  self-entry inference, dynamic scratch planning, official heap constants, and assembly branches for
  32-record and 1,246-byte pre-flush.
- Phoenix-v1 IR guards require begin/append/finish composition. Existing Mollusk tests still check
  exact 93-byte missing-order and 128-byte one-record `Program data` payloads.
- `PhoenixV1Profile` digest is `79102f84e2217820`; the build produces 9,708,793-byte assembly,
  3,052,280-byte ELF, and 9,537-byte IDL.
- `lake build Tests` completed 205 jobs; all 51 SVM programs and all 12 EVM programs built; the
  complete Mollusk suite passed 247/247 and Anvil passed 12/12.
- Surfpool 1.5.0 deployed that exact 3,052,280-byte ELF through 3,017 Loader-v3 write
  transactions and verified the complete 3,052,325-byte ProgramData account. No
  `solana-test-validator` was used.
