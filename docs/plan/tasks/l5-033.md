# l5-033 Bounded account-storage map mutations

## objective

把 five bespoke trader/order red-black-tree mutation constructors 从顶层 SVM Ops/IR 和主
emitter dispatch 收敛为 `Svm.AccountStorage.Call` 下的 three reusable bounded map calls，
让后续 search、allocator、rotation、transplant 与 fixup 迁移不再扩张通用 IR plumbing。

## invariants

- `RbMap` 只描述编译期固定的 account、four-word/FIFO key fields、root/header、node stride、
  capacity、one-based indexing 与 key ordering；`0` 继续只作 null/free-list sentinel
- mutation region 必须是 non-state writable account、current-program-owned、fixed-capacity，
  header 必须在 node array 前，parent/color 和 key fields 必须落在 node stride 内
- `rbMapInsert`、`rbMapRemove`、`rbMapCheckedAdd` 是 stable storage vocabulary；duplicate-key
  reject/replace 是显式 policy，不再编码为新的 SVM operation kind
- source helpers 和 Runtime intrinsics 保持原名称；decoder 直接构造 generic storage call，
  因此现有 Phoenix source 与 wire ABI 不变
- extraction flip/normalize/field/escape traversal、CFG payload、signer/account inference、IDL
  write inference 与 canonicalization 全部只使用 `Call.values/effects/mapValues`
- storage emitter 拥有统一 mutation dispatch；现有逐字节验证过的 in-place assembly routine
  暂由 backend adapter 提供，下一切片可迁移实现而无需再次改 Ops/IR/callers
- 不分配 heap `Map`，不复制 tree/node，不开放 runtime geometry、detached persistent node、
  persistent pointer 或 unbounded traversal

## verification

- guards 覆盖 Key4/FIFO geometry、operand shape、writable effects、canonical spelling 与
  malformed descriptor rejection
- source digest 保持 `e9966de4a1795a47`；assembly 4,652,144 B、ELF 1,489,088 B、
  IDL 7,613 B 均保持不变
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 230/230、Anvil 12/12
  全绿；Surfpool 1.5.0 以 1,472 个 Loader write transactions 部署并核对 exact
  1,489,133-byte ProgramData

## next migration

把现有 in-place mutation assembly 从主 emitter 迁入 storage backend，并在 backend 内复用
bounded key search/comparison、allocator acquire/release、left/right rotation、transplant 与
insert/delete fixup；业务层只组合 duplicate policy、value update、collateral 和 event。

## non-goals

- 本切片不改变 mutation 的 sBPF 指令序列、Phoenix wire ABI、allocation 顺序或 RB 语义
- 不实现 ReduceOrder，也不把业务 collateral/event policy 塞进 generic map primitive
- 不引入通用动态 `HashMap`、unbounded queue、runtime capacity 或 transient full-tree copy
