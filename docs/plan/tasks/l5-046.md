# L5-046 — Compose official Phoenix-v1 CancelUpTo through bounded components

## Goal

Implement official tags 8/9 without growing generic Ops, IR, CFG, or the main emitter. Reuse the
bounded Borsh-option entry plan and extend the target-owned FIFO cancellation component with
side-aware inclusive tick, search, and cancellation limits while keeping persistent traversal in
fixed account bytes.

## Delivered

- Added exact variable-length wires for tag 9 `CancelUpToOrdersWithFreeFunds` with four accounts
  and tag 8 `CancelUpToOrders` with nine classic Token accounts:
  `tag || side:u8 || Option<u64> || Option<u32> || Option<u32>`. The existing entry adapter owns
  canonical Borsh decoding and accepts only lengths 5..21; no protocol codec became a generic Op.
- Extended only `Svm.FifoCancel.Call` with `cancelUpTo`. Generic extraction projects the source
  intrinsic into the existing `.component` bridge, so generic executable Ops, IR, CFG, and the main
  emitter still have no Queue/Map/Phoenix-specific cases.
- Reused the storage-owned strict-successor cursor over the statically described FIFO RB map.
  Search counts each cursor result before owner and price filtering, cancellation counts only
  selected orders, and both counts are capped by caller limits and the compiled map capacity.
  Bids use inclusive `price >= tick`; asks use inclusive `price <= tick`; equal prices retain FIFO
  sequence order.
- Implemented official `None` defaults without dynamic geometry: the tick becomes the selected
  side's extreme and search/cancel limits become that compiled book's current size. Missing traders,
  no matches, and explicit zero limits still increment sequence and emit a header-only batch.
- Tag 9 retains released collateral as trader free funds and does not enter Token or market-status
  validation. Tag 8 claims every selected order's release inside the component, preserving
  pre-existing free funds, then withdraws only the selected side's aggregate through the shared
  classic Token context.
- Kept all durable Queue/Map/Allocator state in account bytes with one-based indexes and `0`
  sentinels. The loop carries only bounded scalar cursor/counter scratch; it introduces no heap
  `Vec/Map`, copied tree, detached node, persistent pointer, runtime stride, or unbounded walk.

The stable lowering boundary is now exercised by entry decoding, ordered storage, mutation,
recording, and Token composition:

```text
source semantics -> EntryAdapter protocol plan -> Component Query/Call
                 -> component-owned validation/effects/emitter -> AccountStorage -> sBPF
```

Shared component infrastructure owns Region/Field geometry, effects, bounds, validation, scratch,
and backend dispatch. Algorithm-specific traversal and failure semantics remain component-owned;
they are not flattened into another generic micro-instruction set.

## Next

boundary: first identify the smallest official placement/matching instruction ABI that composes
the existing account-storage cursor/mutation routines. Treat remaining accounts as a separate
bounded adapter capability. Do not add Phoenix-specific generic Ops/IR/main-emitter cases or use
transient allocation for persistent order-book state.
