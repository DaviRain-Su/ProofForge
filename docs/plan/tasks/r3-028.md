# R3-028 — Fixed-account version header and explicit migration edge

Date: 2026-08-31
Status: done

## Goal

Provide one reusable, allocation-free SVM account header that distinguishes uninitialized,
current, foreign, unsupported-version, and malformed states. Initialization must publish a fixed
nonzero discriminator/version atomically, while migration remains an explicit compile-time edge
rather than an automatic scan or runtime-selected upgrade.

## Delivered contract

- `Svm.Sdk.Versioned.Header` owns two adjacent typed `Field`s plus an exact nonzero discriminator
  and supported version. The descriptor is compiler data; reads and writes use only the existing
  checked account-storage component.
- `inspect` reads both words and returns distinct statuses for all-zero uninitialized, exact ready,
  wrong discriminator, unsupported version, and either mixed-zero malformed form. A short account
  terminates through the existing checked storage gate.
- `initialize` accepts only all-zero state, writes version first and discriminator last, accepts
  exact replay without a write, and rejects every incompatible state without mutation.
- `Transition` names one nonzero source version and the header's distinct supported target. It is
  separate from inspection/initialization, idempotent at the target, and rejects zero, same,
  unlisted, foreign, and malformed states. There is no runtime version range or geometry.
- `VersionedLedger` chooses strict fresh-or-current v1 policy and never migrates.
  `VersionedMigrator` independently chooses fresh v2 plus exactly one explicit v1→v2 entry.
  Application payload/error policy remains under `Examples`.

- Focused Lean extraction/geometry guards pass. VersionedLedger digest is
  `c5e2fe4d0f36deb1`; assembly is 42,045 bytes and ELF is 14,704 bytes with SHA-256
  `a1d989822d2878b7e0188036312b660eebc3e3fa0c6d57b3bb2fb623efbfc567`.
- VersionedMigrator digest is `2c6847a98f93b590`; assembly is 50,200 bytes and ELF is 17,456
  bytes with SHA-256 `bf3fa6cd64925faaaad5944675c6773dcecab418bbd94cac810d274124447949`.
- Focused Mollusk passes 4/4, covering fresh initialization, exact replay/no-write, every header
  status, payload gating, both short-account operations, explicit transition/replay, and
  byte-identical source/storage on rejected states.
- Surfpool 1.5.0 deployed the exact 14,704-byte VersionedLedger ELF through 15 ordinary Loader-v3
  write transactions. The 14,749-byte ProgramData matched the local ELF byte-for-byte. No Test
  Validator or direct-state deployment path was used.

## Boundary

V1 owns only a two-word identity/version header and one explicit migration edge. Payload schema,
payload transformation, rent/account creation, close/refund, owner reassignment, multi-step
migration graphs, runtime version selection, persistent pointers, heap collections, and dynamic
geometry remain separate policy. No Runtime leaf, Ops/IR/Component/Emit case, allocator, or map was
added.
