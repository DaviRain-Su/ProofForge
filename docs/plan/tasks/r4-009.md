# R4-009 — Add coinbase and blockhash through the environment component

## Goal

Prove the R4-008 boundary is a reusable target component by adding two Solidity-shaped environment
capabilities without extending top-level EVM Ops, IR, CFG, or the main emitter.

## Delivered contract

- `Evm.Sdk.Context.coinbase : Address` exposes the complete 20-byte block beneficiary. It does not
  silently truncate to the low UInt64 compatibility view.
- `Evm.Sdk.Context.blockHash (number : UInt64) : UInt256` exposes EVM `BLOCKHASH` and preserves its
  native recent-256-block and zero-result semantics. The bounded UInt64 input is explicit; a full
  UInt256 block-number input is not claimed by this slice.
- Production extraction lowers all three address limbs and all four hash limbs to
  `Component.Query.environment`. The block number is the query's one typed scalar operand.
- The target-owned environment interpreter captures `coinbase()` or `blockhash(number)` once per
  returned value and projects every limb from the generic wide-value cache.
- No allocation, storage write, external call, top-level value constructor, or main-emitter recipe
  was added. `Examples.TipJar` and `Examples.EvmCtx` are consumers, not owners of lowering policy.

## Evidence

- `Tests.EvmEnvironmentSpec` pins arity, limb bounds, canonical identity, Component extraction, and
  exactly one opcode observation per multi-limb result.
- Anvil compares `TipJar.coinbase()` with the current block beneficiary and
  `EvmCtx.blockHash(previous)` with the exact JSON-RPC block hash.
- Canonical target IR digests:
