# R3-008 — SVM generic seeded System facade

## Goal

Replace the application-visible `"vault"`-specific seeded System wrappers with one honest,
reusable compile-time ASCII seed contract. Keep instruction encoding and account geometry inside
the SDK/target verifier rather than adding four recipe operations or emitter cases.

## Delivered contract

- `Svm.Sdk.System.AsciiSeed.wellFormed`, `allocate`, `createAccount`, `assign`, and `transfer`
  expose the target's bounded policy, accept a static seed, and automatically place its byte
  length next to the literal in the System Program bincode payload. Lamports and space remain
  ordinary scalar instruction values.
- `Svm.Seed.Ascii.wellFormed` is the single bounded policy consumed by PDA, seeded System,
  extraction, and target Ops validation; the SDK does not carry a second copy.
- SysSeed and SysXfer select `"vault"` as application policy but consume only SDK names. A focused
  `"ledger"` fixture extracts all four instruction shapes, including the derived length `6`, so
  the source contract is not a renamed literal recipe.
- Extract's generic static Nat evaluator recognizes `String.length` of a literal when decoding a
  CPI u64 word. Seeded return semantics match the four instruction shapes rather than one seed
  spelling.
- The SVM Ops verifier validates 1–32 seven-bit bytes and exact adjacent bincode length only when
  the instruction and account metas match the four closed seeded-System geometries. Other CPI
  `.ascii` words remain generic data.

There is no new Op/IR/Component/Emit variant, instruction opcode, dynamic account table, heap
container, persistent pointer, or application-owned magic tag/meta/data list.

## Lifetime and fail-closed boundary

The seed is a compile-time literal. It is copied into the existing bounded 1,024-byte CPI scratch
plan for one invocation and never enters account state as a pointer. Empty, non-ASCII, over-32-byte,
or length-mismatched seed encodings fail before emission. Runtime-selected strings, arbitrary
instruction bytes, alternate account geometry, rent-aware resize, and arbitrary owner program ids
remain unavailable.

## Evidence

- Focused System SDK, SysSeed/SysXfer, and extraction suites pass. The alternate `"ledger"` fixture
  covers all four positive shapes; empty, non-ASCII, 33-byte, and forged-length fixtures fail
  closed.
- SysSeed retains canonical digest `490cec59af518f0c`; SysXfer retains
  `906efee37227cb35`.
- All six SysSeed/SysXfer assembly, ELF, and IDL artifacts are byte-identical to the pre-facade
  baseline. The aggregate `lake build Tests` gate passes 298 jobs.
- Mollusk and Surfpool are not repeated because both deployed machine programs are byte-identical;
  Surfpool remains the only deployment qualification environment.
