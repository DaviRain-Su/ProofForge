# R1-035 — Shared bounded byte and string prefix/suffix matching

Date: 2026-09-01
Status: done

## Goal

Give both targets reusable allocation-free `startsWith`/`endsWith` policy comparable to Rust slice
and String prefix/suffix checks and Solidity bytes/string helpers, without adding a target opcode,
component, allocator, pointer, or emitter recipe.

## Delivered contract

- `BoundedBytes.startsWith` and `endsWith` accept independently sized value and needle carriers.
  They reject either over-capacity frame, accept an empty canonical needle, reject a nonempty needle
  longer than the value, and ignore both inactive fixed-frame tails.
- Contains, prefix, and suffix now share one private static product-scan kernel. Its private scalar
  mode selects any valid start, start zero, or the unique final start; no mode/tag representation is
  exposed through the three Bool APIs and no allocation or runtime-selected geometry is introduced.
- `BoundedString.startsWith` and `endsWith` reuse the compiler-erased byte view. String validity
  remains a checked-constructor/target-codec invariant; matching is exact UTF-8 byte policy, not
  normalization, locale collation, or Unicode-scalar pattern matching.
- SVM `RawEntry` tags 33–36 bind canonical dual Borsh frames. The existing independent
  `Examples.EvmSearch` consumer binds each operation to two adjacent canonical standard-ABI tails.
  Core remains the sole policy owner.

## Evidence

- Extract/adapter guards pin the shared static bound at 64 iterations for SVM and 9 for EVM, all
  four logical method schemas, exact tags, complete Borsh/ABI input plans, scalar Bool exits, and
  both UTF-8 input gates for each String operation.

## Boundary

This is exact bounded contains/prefix/suffix policy, not concatenation, split/replace, regex,
Unicode normalization/collation, allocation, persistence, or a shared wire layout. No Runtime,
Ops, IR, CFG, Component, Extract, or Emit operation/case was added.
