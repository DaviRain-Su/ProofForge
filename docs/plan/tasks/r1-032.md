# R1-032 — Shared bounded byte and string equality

Date: 2026-09-01
Status: done

## Goal

Give both targets one allocation-free equality policy for bounded bytes and strings, comparable to
Rust slice/`String` equality and Solidity `bytes`/`string` comparison policy, without introducing a
container opcode or target emitter recipe.

## Delivered contract

- `Core.Value.BoundedBytes.equals` rejects an over-capacity frame or unequal runtime lengths, then
  compares exactly the active byte prefix with a compile-time bounded scan. Inactive fixed-frame
  slots are not observable. Both operands have the same bounded source type; changing capacity is
  an explicit conversion rather than an implicit equality coercion.
- `Core.Value.BoundedString.equals` reuses that one scan through a compiler-erased bounded-byte
  view. Like Rust `String`, strict UTF-8 is a carrier invariant enforced by checked constructors and
  both target boundary codecs; equality does not repeat validation, normalize Unicode, or infer
  locale policy.
- SVM `RawEntry` tags 27/28 consume two independent canonical Borsh Vec/String frames. EVM
  `EvmBounded` consumes two canonical adjacent standard-ABI dynamic tails. Both return typed Bool.

## Boundary

This is source-level value equality, not storage lookup, hashing, ordering, Unicode normalization,
substring/search, concatenation, allocation, or a persistent collection. Capacities and scans are
compile-time bounded. No Runtime/Ops/IR/CFG/Component/Emit case, pointer, allocator, or shared wire
layout was added; SVM and EVM retain separate Borsh and standard-ABI codecs.
