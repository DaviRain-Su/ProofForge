# R3-013 — Source-visible invocation-local bounded bytes

## Goal

Provide the byte-buffer/writer counterpart to transient `Vector64` without exposing arbitrary
dynamic allocation, a native pointer, or a persistent heap abstraction. The contract must follow
Solana's bounded 32 KiB downward bump allocator and no-op deallocation semantics.

## Delivered contract

- `Svm.Sdk.Transient.Bytes.bounded capacity` is compiler-erased invocation-local geometry. It
  exposes `begin`, checked byte `push`/`set`/`get`, `length`, `clear`, `finish`, and one fixed-width
  `appendLe64` codec primitive.
- Capacity is compile-time fixed. Every runtime byte is checked as canonical `0..255`; reads and
  writes use the active prefix rather than raw capacity. `appendLe64` requires capacity of at least
  eight bytes and atomically checks room for the complete record.
- The payload uses `Heap.Emit.emitAllocate`, the same official-shaped default-heap interpreter as
  `Vector64` and BatchRecorder. `finish` invalidates metadata but never rewinds the bump pointer.
- One byte-buffer handle and one `Vector64` handle may coexist. They share the bump position but
  own disjoint invocation-only pointer/length/capacity/active metadata.
- OOM, full/OOB, stale or capacity-mismatched handle, and noncanonical byte values terminate with
  distinct custom errors `0x1211` through `0x1214`. No partial mutation follows a failed gate.

The feature stays behind the existing `Svm.Component` call/query bridge. It adds no generic
top-level Ops/IR/main-emitter recipe, and neither source values nor account state can observe the
native pointer.

## Consumers and evidence

- `Examples.MemoryOps` covers dynamic push/set/get, clear/length, little-endian append, byte/vector
  coexistence, all four error classes, and exact default-heap exhaustion.
- `Examples.AccountView.stageSelectedBytes` independently stages a runtime-selected account word
  and reads its low little-endian byte.
- Focused Lean guards pin the component vocabulary, source effect order, allocation shape, byte
  load/store instructions, and terminal codes. Focused Mollusk suites pass 14/14 and 10/10.
- A clean isolated build passes all Lean tests, all 56 registered SVM builds, and the complete
  Mollusk suite, including Phoenix-v1 profile 76/76. Surfpool remains the only deployment gate;
  this slice introduces no `solana-test-validator` path.

## Remaining boundary

The byte and `Vector64` emitters deliberately retain distinct public typed components, but their
common active-handle/allocation/lifetime machinery is duplicated in this functional slice. The
next behavior-preserving slice extracts that machinery into one reusable transient linear-buffer
emitter contract. Multiple handles of the same kind, generic POD element layouts, variable-width
records, persistent pointers, reallocating growth, and reclaiming `free` remain unsupported.
