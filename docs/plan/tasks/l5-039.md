# L5-039 — Compose official Phoenix tag 5 through reusable account storage

## Goal

Implement the smallest official Phoenix-v1 `ReduceOrderWithFreeFunds` entry without adding a
Phoenix-specific top-level op, IR node, or main emitter branch. The source adapter must compose the
existing fixed-capacity account-resident storage routines and preserve Phoenix's exact wire,
account, mutation, and event contracts.

## Delivered

- Added raw tag 5 with exact 26-byte wire:
  `05 || side:u8 || price:u64-le || sequence:u64-le || size:u64-le`.
- Pinned four physical accounts: current executable program, readonly canonical `"log"` PDA,
  writable Phoenix market, and readonly trader signer.
- Made the profile/header/reducer source routines extraction-time account-index-parametric, then
  composed the generated probes and official raw adapter from the same `AccountStorage` routines.
- Preserved fixed-capacity, account-resident Sokoban geometry with one-based indexes and zero as the
  sentinel. No heap map, detached node, persistent pointer, runtime geometry, or unbounded walk was
  introduced.
- Implemented both sides: ask reductions release base lots; bid reductions release quote collateral
  using the pinned market lot/tick scalars. Partial reductions update the live slot and full
  reductions reuse the bounded RB-tree removal/free-list routine.
- Matched Phoenix sequencing and logging: a missing order advances market sequence without an event;
  an existing order emits one exact 128-byte authenticated signed self-CPI record, then advances
  sequence. Tag 5 performs no Token CPI.
- Defined the external-account index contract for raw adapters: the physical program prefix is not
  part of the external region, so `checkPdaSeeds 0` addresses physical account 1 here.
- Preserved target `.ext` effects before scalar bind success and normalized effectful raw handlers to
  scalar returns without managed-State writeback.
- Stabilized the SVM frame contract: account-storage scratch through offset 408, walked headers from
  512, scalar locals below 1024, CPI material in 1024..2048, and deep PDA/sysvar/storage scratch in
  2048..4096. CPI frame construction now fails closed if its complete frame exceeds 1024 bytes.

The resulting layering is:

```text
source semantics → Svm.EntryAdapter → Svm.AccountStorage → target-owned SVM backend/frame → sBPF
```
