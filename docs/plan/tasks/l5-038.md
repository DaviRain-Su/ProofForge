# l5-038 Reusable packed SVM entry adapter

## objective

把协议 wire decode、raw dispatch 与账户合同从业务语义和主 SVM emitter 中抽成可复用的
target-owned `EntryAdapter`。Phoenix、队列、Map、allocator 等上层组件只组合
`EntryAdapter` 与既有 `AccountStorage`，不再为每条外部协议指令增加顶层 Ops/IR/Emit case。

## boundary

```text
source semantics
  -> EntryAdapter (wire/account contract)
  -> AccountStorage (bounded account-resident containers)
  -> target-owned SVM backend
  -> sBPF
```

- `@[pf_svm_raw tag accountCount programAccount]` 只产生 opaque target annotation；它不是
  executable Op，EVM/Legacy 边界不得把它误当普通语言语义或静默丢弃
- `EntryAdapter` 只拥有 u8 tag、exact packed u8/u16/u32/u64 decode、bounded physical
  account prefix、当前 executable program authentication 和 generated/raw dispatch
- raw 参数先零扩展到普通 scalar locals，再进入原有 CFG；上层方法继续使用已有 value/effect
  vocabulary，不获得 instruction-data pointer
- raw 方法不得把 physical program account 解释为 ProofForge managed `State`；持久读写必须
  进入显式 external `AccountStorage` descriptor
- 实际账户数最多 64；adapter 可消费静态前缀并容许 bounded trailing accounts，但不开放
  unbounded remaining-account iteration 或持久 pointer
- raw tag/length 与 generated discriminator 必须不歧义；重复 tag、错长度、错 program、缺
  signer 和 malformed metadata 全部 fail closed

## implementation

- Core method 增加 opaque `annotations`，target projection 保留；SVM projection 解码成
  `EntryAdapter.MethodEntry`，canonical digest 只对 raw method 增加 adapter metadata
- 独立 `Svm.EntryAdapter.Emit` 负责动态定位 instruction data、短跳 trampoline、静态账户
  walk、program-id 校验和 packed scalar load；主 emitter 只提供既有 walk/signer/local callback
- generated handler 使用自身 account geometry；raw malformed input 不会回落后按 executable
  program account 的 data geometry 执行 generated prelude
- IDL 只发布 generated instructions；Legacy downgrade 遇到 annotation 显式拒绝

## verification

- `Examples.RawEntry` 同一 ELF 同时包含 generated `initialize/touch/get` 与
  `07 || u8 || u64` raw entry
- Lean guards 钉住 annotation、widths、target IR、raw/generated account geometry、assembly、
  IDL 隔离、Legacy fail-closed 和 managed-State rejection
- Mollusk 覆盖 exact decode、u8 zero-extension/u64 offset、trailing account、generated route、
  wrong tag、short/long data、missing signer、wrong/non-executable program account
- Surfpool 1.5.0 Loader-v3 真实交易部署：3,064-byte ELF、4 个 write transactions、
  Program/ProgramData layout 与 ELF exact bytes 全绿；不用 `solana-test-validator`
- 全量回归：200-job Lean、51 个 SVM registry build、Mollusk 238/238、Anvil 12/12

组合到 l5-037 的 reducer 和既有 signed self-CPI event recorder；不得新增 Phoenix-specific
顶层 Op/IR/main Emit case。随后独立实现 tag 4 Token withdrawal。

## non-goals

- 不开放 heap `Map`/`HashMap`、runtime capacity、detached node、persistent pointer 或

- 不把 Rust transient bump heap 当作 account-resident allocator
