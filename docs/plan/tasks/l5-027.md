# l5-027 fixed-capacity Phoenix bid/ask removal

## objective

为最小官方 Phoenix-v1 profile 的 512-node bid/ask books 增加通用 fixed-capacity
account-resident removal effect。按 Phoenix `FIFOOrderId` 与 Sokoban 0.3.0 的真实布局、
比较和 deletion 语义直接修改账户 bytes，不把订单树复制进 Rust heap，也不持久化
Map、节点 pointer、detached node 或 copied tree。

## invariants

- account、root/links/parent/key/sequence base、8-word stride、512 capacity 与 bid/ask side
  都是编译期常量；运行时只携带 2-word encoded order key
- writable、current-program owner、data length、encoded sequence side tag、完整 tree/free-list
  partition 与 key lookup 全部在第一次 store 前完成；missing/malformed/readonly/wrong owner
  均原子失败
- bid 按 price/encoded sequence descending 搜索且 sequence 高位为 1；ask 两者 ascending
  且高位为 0
- 删除按 Sokoban 0.3.0 原位执行 predecessor transplant、delete fixup 与 free-list push；
  allocator 继续使用 one-based index，`0` 只作 sentinel
- 被删 slot 的 key/value payload 保持 stale，只有 links/parent 与 allocator header 被更新；
  后续 insertion 从 LIFO free list 取回并完整重初始化同一固定 slot
- effect 在 extraction、target projection、CFG value mapping/canonicalization、static geometry、
  writable IDL 推导和 legacy fail-closed 路径中保持显式；源码入口不展开
  `accDataWordSetAt`
- emitter stack 只保存有界 scalar index 和临时 account-derived pointer；不存在 persistent
  pointer、heap tree copy、`Map`/`HashMap` 或无界 allocation

## verification

- Lean guard 钉住 bids `110/114/115/116/117`、asks `4210/4214/4215/4216/4217`、
  stride 8、capacity 512、side flag、零个展开 write 与两个 writable IDL meta
- 测试直接用 `lib-sokoban = 0.3.0` 构造各自满载的 512-node bid/ask tree；两个 books
  分别按独立 permutation 逐个删空，每一步比较完整 32,800 tree bytes 并调用官方
  `is_valid_red_black_tree()`
- 删空后各自重新插入 16 orders，完整 bytes 证明与官方 LIFO free-list slot reuse 精确
  一致；missing key、side mismatch、readonly、wrong owner 与 malformed topology 均原子失败
- digest `8290f8143ffc2374`；assembly 4,616,716 B；ELF 1,477,344 B；IDL 7,210 B
- Surfpool 1.5.0 用 1,460 个 Loader write + deploy + authority transactions 完成本地部署，
  并核对 exact 1,477,389-byte ProgramData；不用 `solana-test-validator`
- 全量 194-job Lean、50 个 SVM build、Mollusk 228/228 与 Anvil 12/12 回归通过
