# R3-006 — SVM classic Token SDK facade

## Goal

Move classic SPL Token composition behind reusable source-level names and role-typed account
layouts, without turning Token instructions or Phoenix account order into new Ops, IR, Component,
Extract, or emitter recipes.

## Delivered contract

- `Svm.Sdk.CpiAccount.Handle` distinguishes indexes relative to the external CPI account region
  from physical `Account.Handle` indexes. Both remain compile-time values and erase during
  extraction.
- `Token.CheckedTransferAccounts` names token program, source, mint, destination, and authority;
  `UncheckedTransferAccounts` is an explicit boundary for protocols that authenticate the mint in
  their own header. Their `wellFormed` gates reserve physical account zero and retain the static
  64-account lock ceiling.
- `transferCheckedWith`, `transferCheckedSignedWith`, and `transferSignedWith` compose those
  descriptors with the existing generic Runtime wrappers. The fixed-account transfer/mint/burn/
  account/approve/revoke/freeze/authority/native/multisig/data-size surface has the same SDK owner.
- Names expose fixed policy honestly: `initializeMint6` pins six decimals and no freeze authority;
  `baseAccountDataSize` requests the classic base account shape.

Phoenix and PhoenixV1Profile own four checked and two unchecked concrete account layouts under
`Examples`; business methods consume their names instead of repeating positional lists. No
Phoenix offset, seed, vault role, or instruction policy moves into `ProofForge/Svm`.

## Lifetime and fail-closed boundary

The facade contains only compile-time indexes and compile-time-shaped PDA seed arrays. It does not
allocate an account list or instruction buffer, store a pointer, create a persistent `Array`/`Map`,
or make account geometry runtime-selectable. Token-2022 extension semantics, Token state parsers,
program-id policy, seeded System, ATA, and Memo remain separate work.

## Evidence

- Focused descriptor/facade/example extraction gates pass, including Phoenix and PhoenixV1Profile
  descriptor ownership checks and twelve non-Phoenix classic Token consumers.
- Thirty-nine Token/Seat/Phoenix assembly, ELF, and IDL artifacts plus the three
  PhoenixV1Profile artifacts are byte-identical to their pre-facade baselines.
- Aggregate Lean, ownership, whitespace, and Markdown-link gates pass. Mollusk and Surfpool are not
  repeated because every affected machine artifact is byte-identical; Surfpool remains the only
  deployment qualification environment.
