# l5-031 FIFO RB-tree account-storage query

## objective

把 bid/ask 共用的 complete FIFO red-black-tree + allocator partition validator 从顶层 SVM
value kind 和主 emitter 迁入 `Svm.AccountStorage.Query`，并让 order insert/remove preflight
也组合调用同一个 bounded routine。

## invariants

- `FifoRbTree` 只描述编译期固定的 links、parent/color、price、sequence `Field` 和 side；
  四个 field 必须共享 account/stride/capacity/index/access shape
- slot index 固定 one-based，`0` 只作 null sentinel；capacity 固定且不超过 4096，因此
  live/free partition 始终使用 frame 底部固定 4096-bit bitmap
- query 自己拥有四参数 arity、read-only effects、geometry/capacity validation、walk/minimum
  account 与 canonical spelling；source helper 仍保留 `accDataRbTreeValid`
- complete preflight 原位检查 root/size/bump/free envelope、child↔parent reciprocity、color、
  black height、side tag、FIFO ordering、cycle/duplicate 与 live/free exact partition
- order insert/remove 不复制 validator，也不直接调用主 emitter 私有函数，而是组合
  `AccountStorage.Emit.emitQuery`
- 主 `loadVal` 仍只有一个 `.accountStorage query` case；generic extraction traversal、field
  collection、canonicalization 和 account inference 不新增 FIFO constructor 特判
- 不分配 heap `Map`/visited collection，不复制 node，不开放 runtime geometry、detached
  persistent node 或 persistent pointer

## verification

- guards 覆盖 query arity、shared one-based geometry、read-only effects、canonical spelling、
  malformed operand count 与 4096 capacity bound
- source digest 保持 `e9966de4a1795a47`；assembly 4,652,144 B、ELF 1,489,088 B、
  IDL 7,613 B 均保持不变
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 230/230、Anvil 12/12
  全绿；Surfpool 1.5.0 以 1,472 个 Loader write transactions 部署并核对 exact
  1,489,133-byte ProgramData
