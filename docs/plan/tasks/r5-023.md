# R5-023 — Checked wide-to-UInt8 casts

Date: 2026-08-31
Status: done

## Goal

Complete the shared allocation-free unsigned fixed-scalar SafeCast surface with UInt8 through the
existing generic fixed-scalar `Except` path, without adding a target opcode, runtime effect,
storage operation, allocation scheme, or width-specific lowering recipe.

## Delivered contract

- `Core.SafeCast.UInt128.toUInt8` first requires `w1 == 0`; `UInt256.toUInt8` first requires
  `w1 ||| w2 ||| w3 == 0`. Both then require `w0 < 2^8` before the explicit narrowing conversion.
  The first non-representable value is named once at the shared policy boundary. The helpers return
  the caller's typed error and perform no allocation, terminal, effect, or state write.
- R5-021's generic fixed-scalar `Except` bind is reused unchanged. UInt8 does not receive a new
  Ops, IR, CFG, Component, Runtime, or Emit case, and ordinary let/state/effect normalization is
  unchanged.
- Existing consumers were extended instead of adding single-use fixtures.
  `EvmSafeCastAccumulator.setMode` is permissionless UInt256→UInt8 replacement with independent
  width and zero errors. `EvmSafeCastConfig.setLevel` applies owner authorization first, then
  UInt128 narrowing, zero policy, and one literal UInt8 state update.
- `setLevel` deliberately returns the successful byte widened to UInt64. The unauthorized branch
  must preserve `Access.ownerViolation = 0x1001`; returning UInt8 there would silently truncate the
  control sentinel to `1`. Narrow storage and full-width control/result policy therefore remain
  separate, explicit contracts.
- Signed, saturating, and wide-to-wide casts remain separate consumer-driven work.

## Evidence

- Focused Lean truth tables cover exact UInt8 max, the first low-word overflow, and every upper
  limb. Extraction guards prove every upper-limb test and the exact `w0 < 2^8` gate dominate the
  narrowed local bind, and pin both updated state layouts, ABI, and IR digests. The focused gate
  passes 179 jobs; the aggregate Lean gate passes 411 jobs.
- `EvmSafeCastAccumulator` digest is `f9eb0bacf4d40cfd`; Yul is 10,722 bytes and deployment bytecode
  is 1,657 bytes. `EvmSafeCastConfig` digest is `40d1569adcdc05a6`; Yul is 21,039 bytes and deployment
  bytecode is 3,139 bytes.
- Dedicated Anvil matrices cover the UInt8 exact boundary, low-word `2^8` overflow, every upper
  limb, authorization/application-policy ordering, full-sentinel unauthorized behavior,
  preservation of the existing UInt64/UInt32/UInt16 fields, and raw-storage atomicity. The clean
  EVM build validates all 40 registered contracts against the actual artifact manifest, and
  aggregate Anvil runs 40/40 with no skips.

## Boundary

The cast helper is target-neutral pure policy, not a shared physical ABI or storage contract. EVM
consumers use canonical Solidity wide calldata and named errors; a future SVM consumer must qualify
its own entry/result plan. UInt8 remains a fixed scalar value rather than a heap allocation, and no
pointer, dynamic Map, unchecked truncation, or duplicated numeric sentinel is exposed to contract
applications.
