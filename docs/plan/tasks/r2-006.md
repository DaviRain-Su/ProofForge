# R2-006 — Allocation-free SVM invocation telemetry

## Goal

Expose the official remaining-compute, invocation-stack, and numeric logging host functions without
adding application-specific operations, heap-backed source values, persistent pointers, or another
main-emitter recipe.

## Delivered contract

- `Svm.Telemetry.Query` owns `remainingComputeUnits` and `stackHeight`; `Svm.Telemetry.Call` owns
  `logComputeUnits` and the exact five-word `log64` shape. Both cross the existing generic Component
  bridge, so generic SVM Ops, IR, CFG, and the main emitter remain unchanged.
- `Svm.Sdk.Telemetry` is the source-facing facade. Applications do not name component constructors
  or syscall symbols.
- Emission binds the exact official symbols `sol_remaining_compute_units`, `sol_get_stack_height`,
  `sol_log_compute_units_`, and `sol_log_64_`. The logging symbols' trailing underscores are part of
  the ABI.
- All values are scalar `UInt64`; the calls allocate no buffer and expose no native pointer. Numeric
  logging uses the host's fixed five-register ABI rather than a source `Array`, `Vec`, `String`, or
  map.

`stackHeight` is an invocation fact: a transaction-level instruction observes 1 and each CPI adds
one. `remainingComputeUnits` is a live snapshot and the query itself consumes compute, so it must not
be treated as a stable budget constant. The logging calls are diagnostics, not a stable typed-event
or authorization protocol.

## Evidence

- Focused Lean guards prove all four source calls lower behind the Component bridge and bind all four
  exact syscall symbols.
- `Examples.Info` consumes the SDK without adding target policy. Mollusk verifies top-level stack
  height 1, a live nonzero compute snapshot below the instruction limit, unchanged account data, and
  successful execution of both allocation-free loggers. The live numeric log is
  `0x1, 0x2, 0x3, 0x4, 0x5`.
- The updated Info digest is `92992971c8b3fd12`; its ELF is 8,536 bytes.
- Surfpool 1.5.0 deployed that exact ELF through nine Loader-v3 write transactions and verified the
  complete ProgramData bytes. The reusable smoke target now accepts Info; no Test Validator path is
  introduced.
