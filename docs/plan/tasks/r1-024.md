# R1-024 — Shared allocation-free UInt64 math

Date: 2026-08-31
Status: done

## Goal

Provide the first target-neutral reusable math component for ordinary bounded contract arithmetic,
with independent SVM and EVM consumers and no target Runtime, Ops, IR, Component, or Emit recipe.

## Delivered contract

- `Core.Math.UInt64` provides `min`, `max`, overflow-safe floor `average`, and checked `ceilDiv`.
  `average` uses `(a &&& b) + ((a ^^^ b) >>> 1)`, so even two maximum inputs never construct an
  overflowing sum. `ceilDiv` rejects denominator zero with the caller's typed error, maps zero
  numerator to zero, and otherwise evaluates `(numerator - 1) / denominator + 1` without an
  overflowing `numerator + denominator - 1` intermediate.
- The helpers are ordinary `@[pf_inline]` Lean over existing UInt64 scalar control and arithmetic.
  They allocate no collection or pointer, perform no target extension effect or hidden state write,
  and are re-exported by both target SDK umbrellas.
- `BatchSizer` is an SVM consumer with a `zeroCapacity` error and `lastBatchCount` state policy.
  `EvmPriceBand` independently owns a `zeroTick` error and `lastQuote` update policy. Both expose
  read-only min/max/midpoint queries plus one stateful ceil-division method; neither physical state
  layout nor error vocabulary is shared between targets.
- Signed math, saturating operations, full-precision multiply/divide, square root, logarithms, and
  wide UInt128/UInt256 helpers remain fail closed until a bounded implementation and real consumer
  justify each surface.

## Boundary

This is shared source math, not a shared ABI, account layout, storage layout, or error protocol.
SVM still owns Borsh/return-data and fixed-account state; EVM still owns Solidity ABI and storage.
Applications own authorization, domain validation, typed errors, and whether a successful result is
persisted. No host `BigInt`, dynamic allocation, unchecked division, or target-specific shortcut is
part of the component.
