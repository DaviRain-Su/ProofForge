# R1-025 — Shared saturating UInt64 arithmetic

Date: 2026-08-31
Status: done

## Goal

Complete the mainstream unsigned saturating arithmetic trio used by both Rust primitives and
OpenZeppelin Math, while preserving ProofForge's allocation-free target-neutral SDK boundary.

## Delivered contract

- `Core.Math.UInt64.saturatingAdd` returns UInt64 maximum exactly when `maximum - left < right`;
  the subtraction is always representable and the addition occurs only in the fitting branch.
- `saturatingSub` returns zero when `left < right`, otherwise the exact difference.
  `saturatingMul` returns zero for a zero left operand, then uses `maximum / left < right` to choose
  the maximum or the exact product. It never divides by zero and never evaluates an overflowing
  arithmetic branch.
- All three are ordinary `@[pf_inline]` Lean over existing scalar values and control. Structural
  extraction guards pin each preflight around the matching arithmetic operands and reject every
  target extension effect. No Runtime, Ops, IR, CFG, Component, Emit, allocation, pointer, hidden
  write, or shared physical layout was added.
- Existing independent consumers gained application-owned transitions rather than new fixture
  programs. SVM `BatchSizer` exposes reserve/consume/amplify capacity policy; EVM `EvmPriceBand`
  exposes increase/discount/scale quote policy. Their account/ABI/storage bindings remain separate.

## Boundary

Saturation is explicit policy, not a replacement for ProofForge's checked default arithmetic.
Signed saturation, saturating casts, wide UInt128/UInt256 saturation, full-precision `mulDiv`,
square root, and logarithms remain fail closed. Applications must deliberately call these helpers;
the compiler never silently changes `+`, `-`, or `*` semantics.
