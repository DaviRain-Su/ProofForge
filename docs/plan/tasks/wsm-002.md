# wsm-002 Lean → WAT → .wasm：XRPL 拥有 host import 与存储布局

## objective

纠正 wsm-001 的发射目标。ProofForge 的 WASM 产物是 **`.wasm` 字节**，不是 Rust 源。
Lean 不经过 rustc / `xrpl-wasm-std` / scaffold-xrp。链间差异只在两处，全部由
`Wasm/<Chain>/Host` 拥有：

1. **host function（runtime）**：wasm import 表（模块名 + 函数名 + 签名）
2. **存储布局**：UInt64 槽如何落到 linear memory，以及经哪条 host 调用持久化

家族共享的是 Core 标量 / 控制流 → WAT 的 lowering（`i64` 算术、`if`、locals），
对标 `Evm.Emit` 出 Yul、`Svm.Emit` 出 `.s`。组装器是锁定的 `wat2wasm`（wabt），
对标 `solc 0.8.34` / `sbpf 0.2.2`。

XRPL 第一条链钉 XLS-0102 的 import 模块 `host_lib`（不是 Rust 助手名
`get_data` / `get_current_contract_call`）。v0 Counter：一个 UInt64 槽经
`home_le_field`（读 home 对象 `Data`）/ `set_data`（写）持久化；mutating export
`-> i32` 状态码，view export `-> i64`。

`deployable` 对主网仍为 false。本切片出 `.wasm` 并断言 import 表；本地链部署
是 [wsm-003](wsm-003.md)，不在这一刀。不接 AlphaNet。

## 不做什么

- 不把 Lean 编译器（leanc → C → emcc）当链上 artifact
- 不保留 Core→Rust 发射器作为产物路径（wsm-001 的 `.rs` 从 CLI / Registry 产物
  面拿掉；Rust 文件可留作对照夹具，不是 artifact）
- 不发明 `pf` 通用 import 模块；不把 wasmtime 当链宿主
- 不声称 XLS-0102 已覆盖 XLS-0101 智能合约的全部 host（规范写明目前只钉
  Smart Escrow；同名函数「将可从 smart contracts 访问」）。v0 只用
  `host_lib.{home_le_field,set_data}` 这一对存储调用，缺席的 capability
  （ledger time / caller / hash）继续 fail closed
- 不锁 rustc / cargo / flint

## verification

- `pf build --target xrpl --out build/xrpl` 写 `Counter.wasm`（及对照 WAT）；
  digest 行钉 canonical IR（域仍 `xrpl-bedrock|`，拼写因产物形状变了要重钉
  Registry，旧 `e029f72296e320be` 作废）
- 发射锚点：`(import "host_lib" "home_le_field" …)`、
  `(import "host_lib" "set_data" …)`；**没有** `get_data` /
  `get_current_contract_call` / `xrpl_wasm_std`
- mutating export `initialize` / `increment` 返回 `i32`；`get` 返回 `i64`
- checked 五则在 WAT 里是显式 overflow 检查 + 状态码 1/2，不依赖 Rust
  `checked_*`
- `#pf_xrpl_reject Examples.Svm.Clock` / `Examples.Evm.EvmCtx` 仍 fail closed
- `runtime-tests/xrpl/check.sh`：用钉死版本的 `wat2wasm` 编过，再用 wasm 解析器
  断言 import 模块 == `host_lib`、所需 export 存在（不跑 rippled / AlphaNet）
- `--target wasm` 仍提示家族不是链
