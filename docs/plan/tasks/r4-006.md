# R4-006 — Full-width EVM environment words

## Goal

Expose the missing mainstream block/gas queries without truncating native 256-bit EVM values or
leaving fork-sensitive opcode semantics implicit.

## Delivered contract

- `Evm.Runtime` and `Evm.Sdk.Context` expose full `UInt256` values for `gasLeft`, `baseFee`,
  `prevRandao`, and `gasLimit`.
- `Evm.Sdk.Context` also owns the explicit truncating `callerLow`/`selfLow` compatibility views;
  applications do not import target Runtime leaves directly.
- Extract projects each ordinary Lean result into four fixed UInt64 limbs. One reusable emitter
  policy captures the environment opcode once per result and serves all limbs from the existing
  render cache; applications never manipulate Yul or target words.
- Assembly pins both solc 0.8.34 and the Cancun EVM target. Therefore opcode `0x44` has the required
  `PREVRANDAO` semantics and cannot silently become pre-Paris `DIFFICULTY`.
- `Examples.EvmCtx` and `Examples.TipJar` independently import and consume only the SDK facade.
  Anvil compares
  BASEFEE, PREVRANDAO, and GASLIMIT against the current block and checks a positive GAS result.

## Resource and failure boundary

These are genuine VM observations, so they extend target-owned value Ops/IR and generic EVM
emission. They allocate no runtime memory or storage, add no application/component recipe, and do
not expose `tx.origin`, arbitrary opcodes, blockhash, coinbase, code inspection, or a configurable
pre-Paris target. All wide values remain allocation-free fixed limbs.

## Evidence

- Focused Lean extraction/emission checks cover the SDK source identity, typed `uint256` result,
  canonical digest identity, opcode rendering, and ABI JSON.
- EvmCtx and TipJar assemble under solc 0.8.34 with `--evm-version cancun` and pass their Anvil
  runtime gates.
