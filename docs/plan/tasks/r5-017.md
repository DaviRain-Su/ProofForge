# R5-017 — Persistent bounded EVM enumerable set

## Goal

Bind the shared bounded Set law to honest EVM persistent storage as a reusable O(1) enumerable
UInt64 set, without adding a container opcode, runtime allocator, pointer, application-specific
extractor rule, or pretending that a hashed map is intrinsically enumerable.

## Delivered contract

- `Evm.Sdk.StorageEnumerableSet.Descriptor capacity` declares one ordinary static
  `Vector UInt64 capacity` backing prefix, one adjacent live-count scalar, and one compile-time
  hashed `U64Map` namespace from key to position+1. Position zero is the absent sentinel, so key
  zero remains a valid member.
- SDK policy owns count/position validation, membership evidence, insertion geometry, positional
  enumeration, and the middle-vs-last swap-remove decision. A malformed count, out-of-range
  nonzero position, or backing-key mismatch fails closed before every mutation.
- Insert, contains, value-at, and remove are O(1). Middle removal moves the final live value and
  repairs its position; last/only removal avoids the redundant backing self-write and repair.
  Stale values beyond the live prefix remain unreachable. Bulk clear is deliberately unavailable
  because honestly clearing every hashed position is O(n).
- EvmAllowlist is an owner-gated capacity-4 consumer with strict malformed views and shared
  `CapExceeded()` full behavior. EvmIdRegistry is an independent permissionless capacity-3
  consumer with typed `full()` and a non-reverting malformed membership fallback.
- Consumers retain literal fixed-vector/count writes and explicit map puts because those are the
  extractor's honest physical boundary. They contain no numeric static slots, selectors, topics,
  lower IR/Emit imports, or hidden returned-set transition.

## Generic extraction correction

The first runtime swap-remove exposed a compiler sequencing bug, not an SDK policy bug: an ordinary
Vector store could re-evaluate its map-derived index after the preceding map effect had cleared that
entry. `mergeEvmStores` now uses component effect summaries to snapshot mutable target queries into
lexical locals before storage-writing/external-call effects, then preserves the established
`effect → final State stores → return` order. The same simultaneous-update path also snapshots
later wide State leaves before an earlier leaf store can change their shared pre-state input.

`Tests.EvmEffectStateSpec` owns a container-independent map-query/index regression. The correction
intentionally changes Token and Credits IR: their multi-limb State writeback now observes one
pre-transition value. Token digest is `b69773a11a64286e`, Credits is `b419d86e92ae9e9e`; the corrected
Token also compiles under locked solc 0.8.34 instead of the prior Yul StackTooDeep failure.

## Explicit boundary and follow-up

This v1 stores UInt64 keys with fixed compile-time capacity. Address/Bytes32/wide keys, bulk clear,
ordered iteration, checkpoints, dynamic capacity, packed backing, and unbounded Solidity-style
arrays remain unavailable. They require separate bounded physical contracts, not another main
Runtime/Ops/IR/Emit recipe.
