# R5-011 — Add an honest EVM runtime-code observation policy

## Goal

Expose the common Solidity `address.code.length != 0` decision through the stable SDK without
adding another opcode recipe or claiming that code presence proves account identity or call
success.

## Delivered contract

- `Evm.Sdk.Address.hasCode (address : Address) : Bool` is exactly
  `Address.codeSize address != 0` at the observation point. It composes the existing R4-010
  `EXTCODESIZE` query with an ordinary UInt64 comparison.
- The API documents the important VM edges: contracts under construction and precompiles can
  report zero runtime-code size, while nonzero code does not guarantee a particular call succeeds.
  It therefore must not be used as an EOA/authentication test.
- The policy is an explicit observation. It is not silently inserted before existing closed calls,
  does not expose arbitrary calldata/callee/returndata, and makes no revert-bubbling claim.
- No Runtime, Ops, IR, Component, Environment emitter, main emitter, memory, storage, selector, or
  allocation case was added. The SDK reuses the existing target-owned Environment component.

## Evidence

- `Tests.EvmCtxSpec` pins contract-facing SDK delegation.
- `Tests.EvmEnvironmentSpec` recursively verifies that the boolean result still owns exactly an
  Environment `codeSize20` query and that the generated contract contains one EXTCODESIZE for each
  explicit `codeSize`/`hasCode` entry.
- The EvmCtx Anvil gate checks `true` for the deployed contract and `false` for a nonexistent
  address while retaining the direct code-size/hash checks.
- EvmCtx target-IR digest: `4eb0c4cd2c0b1239`.
- solc 0.8.34 / Cancun artifact: 3,383-byte deployment bytecode; Yul SHA-256
  `907c54ed0995a1da6a9385bde998cbbb9d851a483766d054f5367e065264d42f`; binary SHA-256
  `2e7cdeebe5cc700207651acab21d65cbc556c33b8aa4baf780f76d76110e1fad`.

The next safe-call slice must define how a specific call result and revert payload interact with
this observation; this predicate alone intentionally does not decide that policy.
