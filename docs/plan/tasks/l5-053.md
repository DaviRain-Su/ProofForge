# L5-053 — Route Phoenix audit recording through a static source facade

## Goal

Remove Phoenix-v1's remaining positional recorder geometry from contract helpers. Reuse the same
static audit descriptor already consumed by cancellation, preserve the existing bounded recorder
backend, and avoid extending Ops, IR, components, CFG, or the emitter for a source-level API.

## Delivered

- Added `ProofForge.Svm.BatchRecorder.Source` with source-facing `begin`, `append`, and `finish`
  operations over a compile-time `BatchRecorder.Config`. Extraction erases the descriptor into the
  existing positional runtime intrinsics; only the header/record scalar values, append enable value,
  and PDA bump remain dynamic.
- Migrated Phoenix's batch open, Reduce append, Place append, and finish helpers to that facade.
  They all consume the single `marketRecorderConfig` in `Examples.Svm.PhoenixV1Profile`; cancellation
  continues to consume the same descriptor through `FifoCancel.Source`.
- Kept Phoenix-specific account selection, authority seed, limits, wire header, event tags, and
  record layout in `Examples`. `ProofForge/Svm` contains only the reusable recorder interface and
  has no Phoenix profile or offsets.
- Added no Core/SVM opcode, top-level IR node, component variant, CFG case, or main-emitter case.
  The existing component retains the invocation-local byte buffer in Solana's bounded bump heap;
  source code receives no pointer or runtime-selected geometry. Persistent state remains fixed
  account bytes with one-based indexes and the `0` sentinel, not a heap `Map`/`Vec`.

The stable source boundary is now:

```text
Phoenix audit profile + wire records (Examples)
        │ static BatchRecorder.Config
        ▼
BatchRecorder.Source (ProofForge/Svm)
        │ compile-time descriptor erasure
        ▼
existing BatchRecorder component/runtime → bounded scratch heap + signed self-CPI
```
