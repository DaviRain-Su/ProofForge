# R3-027 — Persistent bounded SVM enumerable set

Date: 2026-08-31
Status: done

## Goal

Provide an account-persistent, fixed-capacity UInt64 set with membership, bounded enumeration, and
swap-remove as one reusable SVM SDK component. The component must derive its complete physical
layout from `(account, baseWord, capacity)`, support value zero, fail closed on malformed backing
metadata, and reuse existing account-storage/RB-tree operations instead of adding a Set opcode or
container emitter.

## Delivered contract

- `Core.Collections.BoundedSet` now owns the target-neutral position+1 and swap-remove laws:
  canonical count, absent/live/forged positions, insertion position/count, moved-last position,
  removal count, and bounded enumeration. Existing EVM `StorageEnumerableSet` delegates those pure
  decisions to Core while retaining its separate static/hashed-slot representation.
- `Svm.Sdk.StorageEnumerableSet.Descriptor.oneBased account baseWord capacity` derives one compact
  layout: an active value prefix, four RB allocator/root header words, and seven-word key4 nodes
  containing links, parent/color, four key words, and reverse enumeration position. Descriptors are
  compile-time data and erase during extraction; applications supply no node stride, root offset,
  payload offset, pointer, runtime capacity, or allocator geometry.
- `initialize` explicitly canonicalizes the existing one-based map allocator. `size`, `contains`,
  `insert`, zero-based `valueAt`, and `remove` compose only existing checked `Field` and `RbMap`
  reads/writes/search/insert/remove. Value `0` remains a valid member because map absence uses node
  `0` while reverse positions use position+1.
- Membership and removal trust a map hit only after validating its live reverse position and active
  backing value. Middle removal validates the moved final value's node and reverse position before
  deleting anything, then repairs both the active prefix and moved-node position. Last/only removal
  needs no move. Full, absent, malformed count/position/backing, uninitialized, and short-account
  outcomes fail closed; Solana instruction rollback covers any target-level length failure.
- `Examples.MemberDirectory` chooses strict duplicate/full/missing policy at capacity 4.
  `Examples.UniqueRoster` independently chooses idempotent enroll/withdraw policy at capacity 5.
  Protocol errors and policy remain under `Examples`; the reusable target-owned collection remains
  under `ProofForge/Svm/Sdk`.
- Extraction now reduces a match over a pure static SDK descriptor before classifying lambdas as
  deferred continuations. This generic composition fix preserves effects in the selected branch;
  it adds no Runtime leaf, Ops/IR variant, Component case, or Emit recipe.

## Boundary

V1 stores only UInt64 keys and exposes bounded indexed reads, not a general iterator object. It has
no runtime-selected geometry, dynamic capacity, persistent pointer, heap allocation, HashMap,
automatic account creation/rent/close/version migration, bulk set algebra, or arbitrary POD key
shape. Wider keys/values and versioned account codecs remain separate bounded SDK work.
