# R5-018 — Persistent bounded EVM UInt64 checkpoints

Date: 2026-08-30
Status: done

## Goal

Provide the bounded persistent equivalent of OpenZeppelin `Checkpoints.Trace*`: ordered
`(UInt64 key, UInt64 value)` history with latest lookup, lower-bound lookup, monotonic append,
and same-latest-key overwrite, without adding a checkpoint opcode, dynamic storage allocator,
pointer, unbounded Solidity array, or application-specific Extract/IR/Emit case.

## Delivered contract

- `Evm.Sdk.StorageCheckpoints.Descriptor capacity` declares two adjacent ordinary static
  vectors (`keys`, `values`) followed by one live-count scalar. Descriptor validation accepts
  only the explicitly qualified V1 capacity range `1..4` and rejects zero, wider, malformed,
  displaced, or non-UInt64 geometry.
- Runtime policy validates `count ≤ capacity` and strict ordering across the complete live key
  prefix before every update or lookup. Duplicate/decreasing persisted keys and over-capacity
  counts are malformed and fail closed.
- A key equal to the latest checkpoint overwrites only its value and does not grow count, even
  when full. A greater key appends only when capacity remains. A decreasing candidate remains an
  ordered-key error rather than being masked as capacity exhaustion.
- `latestIndex` and `lowerBoundIndex` provide fixed-frame lookup geometry. Lower bound means the
  first live key greater than or equal to the query; no match, empty state, and malformed state
  use the consumer's explicit zero view fallback.
- EvmCheckpointBook is an owner-gated capacity-4 consumer with shared `CapExceeded()` on valid
  full growth. EvmCheckpointTrace is an independent permissionless capacity-3 consumer with
  application-owned `full()`/`unordered()` errors. Both keep literal State vector/count writes
  and explicit bounds proofs visible at the extraction boundary.

## Resource and ownership boundary

V1 is fixed arity rather than pretending to implement an unbounded trace. A mutation touches at
most one key slot, one value slot, and the count slot; overwrite touches only one value slot.
Latest reads one selected value after bounded metadata checks. Lower-bound lookup compares at
most four key lanes and reads at most one selected value. Every operation is O(1) under the
qualified ceiling; no loop, map, heap object, allocation, pointer, or hidden transition survives
extraction.

The component adds no Runtime leaf, top-level Ops/IR constructor, Component variant, or Emit
recipe. It composes the existing ordinary fixed-vector extraction and static `sload`/`sstore`
paths. Application authorization and error policy remain in `Examples`.

## Explicit boundary

This slice supports only UInt64 keys/values and capacities `1..4`. Wider values, Address/Bytes32
keys, upper-bound/recent lookup variants, binary-search ceilings, dynamic capacity, history
pruning, and unbounded arrays remain unavailable. Raising the capacity requires a separately
qualified bounded lookup/write shape and resource manifest, not a runtime allocator or emitter
special case.
