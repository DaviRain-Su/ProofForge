# L5-059 — Two-maker noncrossing remainder posting

## Goal

Complete the bounded `matchLimit = 2` Limit slice when two makers are consumed and the taker's
remainder no longer crosses. Reuse the existing account-resident ordered map, one-based allocator,
invocation-local scalar frame, batch recorder, collateral fields, and optional return plan; do not
add a Phoenix operation or protocol branch to generic Ops, IR, CFG, Component, or Emit layers.

## Delivered

- The fixed two-step read-only preflight now accepts either full taker exhaustion or a live
  remainder whose strict successor is absent or noncrossing. It validates selected-book capacity,
  initialized order sequence, duplicate key absence, successor TIF, collateral arithmetic, fee
  arithmetic, and both makers before the first persistent write or audit effect.
- The fixed two-step replay settles both exact makers through the existing account-storage map
  operations. Bid takers lock remainder quote lots at the taker's limit price; ask takers lock the
  remaining base lots. Taker free/locked balances, maker balances, aggregate fee, market sequence,
  and order sequence are committed as one rollback-safe Solana instruction.
- The audit order is `Fill(0) → Fill(1) → FillSummary(2) → Place(3)`. A posted remainder returns
  one Borsh `FIFOOrderId` through the existing bounded optional-return plan; full taker exhaustion
  still leaves return data unset.
- Phoenix crossing, collateral, fee, sequence, TIF, event, and wire policy remain in
  `Examples.Svm.PhoenixV1Profile`. The generic SVM layer receives only its existing fixed geometry
  descriptors and scalar operands; no protocol-specific opcode, IR node, or emitter branch was
  added.
- Persistent state remains account bytes with fixed stride/capacity, one-based indexes, and the
  `0` sentinel. No heap `Map`/`Vec`, detached node, runtime geometry, native pointer, or unbounded
  traversal is stored in an account. Invocation-local scratch remains bounded and cannot replace
  the account-resident allocator.

The resulting composition is:

```text
Phoenix match/crossing/collateral policy (Examples)
        │ fixed two-step read-only scalar-frame preflight
        ▼
validated makers + aggregate quote + strict successor
        │ fixed replay through AccountStorage
        ▼
two maker settlements → taker/fee settlement → optional fixed-book insertion
        │
        └── BatchRecorder + optional packed return
```
