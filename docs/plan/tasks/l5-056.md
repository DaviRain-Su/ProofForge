# L5-056 — Bounded Phoenix remainder posting on reusable account storage

## Goal

Complete the one-maker Limit slice when a smaller maker is consumed and the taker's remainder no
longer crosses. Compose the existing fixed-account ordered map, collateral fields, recorder facade,
and optional return contract; do not add a Phoenix opcode, protocol layout, or branch to generic
IR or emitters.

## Delivered

- The exact modern `OrderPacket::Limit` slice now consumes a smaller maker and posts the remaining
  base lots to the taker's own fixed 512-slot book when the next opposite order is absent or
  noncrossing. Bid remainders use Phoenix's complemented sequence; ask remainders use the raw
  sequence. The order sequence advances only when posting succeeds, while the market/audit
  sequence advances once for the successful instruction.
- Posting uses the existing `Examples.PhoenixV1.Layout` facade over generic
  `AccountStorage.Source.cursorOrderedPair`, insertion/removal, fixed-record reads/writes, and
  one-based allocation. Bid collateral locks quote lots at the taker's limit price; ask collateral
  locks the remaining base lots. Maker and taker balances, aggregate taker fee, and maker removal
  are committed with the same account-resident representation.
- The recorder emits official `Fill(index=0) → FillSummary(index=1) → Place(index=2)` ordering.
  Successful posting returns the existing fixed-width encoding of one Borsh `FIFOOrderId` through
  the generic optional-return contract. Fully or partially exhausted takers still leave return data
  unset.
- Full selected books, eviction, duplicate/uninitialized sequence state, a remainder that still
  crosses after `match_limit=Some(1)`, TIF, and unsupported self-trade/funds policy fail closed.
  These checks happen before protocol-visible success; Solana instruction rollback preserves
  atomicity on every error path.
- No persistent heap `Map`/`Vec`, detached tree, runtime geometry, persistent pointer, or unbounded
  traversal was introduced. Generic Ops, IR, CFG, component vocabulary, and main Emit files are
  unchanged; Phoenix layout, crossing, collateral, fee, event, and packet policy remain in
  `Examples`.

The composition boundary is:

```text
Phoenix one-maker/remainder policy (Examples)
        │
        ├── strict opposite-book cursor + maker removal
        ├── taker-side fixed-book insertion + collateral fields
        ├── static BatchRecorder facade
        └── generic optional packed return
```

## Next

Keep the ordered storage, recorder, and return boundaries fixed. Before expanding protocol policy,
add a reusable invocation-local bounded scalar fold/frame abstraction over the existing local and
`forBody` IR so cursor, filled lots, adjusted quote, maker quote, stop, and error scalars do not
become persistent account fields. Then compose it with the same account-storage facade for bounded
multi-maker matching and aggregate fee settlement. Eviction, TIF, alternate self-trade behavior,
soft funds, and remaining accounts stay fail closed until their complete transitions are covered.
