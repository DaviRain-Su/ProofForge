# L5-051 — Route Phoenix reduce through static storage components

## Goal

Remove Phoenix-v1 reduce paths and their shared cancel scalar reads from positional account
geometry. Keep the concrete Phoenix profile in `Examples`, expose reusable static map/field
operations from the SVM SDK layer, and preserve the existing bounded account-resident execution
model without extending the emitter.

## Delivered

- Added a source-facing `AccountStorage.Source.validate` operation over a static `RbMap` handle.
  The facade owns the map's allocator-header encoding, root/size/cursor reads, packed cursor split,
  stride, capacity, key shape, and bid ordering. Contract code no longer passes those values or
  reconstructs validator calls.
- Generalized the extractor's existing FIFO/Key4 validator geometry from direct literals to
  statically reducible literals. This erases opted-in descriptor projections but adds no Phoenix
  name, runtime geometry, target operation, IR node, component variant, or main-emitter case.
- Extended `Examples.PhoenixV1.Layout` with named lot-size and price geometry, complete map
  validation, order owner/size reads, order size writes, removals, and trader balance access. The
  offsets and capacities used by the migrated 512/512/128 path are centralized in the `small`
  layout instance; the remaining positional cancel/recorder paths are explicitly left for the next
  slice.
- Rewrote the bid/ask free-funds reducers and their generated/raw adapters around that layout. The
  reducer now expresses `find order → verify owner → reduce/remove → unlock balance` without
  positional book/trader words. Raw reduce routes and their claim/withdraw sequencing also use
  named market sequence, lot-size, order, and balance operations.
- Kept persistent state entirely in fixed account bytes with one-based indexes and `0` sentinels.
  No heap `Map`/`Vec`, persistent pointer, copied node, unbounded traversal, runtime-selected
  offset, or dynamic storage geometry was introduced.
- The migrated Phoenix sources remain only under `Examples`; the obsolete `Projects` path is now
  absent from the checkout. Historical task references to its former paths remain migration
  records, not live source ownership.

The source boundary is now:

```text
Phoenix static profile (Examples)
        │ named fields/books/traders
        ▼
AccountStorage.Source (ProofForge/Svm)
        │ static descriptor erasure
        ▼
existing Component → AccountStorage validator/find/read/write/remove backend
```

semantics expand.
