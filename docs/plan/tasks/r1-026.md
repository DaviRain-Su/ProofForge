# R1-026 — Shared UInt64 integer logarithms

Date: 2026-08-31
Status: done

## Goal

Add the allocation-free floor integer logarithms shared by Rust-style unsigned integer policy and
OpenZeppelin Math without introducing a target opcode, host allocation, or duplicated low-level
emitter recipe.

## Delivered contract

- `Core.Math.UInt64.log2`, `log10`, and `log256` return the floor logarithm and map zero to zero.
  Their maximum UInt64 results are respectively 63, 19, and 7.
- The implementation uses existing scalar locals and exact 6-/5-/7-step bounded loops. Binary
  order reduces by shifts 32/16/8/4/2/1; decimal order uses only the nonzero literal divisors
  10^16/10^8/10^4/10^2/10; byte order shifts at most seven bytes. No dynamic collection, recursion,
  pointer, host bigint, or unbounded loop survives extraction.
- A direct pure-let ladder was rejected during implementation because substitution expanded shared
  intermediate expressions to 171,030 bytes of SVM assembly and 81,393 bytes of Yul. The bounded
  local-frame form evaluates every stage once and emits 35,250 / 15,751 bytes instead.
- Existing independent consumers expose application-owned names: SVM `BatchSizer` classifies
  capacity/encoding orders; EVM `EvmPriceBand` classifies quote bands. They share value policy but
  not account state, ABI/storage, authorization, error vocabulary, or physical layout.

## Boundary

These are floor operations, not formatting utilities or floating-point logarithms. Rounded-up
variants, explicit rounding modes, count-leading-zeros/MSB aliases, square root, signed math, and
wide/full-precision UInt128/UInt256 math remain fail closed. The compiler does not silently change
checked arithmetic or invent target-specific instructions for these helpers.
