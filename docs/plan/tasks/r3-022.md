# R3-022 — Invocation-local fixed-width UInt64 POD records

## Goal

Provide a reusable bounded `Vec<Record>`-shaped SDK layer over the official-shaped SVM invocation
heap without exposing a raw pointer, allowing partial records, or adding another low-level
Runtime/Ops/IR/Component/emitter recipe.

## Delivered contract

- `Svm.Sdk.Transient.Record64.bounded limbs records` and `.boundedAlt` derive the payload product
  and existing Vector64 slot handle. Callers no longer repeat `(limbs × records)` or provide a
  numeric slot, so inconsistent geometry is unrepresentable through the constructors.
- The underlying Vector64 handle and its one-word `push` stay private. `append1` through `append4`
  check exact record arity and whole-record capacity before the first existing component push.
  Wider records remain explicitly unsupported rather than falling back to a partial write loop.
- `count` rejects any live prefix not divisible by the fixed stride. `getLimb`, `setLimb`,
  `truncateRecords`, `lastLimb`, `dropLast`, and `clear` preserve whole-record boundaries and reuse
  Vector64's `0x1202` bounds, `0x1203` state, and `0x1201` OOM vocabulary.
- The extractor generically preserves marked helpers that own effectful branch/sequencing
  structure, while simple one-effect storage facades keep historical recursive discovery. This is
  not a `Record64` name case: the target IR still contains only existing transient-vector calls.
- The allocation is invocation-local and non-reclaiming. No source-visible/native pointer,
  account-resident heap metadata, realloc, persistent object, new Runtime leaf, top-level Ops/IR,
  Component variant, or main-emitter case was added.

## Evidence

- `Examples.Svm.TransientLedger` independently consumes two-limb `(holder, amount)` records with
  reject-at-full policy. Digest `a91e5e115c1f83b`; assembly 573,988 bytes; linked ELF 164,824
  bytes; ELF SHA-256 `3a9133ca66a0b34bbdb0ddc70871f15f51a04ae3f1584655ba05b0b1c31736e7`.
- `Examples.Svm.TransientOrderTape` independently consumes three-limb
  `(price, quantity, sequence)` records with clear-and-reuse policy. Digest `e203afd44ef6eea9`;
  assembly 587,880 bytes; linked ELF 169,400 bytes; ELF SHA-256
  `c57cdba2f1f4fb653fae99ceef39314db620ea14a5814247a3222aa108d26d11`.
- Focused Lean proves derived/malformed geometry, two-slot inheritance, whole-record branch push
  counts, component-only lowering, and preserved storage/queue facade digests. Focused Mollusk
  passes 14/14 for aligned append/read/write/truncate/drop/clear, two-slot isolation, full/OOB/
  stale/unbegun/OOM behavior.
- Aggregate qualification passes 364 Lean jobs, all 59 registered SVM builds, locked Mollusk
  363/363, all 30 EVM builds and Anvil 30/30, artifact manifests, ownership and whitespace gates.

Two Vector64 slots and record widths 1–4 are the explicit resource ceiling. Wider or typed/wide
records, more slots, insert/remove-at/iteration, persistence, pointer storage, reclaim, and realloc
remain fail closed. Surfpool remains the sole deployment qualification environment; this SDK
composition slice adds no new deployment smoke and does not use Test Validator.
