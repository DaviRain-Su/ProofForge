# wsm-003 XRPL 本地链工程门：起节点、部署 Counter、四场景

## objective

对标 `runtime-tests/evm/anvil.sh`。`Examples.Counter` 走完：

1. 起本地链
2. 部署 `Counter.wasm`
3. 测 initialize / increment ok / increment overflow / get

宿主是 **Bedrock 本地节点**（`bedrock node start` → Docker，`ws://localhost:6006`），
不是 AlphaNet，不是主网，不是 wasmtime。部署走 `ContractCreate`，调用走
`ContractCall`。本仓不锁 rustc；`bedrock` 只当 Anvil/cast 的对应物，缺工具则
skip（exit 0），和 Foundry 不在时 Anvil 门一样。

前置：wsm-002 已经让 `pf build --target xrpl` 写出 `Counter.wasm`，import 表是
`host_lib.{home_le_field,set_data}`。本切片不改发射器。

## 本地链与 CLI（钉死来源）

[XRPL-Commons/bedrock](https://github.com/XRPL-Commons/bedrock)：Foundry-for-XRPL。

```text
runtime-tests/xrpl/counter.sh
  bedrock node start                          # Docker 镜像 lejamon/rippled_smart_contract_vault_x86
  把 build/xrpl/Counter.wasm 拷到
    fixture/contract/target/wasm32-unknown-unknown/release/Counter.wasm
  bedrock deploy --network local --skip-build --skip-abi --abi abi.json
  bedrock call <contract> initialize --params '{"initial_value":"0"}'
  bedrock call <contract> increment  --params '{"amount":"1"}'
  bedrock call <contract> get
```

`--skip-build` 是硬约束：部署的必须是 ProofForge 的 `.wasm`。bedrock 没有
`--wasm` 标志，所以脚本把产物拷到它从 `bedrock.toml` 推出来的路径。

## 诚实边界

- 工程门，不是「定理蕴含已部署」。`deployable` 对主网仍为 false。
- 不打 AlphaNet（`wss://alphanet.nerdnest.xyz`）、不打主网。CI 只跑 local。
- Docker / `bedrock` 缺失 → skip，不红。节点起不来或 `ContractCreate` 被拒
  → fail closed（工具在、链不认我们的 wasm，那是真问题）。
- 不把 `bedrock build`（Rust→wasm）接进本仓流水线。

## 四场景

| Lean | 链上 |
|---|---|
| `initialize(0)` | `ContractCreate` 触发 init，或随后一次 `ContractCall initialize`；状态 0 |
| `increment(1)` ok | `ContractCall increment` 返回 i32 0；`get` = 1 |
| `increment` overflow | 大加数 → 状态码 1，槽不写 |
| `get` | 只读，返回 i64 |

## verification

- 无 Docker / 无 `bedrock`：`runtime-tests/xrpl/counter.sh` 打 `skip:` 且 exit 0
- 有 Docker + `bedrock`：四场景绿（本机 daemon 未起时尚未实测；节点起不来或
  `ContractCreate` 拒 wasm 必须 fail closed，不能改成 skip）
- 部署的 wasm 是 `build/xrpl/Counter.wasm`，拷到 bedrock 推出来的路径，
  `--skip-build` 禁止它再编 Rust
- CI 不访问 AlphaNet / 主网
