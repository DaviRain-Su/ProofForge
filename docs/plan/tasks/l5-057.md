# L5-057 — Invocation-local bounded scalar frames

## Goal

Provide the reusable transient state needed by bounded traversals without adding another protocol
operation, target extension, or emitter branch. Ordinary Lean `let mut UInt64` bindings should
carry cursors, totals, stop/error flags, and fee accumulators across a statically bounded loop while
persistent contract state remains in account bytes.

## Delivered

- The extractor now recognizes the `MProd` shape Lean itself elaborates for two or more mutable
  `UInt64` bindings in a bounded `for` loop. It initializes one existing local per scalar, lowers
  the loop through the existing `forBody` operation, and publishes each yielded frame with existing
  `setLocal` operations. `MProd` is only an elaboration artifact: it is neither a source SDK type
  callers must construct nor a target/runtime representation.
- Each iteration first snapshots every next-frame value into disjoint temporary locals and only
  then updates frame locals. Swaps and mutually dependent assignments therefore retain Lean's
  simultaneous yielded-frame semantics instead of observing an earlier destination write.
- Effects remain before frame publication. A CPI inside the loop is emitted before any temporary
  snapshot or `setLocal`, so the next invocation-local frame becomes visible only after that
  iteration's effects complete.
- Generic static account-storage reads compose as ordinary frame values. The SVM projection keeps
  the field's fixed account, word, stride, capacity, access, and index-base geometry while the
  traversal carries only scalar results in locals; no descriptor, pointer, or account copy enters
  runtime state.
- Recognition is deliberately narrow and fail closed: at least two `UInt64` leaves, an exact
  bounded loop, a matching `MProd` continuation, and decodable scalar yields are required. Existing
  persistent State loops, single-accumulator loops, and early-return loops retain their established
  paths.
- No Ops, IR, CFG, Component, SVM Emit, or EVM Emit vocabulary changed. The implementation is an
  extraction normalization over the already shared local/`forBody` contract, so future queue/map
  traversals and protocol code reuse normal Lean syntax rather than adding more bottom-level
  instructions.

The reusable boundary is:

```text
bounded source loop with ordinary mutable UInt64 scalars
        │ Lean elaboration (`MProd`, erased during extraction)
        ▼
invocation-local frame: letLocal + snapshot locals + setLocal
        │ existing bounded forBody / CFG lowering
        ├── SVM backend + static AccountStorage values
        └── EVM backend + common arithmetic/control values
```

Persistent state still consists only of fixed account bytes, fixed strides, one-based indexes, and
the `0` sentinel. This slice adds no heap `Map`/`Vec`, persistent pointer, runtime geometry,
detached tree, or unbounded traversal.

## Verification

- `lake build Tests` completed all 229 jobs; the focused `Tests.ExtractSpec` build completed all
  139 jobs.
- Source guards cover stop-state propagation and a two-scalar swap. Exact extraction guards cover
  initialization, nested control flow, snapshot-before-publish ordering, CPI-before-publish
  ordering, continuation reads, absence of persistent stores, and a static account-storage query
  inside the frame.
- The common arithmetic frame reaches both existing SVM and EVM emitters. The account-storage
  frame reaches the existing SVM component projection and emitter with its static geometry intact.
