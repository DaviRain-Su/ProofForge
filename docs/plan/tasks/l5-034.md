# l5-034 Bounded account-storage field reads

## objective

把 runtime-indexed account word read 从独立 SVM value kind 和主 `loadVal` emitter 迁入
`Svm.AccountStorage.Query.readWord`，形成可由 map lookup、queue traversal 和业务 preflight
共同组合的 fixed-capacity field extractor。

## invariants

- `Field` 只携带编译期固定 account/base/offset/stride/capacity/index base；runtime 只提供
  scalar index，不能提供 offset、stride、capacity 或 pointer
- zero-based index 必须小于 capacity；one-based index 必须在 `1..capacity`，`0` 固定为
  null sentinel，并在形成 transient account-data pointer 前归一化为 slot offset
- 两种模式都先检查 index，再检查最终所需 data length；外部账户只通过 walked header
  取得 data pointer，不缓存或持久化 pointer
- read query 必须是 width-one read-only field，account/stride/base/final word 全部通过统一
  `Region/Field.wellFormed`；stride 即使在 capacity=1 时也必须落入 u64 byte-address bound
- query 自己拥有 one-operand arity、read effects、account inference 与 canonical spelling；
  zero-based `dwi` 保持旧 digest，one-based 使用独立 `dwi1` 防止语义碰撞
- source `accDataWordAt` 和 Runtime intrinsic 保持不变；顶层 `ValKind.accDataWordAt`、主
  `loadVal` case 和原 emitter 实体删除
- 不分配 heap/Map，不复制 node，不开放 runtime geometry、persistent pointer 或
  unbounded traversal

## verification

- guards 覆盖 zero/one-based geometry、arity、read-only effects、canonical distinction、
  zero stride 与 capacity=1 oversized stride rejection
- source digest 保持 `e9966de4a1795a47`；迁移前后 PhoenixV1Profile assembly 逐字节相同，
  仍为 4,652,144 B；ELF 1,489,088 B、IDL 7,613 B 均保持不变
- `lake build Tests` 196 jobs、50 个 SVM registry build、Mollusk 230/230、Anvil 12/12
  全绿；Surfpool 1.5.0 以 1,472 个 Loader write transactions 部署并核对 exact
  1,489,133-byte ProgramData

## next migration

在 storage backend 增加 bounded Key4/FIFO map-find query，返回 one-based node index 或 `0`；
上层随后可组合 `mapFind → readWordOneBased → checked preflight → writeWord/remove` 实现
ReduceOrder，而不再增加顶层 ValKind/Op/Emit 特判。

## non-goals

- 本切片不实现 map search、ReduceOrder、collateral update 或 event
- 不改变现有 zero-based indexed read 的 sBPF 指令序列或 Phoenix wire ABI
- 不把 account-resident field 复制到 transient heap container
