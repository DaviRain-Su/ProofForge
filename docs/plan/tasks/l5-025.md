# l5-025 general bounded Phoenix trader removal

## objective

为最小 128-seat Phoenix trader allocator 增加通用 fixed-capacity account effect，按
Sokoban 0.3.0 精确执行 predecessor transplant、red-black delete-fixup 与 free-list 回收。
持久树仍完全驻留在 Solana account data 中，不把 transient bump heap 当作 Map 或节点
ownership。

## invariants

- account、root/links/parent/key base、stride 与 capacity 均为编译期常量；运行时只有四个
  key limb 和有界 scalar index
- writable、current-program owner、data length、完整 RB tree、allocator live/free partition
  与目标 key lookup 全部在第一次 store 前完成；missing/malformed/readonly/wrong owner
  均 fail closed 且账户 bytes 不变
- 删除使用 Sokoban 的 predecessor（left subtree maximum）transplant，覆盖 leaf、单 child、
  双 child 与 bounded delete-fixup；root/parent/color/link 只保存 one-based index 和 `0`
  sentinel
- 删除后清零 slot 的四个 allocator registers，并把 address 压入账户内 free-list；官方
  Sokoban 保留 free slot 的 key/TraderState payload，后续通用 insertion 重新初始化完整
  144-byte slot
- rotation/transplant helper 只持有当前 invocation 的 account-derived pointer 与 bounded
  scalar；不持久化 raw pointer，不使用 `Map`/`HashMap`、detached node、heap tree copy 或
  无界 allocation
- IDL 从 remove effect 推导 `acc1` writable，抽取、target projection、CFG canonicalization
  与 static well-formedness 均 fail closed 识别该 effect
