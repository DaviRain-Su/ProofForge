# wsm-005 XRPL-RT：环境 + AccountId（caller / self / ledger）

## objective

对标 [e-rt-001](e-rt-001.md)，但只开 XRPL 自己的 host。见
[xrpl-runtime.md](../analysis/xrpl-runtime.md)。

合约能 `open ProofForge.Wasm.Xrpl.Runtime` 读：

- `AccountId` 三叶（20 字节，w2 仅低 4 字节；**不是** `Evm.Runtime.Addr20`）
- `xrplCaller20` ← `host_lib.get_tx_field(sfAccount=524289)`
- `xrplSelf20` ← `get_current_ledger_obj_field(sfContractAccount=524315)`
- `xrplLedgerSqn` ← `get_ledger_sqn`（i32 零扩展到 UInt64）
- `xrplParentTime` ← `get_parent_ledger_time`

抽出器认全名 `ProofForge.Wasm.Xrpl.Runtime.*`。`Extract.IR.ValKind` 增加
`.xrpl`；SVM / EVM 投影拒绝它。WAT 多这四条 import，存储仍走现有
`ContractJson` 槽。

`Examples.XrplCtx` + `runtime-tests/xrpl/ctx.sh`：mutate 把 caller 低 8 字节
和 ledger sqn 写入槽；本地节点读 `account_objects` 对上 genesis 账户 /
当前序号。`#pf_xrpl_reject Examples.Clock` / `Examples.EvmCtx` 仍绿；
`#pf_svm_reject` / `#pf_evm_reject Examples.XrplCtx` 新加。

digest 域仍 `xrpl-bedrock|`。主网 `deployable=false`。

## 不做什么

- 不把 `clockSlot` / `evmCaller` / NEAR `predecessor` 映射过来
- 不做 hash / event / Map / SDK / Ownable
- 不改 `ProofForge/Wasm/Near/**`（NEAR Runtime 另开；他们已占用 wsm-004）
- 不声称 view `i64` 进 `meta.ReturnValue`

## path

`ProofForge/Extract/{IR,Ops,Decode}.lean`（共享锁：`.xrpl` 构造子），
`ProofForge/Svm/IR.lean`、`ProofForge/Evm/IR.lean`（拒 `.xrpl`），
`ProofForge/Wasm/Family.lean`，
`ProofForge/Wasm/Xrpl/{Runtime,Ops,IR,Host,Emit}.lean`，
`ProofForge/Wasm/Emit.lean`（环境叶子 → host 调用），
`Examples/XrplCtx.lean`，`Tests/XrplSpec.lean`，
`runtime-tests/xrpl/ctx.sh`，`docs/modules/{runtime,xrpl,wasm}.md`

## verification

- `#pf_xrpl_build Examples.XrplCtx` 写出带 `get_tx_field` / `get_ledger_sqn`
  的 WAT；没有 `clockSlot` / `evmCaller`
- SVM/EVM 抽出 `Examples.XrplCtx` fail closed（`rejects xrpl`）
- XRPL 抽出 `Examples.Clock` / `Examples.EvmCtx` 仍 fail closed
- 本地节点：`initialize` 后 `stamp`，`ContractJson` 的 caller 低 8 字节等于
  genesis `rHb9…` 的对应字，sqn 随账本递增
- 缺 docker/bedrock → `ctx.sh` skip（exit 0），与 `counter.sh` 同规矩
