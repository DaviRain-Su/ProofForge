# L5-054 — Compose reusable bounded storage with one-maker Limit matching

## Goal

Stop extending Phoenix through positional calls and protocol-specific emitter changes. Strengthen
the reusable fixed-account SDK boundary, represent Borsh enum dispatch as entry-schema data, and
use those pieces to implement the first exact `OrderPacket::Limit` matching slice in `Examples`.

## Delivered

- Added source constructors for scalar fields, one-based fixed-record fields, a two-word ordered
  map, and its one-based allocator descriptor. Generic source operations now expose ordered find,
  strict cursor, key reads, insert/remove, four-word key projections, and allocator header reads.
  The legacy FIFO names remain compatibility aliases over the same representation.
- Defined Phoenix's `Book` and smallest official layout above those generic handles. All raw
  Phoenix offsets, capacities, balance fields, fee fields, and price-time policy remain centralized
  in `Examples/PhoenixV1Layout.lean`; this slice adds no Phoenix name, layout constant, matching
  opcode, or matching branch to generic Ops/IR/main-emitter surfaces.
- Generalized pure static-facade reduction structurally rather than by namespace whitelist. A
  scalar account read used before a later storage effect is materialized as a local, so recorder or
  mutation composition cannot accidentally re-read changed account bytes.
- Added exact Borsh enum variant selection to `EntryAdapter`. Distinct variants may share one u8
  instruction tag; the adapter validates exact length, tag, and byte-1 discriminant, consumes the
  variant, and passes only that variant's payload to its handler. Main SVM emission only forwards
  generic route metadata. `RawEntry` proves two different payload shapes under tag 11 and rejects
  unknown variants, truncation, trailing bytes, and cross-variant shapes.
- Reclassified Phoenix's existing 40-byte PostOnly packet as tag-3 variant 0 and added exact
  49-byte Limit variant 1. The first Limit slice requires `Abort`, `match_limit=Some(1)`, deposited
  funds, hard funds failure, no TIF, one crossing non-self maker, and an exact full-maker fill. It
  handles both bid-taker/ask-maker and ask-taker/bid-maker balance transitions, credits unclaimed
  quote fees, removes the resting order, increments only market sequence, emits exact Fill and
  FillSummary records, and at this stage returned a four-byte empty Borsh order-id vector. L5-055
  corrects that last protocol divergence: official Phoenix leaves return data entirely unset when
  no remainder is posted.
- Unsupported partial fills, taker remainder/posting, multiple makers, eviction, alternate
  self-trade behavior, other match limits, TIF, and soft funds failure still fail closed before any
  account write.

The ownership boundary is now:

```text
Phoenix layout + OrderPacket + crossing/fee/audit policy (Examples)
        │ named static handles + scalar values
        ▼
AccountStorage fields / ordered map / allocator / cursor (ProofForge/Svm)
        │ existing generic Component bridge
        ▼
fixed account bytes, one-based indexes, 0 sentinel
```

No persistent heap `Map`/`Vec`, copied or detached tree, runtime geometry, persistent pointer, or
unbounded traversal is introduced.

partial-maker fill while preserving the generic ordered-map/allocator API; then add bounded taker
remainder/posting and multi-maker traversal as separate policy slices. Each unsupported packet
