# R0-002 — Define mainstream Runtime / SDK parity

## Goal

Replace the vague target of “more SDK coverage” with one auditable baseline: official Solana
on-chain SDK/SPL capabilities for SVM, and Solidity plus OpenZeppelin capabilities for EVM.

## Delivered contract

- Parity is split into shared bounded language, target Runtime host effects, reusable target SDK
  policy, and application-owned protocol rules.
- Vector/Map/allocation are classified by boundary, invocation-local, SVM account-persistent, and
  EVM storage-persistent lifetimes. No row can claim support merely because one other lifetime has
  a similarly named host type.
- The matrix identifies F0 shared substrate, F1 Runtime, F2 reusable policy, and F3 lifecycle work
  without replacing the existing R2/R3/R4/R5 ownership/task sequence.
- Rust `std` and Solidity syntax are explicitly outside the parity claim. Deterministic bounded
  values, accurate target effects, and reusable audited policy are inside it.

## Evidence

The baseline is grounded in the current source capability matrix and the official Solana account,
CPI, sysvar, program-memory and SPL interface repositories, plus Solidity type/ABI/runtime docs and
OpenZeppelin collection/access/token modules. This slice changes documentation only; it does not
change target artifacts or claim that any listed gap is already available.
