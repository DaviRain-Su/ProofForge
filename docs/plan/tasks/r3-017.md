# R3-017 — Add checked transient Vector64 pop

## Goal

Extend the invocation-local bounded `Vector64` toward Rust `Vec<u64>` parity without pretending
that Solana's program heap supports reclaiming allocation, persistent pointers, or unbounded growth.

## Delivered contract

- `Svm.Sdk.Transient.Vector64.pop : UInt64` removes and returns the former final live element.
- Pop first applies the shared active-marker and exact compile-time-capacity gate. Empty vectors
  terminate with the existing bounds code `0x1202` before length or payload is touched.
- A successful pop decrements logical length and reads the old tail in place. It does not clear the
  stale payload bytes, allocate, free, reallocate, expose the native address, or reclaim bump space.
- Extraction lowers the source leaf only through `Component.transientVec`; no top-level Ops/IR or
  main-emitter constructor was added.

## Evidence

- `Tests.SvmTransientVectorSpec` pins zero arity, canonical identity, component ownership,
  begin→push→push→pop→finish ordering, direct empty-pop ordering, and the explicit assembly gate.
- `runtime-tests/solana/tests/memory_ops.rs` verifies exact LIFO return and `Custom(0x1202)` for
  empty pop under Mollusk; the complete MemoryOps binary passed 12/12 tests.
- MemoryOps target IR digest: `e37f469f33e44884`.
- Emitted sBPF assembly: 123,208 bytes. Linked ELF: 41,440 bytes, SHA-256
  `7d1a9c05bdc77a02d0dbf6785c952cf31b45ac344780304812dbfa6826ea8369`.

Multiple simultaneous vectors, generic POD elements, insert/remove, and iteration remain separate
bounded-resource contracts rather than implicit consequences of this operation.
