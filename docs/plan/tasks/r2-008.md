# R2-008 — Complete unsigned Clock and EpochSchedule views

## Goal

Expose the remaining unsigned and Boolean fields of Solana's official native Clock and
EpochSchedule host-call layouts through the stable Sysvar Component boundary.

## Delivered contract

- `Svm.Sdk.Sysvar.Clock.leaderScheduleEpoch` reads the native `Clock` u64 at offset 24.
- `Svm.Sdk.Sysvar.EpochSchedule` adds:
  - `leaderScheduleSlotOffset : UInt64` at offset 8;
  - `warmup : Bool` from the canonical byte at offset 16;
  - `firstNormalEpoch : UInt64` at offset 24;
  - `firstNormalSlot : UInt64` at offset 32.
- The EpochSchedule host call writes native `#[repr(C)] EpochSchedule`, whose two trailing u64
  fields follow seven bytes of C-layout padding. This is a 40-byte host-call layout; it is not the
  separate 33-byte packed/POD layout used by serialized sysvar data and sliced `sol_get_sysvar`.
- All fields reuse `Svm.Sysvar.Query → Component.sysvar → Svm.Sysvar.Emit`. No top-level Ops/IR/
  main-emitter recipe, account effect, allocation, pointer, storage, or application policy is added.
- `warmup` is loaded as one byte and canonicalized to source `Bool`. The signed
  `Clock.epoch_start_timestamp` remains fail closed; existing `unixTimestamp` continues to document
  its current UInt64 bit-pattern boundary until signed source integers exist.
