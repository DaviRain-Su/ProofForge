# L5-050 — Move Phoenix contract sources into Examples

## Goal

Remove the repository-only `Projects` ownership split without deleting either Phoenix model. Keep
Phoenix as an example and compatibility workload above the protocol-neutral ProofForge libraries,
while preserving every existing entry, test, registry name, digest, and generated SVM artifact.

## Delivered

- Moved the complete bounded host-state model from `Projects/Phoenix.lean` to
  `Examples/Phoenix.lean` and changed its namespace to `Examples.Phoenix`.
- Moved the complete official-account profile and raw instruction handlers from
  `Projects/PhoenixV1Profile.lean` to `Examples/PhoenixV1Profile.lean`, next to the reusable
  `PhoenixV1Layout` instance it consumes. This is a source ownership move, not deletion of the
  allocator/tree/order/cancel/reduce/recorder behavior.
- Removed the `Projects` Lake library, root import, and CLI program-name exception. Every registered
  SVM program now follows the same `Examples.<Name>` module lookup path.
- Updated source extraction guards, the legacy comparison fixture, tests, and documentation to the
  new namespaces. No `Projects.Phoenix*` compatibility alias remains to preserve the old split.
- Kept Phoenix-specific account geometry and protocol semantics in `Examples`; no Phoenix name,
  offset, operation, or emitter case moved into `ProofForge/Svm` or the generic extractor.

## Verification

- `lake build Examples.Phoenix Examples.PhoenixV1Profile` completed successfully.
- `lake build Tests.CliSpec Tests.PhoenixSpec Tests.PhoenixV1ProfileSpec Tests.BuildSpec` completed
  139 jobs. The canonical digests remain `Phoenix = ec8383cf470795f4` and
  `PhoenixV1Profile = 9ecc2b7df3ecde85`.
- `lake build Tests` completed all 213 jobs, and the CLI rebuilt all 51 registered SVM programs
  through the uniform `Examples.<Name>` lookup.
- `pf build --target svm Phoenix PhoenixV1Profile` uses the uniform `Examples` lookup and produces
  the same artifact sizes: Phoenix 10,640,734-byte assembly / 3,428,808-byte ELF /
  19,882-byte IDL; PhoenixV1Profile 12,638,154-byte assembly / 3,960,600-byte ELF /
  9,537-byte IDL. The profile ELF remains SHA-256
  `af27cf67566458007c5131aff69cad70101de56f8074c9e5b38973e7bbdce660`, byte-identical to the
  artifact already deployed through Surfpool 1.5.0 in L5-049.
- Live Lean/Lake source contains no remaining `Projects.Phoenix*`, `import Projects`, or
  `lean_lib Projects` reference, and the `Projects` directory contains no source file.

## Next

Keep the ownership boundary fixed. Migrate the remaining Phoenix profile paths—starting with
reduce, then cancel and recorder configuration—from positional account words to the named static
layout/source facade. Only after those source paths share reusable handles should the remaining
`OrderPacket` variants and component-owned matching semantics be expanded.
