# l5-016 complete Phoenix ask tree validation

## objective

把 `l5-015` 的 fixed-memory whole-tree validator 接到四档 Phoenix-v1 ask allocator，覆盖
ask side tag 和 ascending FIFO ordering，不增加 heap、Map 或节点副本。

## invariants

- 四档 ask links/parent/price/sequence base 与 capacity 均编译期固定
- ask sequence 最高位必须为 0；in-order key 严格按 `(price, stored sequence)` 升序
- tree/allocator 仍执行完整 RB invariants、reachable live count 和 exact live/free partition
- 与 bid 共用固定 4096-bit stack bitmap，不开放 runtime offset/capacity

## path

`Examples/Svm/PhoenixV1Profile.lean`, `Tests/PhoenixV1ProfileSpec.lean`,
`runtime-tests/solana/tests/phoenix_v1_profile.rs`

## verification

- IR/assembly 门覆盖 512/1024/2048/4096 四档 ask base 与 `bid=false` lowering
- Mollusk 覆盖 12 个官方 profile、valid ascending tree、descending corruption、bid-side
  sequence corruption；profile suite 9/9
- 4096-capacity ask allocator 的 4095-node perfect black tree 返回 1，消耗
  852,060 / 1,400,000 CU
- `lake build Tests` 194 jobs、50 个 SVM build、Mollusk 207/207、Anvil 12/12 全绿
- digest `1356885e6582aab2`；assembly 3,242,689 B；ELF 1,050,952 B；IDL 2,929 B
- Surfpool 1.5.0 用 1,039 个 Loader write + deploy + authority transactions 落入 exact
  1,050,997-byte ProgramData，并核对完整 ELF；不用 `solana-test-validator`

## non-goals

- trader tree 的 32-byte key ordering/partition 留给后续切片
- 不写节点，不开放 runtime remaining accounts 或公网部署声明
