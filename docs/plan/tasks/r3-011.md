# R3-011 — Canonical SVM program ids and SPL Token base-state views

## Goal

Move full-key program authentication and the stable SPL Token packed layouts out of Phoenix-style
application code into reusable, allocation-free SVM SDK policy. This slice must compose existing
checked account metadata/data-word leaves; program ids, token offsets, and enum/tag validation must
not become new Runtime operations or emitter recipes.

## Delivered contract

- `Svm.Sdk.Pubkey` is a compiler-erased four-word representation of one 32-byte Solana key. It
  compares complete account keys/owners in place and never decodes base58 on chain.
- `Svm.Sdk.Program` publishes canonical System, classic Token, Token-2022, Associated Token, Memo
  v4, and Memo v3 identities. `Id.matches` requires the complete key plus `executable = 1`;
  `Id.owns` additionally authenticates an account's complete owner field.
- `Token.AccountState` models the exact 165-byte classic-compatible base account. It validates the
  selected Token program, owner, data length, and `AccountState` byte; exposes initialized/usable/
  frozen predicates; and reads amount plus complete mint/authority relationships.
- `Token.MintState` models the exact 82-byte base mint. It validates both `COption<Pubkey>` tags and
  the canonical initialized byte, and reconstructs the unaligned supply and decimals fields from
  checked fixed words.
- Both state views accept classic Token or Token-2022 as an explicit compile-time flavor. An
  extension-bearing Token-2022 account deliberately does not pass an exact base view; the existing
  bounded TLV policy remains the owner of that envelope and all real extension semantics remain
  fail closed.

`Examples.TokenStateView` is an independent consumer. PhoenixV1Profile now consumes the same
classic Token program-id policy instead of keeping four local program-id limbs; its canonical IR
digest remains unchanged.

## Resource boundary

All descriptors contain fixed UInt64 words, static physical account handles, and one static flavor.
Extraction erases them to existing `isExecutable`, key-word, owner-word, data-length, and data-word
queries. There is no `Array`, `Map`, base58 parser, account copy, transient allocation, persistent
pointer, new Ops/IR/Component/Emit case, or dynamic account geometry.

## Evidence

- Focused Lean gates pin every canonical key word, descriptor account bounds, exact offsets, full
  32-byte comparisons, and canonical digest `79e777b300b87504`.
- `TokenStateView` assembles to a 33,408-byte Loader-v3 ELF.
- Mollusk executes initialized and frozen states, unaligned amount/supply/decimals, full mint and
  authority relationships, and fail-closed wrong program, wrong owner, unknown state, and invalid
  mint bool cases (4/4 tests).
- PhoenixV1Profile remains digest `af159cb894745102` after replacing its local Token program-id
  constants with the SDK policy.
