# R1-013 — Bounded Map / Set semantic contract

## Goal

Define the reusable key/value abstraction that was missing between ordinary Lean source and the
target-owned SVM/EVM storage implementations. The shared contract must be finite and deterministic,
and must not introduce a host hash table, persistent pointer, or shared physical storage layout.

## Delivered

- `Core.Collections.BoundedMap κ υ capacity` stores one compile-time fixed frame of key/value
  entries plus an explicit `UInt32` active length through the existing shared `BoundedVec`.
- The API provides bounded lookup/contains/get, typed reject-or-replace insertion, unordered
  swap-remove, clear, size/full/empty, and canonical no-duplicate validation.
- `BoundedSet α capacity` reuses the same contract with a unit payload instead of creating a second
  collection representation.
- Every scan is bounded by the type-level capacity. Full, duplicate-under-reject, missing, and
  malformed-frame cases are explicit `Option`/Bool outcomes.

## Ownership and allocation

This is a logical semantic model, not a target persistence promise. It contains no Lean/Std `Map`,
`HashMap`, `Array`, allocator, raw address, or runtime-selected capacity. SVM remains free to bind
the contract to account-resident ordered RBMap + one-based allocator; EVM remains free to bind it to
typed hashed storage plus bounded tracked keys. Iteration order is deliberately not observable.

The current slice does not mark map operations as `pf_inline` and does not claim target lowering.
Publishing a physical binding requires a separate adapter with resource bounds and independent SVM
and EVM validation. This prevents a host model from silently becoming persisted VM representation.

## Verification

`Tests.CoreCollectionsSpec.MapSemantics` covers missing/present lookup, duplicate rejection,
replacement, full capacity, swap removal, clear, Set reuse, malformed lengths, and duplicate-key
well-formedness rejection. `lake build Tests.CoreCollectionsSpec`, ownership, no-sorry, and
whitespace gates pass.
