# L5-044 — Compose official Phoenix-v1 CancelAll through bounded components

## Goal

Implement official tags 6/7 without adding another Phoenix-specific top-level operation, IR node,
CFG case, or main-emitter branch. Reuse fixed account bytes, the storage-owned FIFO cursor and RB
mutation routines, and the bounded recorder while keeping every persistent Queue/Map/Allocator
pointer-free and statically bounded.

## Delivered

- Added target-owned `FifoCancel` query/call vocabulary behind the existing `Svm.Component`
  bridge. `begin` opens invocation-local scalar counters, `cancelSide` owns one statically described
  FIFO map and its trader collateral fields, and `finish` closes the handle. Generic extraction,
  Ops, IR, CFG, and the main emitter continue to traverse only one `.component` case.
- Composed each side from the storage-owned strict-successor cursor, one-based owner/size reads,
  checked locked-to-free balance movement, aggregate released-lot counters, the existing in-place
  RB removal backend, and recorder append. After every mutation the next order is found again from
  the account root using only the retained scalar `(price, sequence)` key. No node pointer, copied
  tree, heap `Vec/Map`, runtime geometry, or detached allocation is introduced.
- Added an internal validated-remove hook to `AccountStorage.Emit.MutationBackend`. Ordinary source
  removal still executes its complete tree/free-list preflight; only the component emitter can reuse
  a dominating whole-map validator. The hook is not represented in source Ops or IR.
- Reserved component deep scratch at offsets 2056..2256, above the CPI bank at 1024..2048. Account
  headers and source scalar locals remain below 1024; the full validators finish before the side
  passes. Only counters, keys, balances, and indexes cross an internal call boundary.
- Added exact one-byte raw tag 7 `CancelAllOrdersWithFreeFunds` with the official four-account
  context. It validates the complete trader/bid/ask maps before sequence, mutation, or audit; walks
  bids before asks and FIFO within each side; filters by trader owner; and never enters Token or
  market-status validation.
- Added exact one-byte raw tag 6 `CancelAllOrders` with the official nine-account classic Token
  context shared with tag 4. It claims only quote/base lots released by this invocation, preserving
  pre-existing free balances, and executes quote claim/withdraw before base claim/withdraw.
- Both tags treat a missing trader or empty books as a successful no-op after incrementing the
  market sequence and emitting the 93-byte header-only batch. Every cancellation emits a 35-byte
  Reduce record with remaining size zero. Event indexes are invocation-global across bid/ask passes
  and automatic 32-record recorder flushes.
- Reused the official SDK-compatible fixed 32 KiB downward bump allocator only for transient audit
  payloads. Persistent market data stays in fixed account bytes with one-based indexes and `0`
  sentinels; no heap address escapes the invocation.
