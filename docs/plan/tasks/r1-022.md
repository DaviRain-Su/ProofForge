# R1-022 — EVM Tagged Tuple v1 return binding

## Goal

Bind the shared fixed tagged-result frame to canonical fixed-tuple ABI returndata without reusing
calldata plans, decoded locals, or input guard state, and without adding tagged recipes to Runtime,
Ops, IR, Component, or the main CFG emitter.

## Delivered

- `Evm.Codec.OutputPlan` is the single output-policy sum. Existing bounded dynamic plans and the
  new independent `TaggedTupleOutputPlan` cannot coexist as ambiguous optional fields.
- The tagged output interpreter materializes the fixed `tag,payload...` source frame, checks tag
  and scalar ranges, reuses one bounded inactive-lane policy interpreter, and publishes canonical
  `(bool,T)` or `(uint8,p0,...)` words.
- Input and output retain separate plan types and execution state. They share only pure fixed-frame
  canonicality rendering; no calldata offset, projection, local, or cursor reaches returndata.
- `Examples.Evm.EvmCtx` directly echoes ordinary Lean `Option UInt64` and a three-variant payload enum.
  Structured ABI JSON exposes the corresponding tuple components.

## Boundaries

The first output contract matches shared Extract projection: a one-limb Option scalar or enum
constructors containing only UInt64 fields. Constructed tagged results, richer payloads, nested
tagged/dynamic values, and frames above 64 words remain fail closed. No heap value or persistent
pointer is introduced.

## Verification

- Focused Lean guards cover output-plan identity, source-frame types/counts, adapter routing,
  output-only tag/inactive-lane checks, and structured ABI JSON.
- EvmCtx digest is `ded60bb1bab650c8`; solc 0.8.34 emits 1,249 bytes of deployment bytecode.
- Anvil round-trips None/Some and all three enum variants as exact canonical returndata words.
- Existing bounded dynamic output tests remain green through the same `OutputPlan` sum.

## Next

The next codec slice should qualify constructed tagged values or nested aggregate output only after
Extract can prove constructor identity, inactive-lane canonicality, and a bounded recursive ABI
memory layout. Persistent collection bindings remain separate target SDK work.
