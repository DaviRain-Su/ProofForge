# CI-002 — Cut PR feedback: Phoenix lane split + NEAR de-dupe + local runner

## Problem

PR wall-clock stayed ~50–60m because:
1. NEAR still re-ran `lake build` + `lake build Tests` (ci-001 only fixed SVM/EVM).
2. Phoenix Lean specs + Mollusk (~99% of Mollusk time) + Surfpool deploys lived on the default SVM/Lean paths.
3. Developers waited on GitHub Actions instead of running the same gates locally.
4. A parallel Phoenix-lane PR (#15) also broke the aggregate `test` job by omitting `needs: phoenix`.

## Delivered contract

- Adopt #15's structural split: `PhoenixExamples` / `PhoenixTests` Lake targets; `runtime-tests/phoenix` crate; dedicated `phoenix` CI lane; SVM keeps only RawEntry Surfpool + non-Phoenix Mollusk (parallel).
- Lean default `Tests` no longer imports Phoenix specs.
- NEAR lane builds `Examples` only (Lean owns Tests).
- Aggregate `test` job `needs: [..., phoenix]` and treats skipped Phoenix as success.
- Phoenix-v1 Surfpool timeout raised to 45m (10MB ELF Loader-v3 writeback).
- `scripts/ci_local.sh` mirrors lane selection for pre-push local runs.
- `ci-phoenix.yml` retained as nightly/manual safety net.

## Local usage

```bash
./.agents/setup
scripts/ci_local.sh --fast
scripts/ci_local.sh                 # auto lanes from diff vs origin/main
scripts/ci_local.sh --lane svm
scripts/ci_local.sh --phoenix
```

## Relationship to #15

#15 owned the Phoenix lane split; this branch merges it and fixes the merge-gate + NEAR de-dupe + local runner + V1 timeout. Prefer landing this combined PR and closing #15 as superseded (or merge #15 first then this as follow-up — do not land both independently).
