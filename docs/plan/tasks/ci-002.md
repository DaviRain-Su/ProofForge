# CI-002 — Cut PR feedback: NEAR de-dupe, Phoenix heavy gate, local CI

## Problem

PR wall-clock stayed ~50–60m because:
1. NEAR still re-ran `lake build` + `lake build Tests` (ci-001 only fixed SVM/EVM).
2. Default SVM PRs always deployed Phoenix Surfpool (+ compiled Mollusk phoenix suites).
3. Developers waited on GitHub Actions instead of running the same gates locally.

## Delivered contract

- NEAR lane builds `Examples` only (Lean lane owns Tests), then `pf build --target near` + sandboxes.
- `surfpool_heavy` path filter gates Phoenix Mollusk (`phoenix-gates` cargo feature) and both Phoenix Surfpool deploys; RawEntry smoke stays on every SVM PR.
- `.github/workflows/ci-phoenix.yml` runs the heavy Phoenix gates on schedule / dispatch / Phoenix paths.
- `scripts/ci_local.sh` mirrors lane selection and gates for pre-push local runs (`--fast`, `--lane`, `--all`, `--phoenix`).

## Local usage

```bash
./.agents/setup
scripts/ci_local.sh --fast          # ownership / SDK / manifest / no-sorry
scripts/ci_local.sh                 # auto lanes from diff vs origin/main
scripts/ci_local.sh --lane svm      # light SVM (no Phoenix unless paths demand it)
scripts/ci_local.sh --surfpool-heavy --lane svm
scripts/ci_local.sh --phoenix
```
