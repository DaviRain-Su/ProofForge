# l5-010 Phoenix-v1 Sokoban allocator header envelope

## objective

在读取任何节点前，验证三棵账户内 Sokoban `RedBlackTree` 的固定 header：`root`、padding、
allocator `size`、`bump_index` 与 `free_list_head`。全部数据直接来自候选 market account；
不创建 Rust/Lean 动态容器。

## invariants

- index 是 1-based，0 仅为空树 `root` sentinel
- `bump_index` 是下一个未用 index，范围 `1..=capacity+1`，不能作为节点解引用
- live `size < bump_index` 且 `size ≤ capacity`
- `free_list_head` 范围为 `1..=bump_index`；等于 bump 表示 bump/end boundary
- 非空 root 必须在 `1..bump_index-1` 且不超过 capacity；空 allocator 的 root 必须为 0
- `root` 后的三个 u32 padding 必须为 0

## path

`Projects/PhoenixV1Profile.lean`, `Tests/PhoenixV1ProfileSpec.lean`,
`runtime-tests/solana/tests/phoenix_v1_profile.rs`

## verification

- 四档 profile 的 bids/asks/traders 固定 header words 都进入 IR gate
- 12 个官方 profile 的有效 header 在 Mollusk 返回 1
- root 越界、padding 非零、零 cursor、free head 越过 bump、trader bump 越过 capacity 均返回 0
- checkpoint digest `3322a44e27b16f42`，ELF 156,200 B

## non-goals

- 不沿 root/left/right/free-list 解引用节点，不判断某个 index 是否位于 free list
- 不开放 runtime-selected account-data offset，不摊平节点数组
- 不验证完整红黑树颜色、black height、parent reciprocity 或 key ordering
- 不写 market account，不宣称完整 Phoenix-v1 兼容
