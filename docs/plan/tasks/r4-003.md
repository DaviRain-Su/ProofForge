# R4-003 — EVM-RT-2c typed payable and receive policy

## Goal

Move repeated EVM entry-value guards and calldata routing geometry into one target-owned typed
plan/interpreter without exposing raw CALLVALUE, arbitrary payable routing, or outgoing calls to
source contracts.

## Delivered contract

- `Evm.Payable.ValueGate` names nonpayable rejection, receive accept-any binding, and exact
  deposit equality.
- `CalldataRoute` names empty-calldata receive and selector dispatch. `EntryPlan` validates the
  allowed gate/route pairs; impossible receive/nonpayable combinations fail closed.
- `Evm.Payable.Emit` is the sole renderer for constructor/runtime/selector CALLVALUE rejection,
  exact deposit checks, receive value binding, empty-calldata routing, and selector dispatch.
- Main `Evm.Emit` consumes the plans at the constructor and runtime boundaries. `NativeFx.Emit`
  consumes the same value gates for closed deposit and receive effects.

Method payable classification, source-facing Ether APIs, selectors, IR, and ABI labels remain in
their existing owners. Native send CALL remains in the closed `NativeFx`/`CallResult` path because
it does not share entry-value responsibility.

## Resource and failure boundary

- Gate/route combinations, missing or empty exact amounts, and route/interpreter mismatches fail
  closed before Yul is returned.
- Plans contain only finite enums and indentation/materialized word strings. They create no
  contract runtime allocator, storage write, returndata buffer, arbitrary callee, delegatecall,
  create, or source opcode escape hatch.
- Refactoring preserves emitted indentation and statement order byte-for-byte.

## Evidence

- Focused `Tests.EvmPayableSpec` passes 117 jobs; aggregate `Tests` passes 275 jobs.
- All 20 registered contracts compile with solc 0.8.34 and Anvil passes 20/20.
- All 20 contracts retain byte-identical Yul/bytecode/ABI artifacts (60 files); four retained mock
  bytecode files are identical as well.
- Ownership and whitespace gates pass.
