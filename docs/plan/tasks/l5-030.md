# l5-030 bounded account-storage query bridge

## objective

把返回 `UInt64` 的 `accDataParentPathValid` 从顶层 SVM value kind 与主 emitter 的 bespoke
实现迁入 `Svm.AccountStorage.Query`，验证新的 account-storage boundary 同时支持有序写入
和 bounded read/traversal routine，而不是只把一个 store helper 换目录。

## invariants

- `ParentPath` 由两个 fixed-stride `Field` 组成；account/stride/capacity/access/index base
  必须一致，links 与 parent/color 的起始 word 均为编译期常量
- query 固定 one-based slot index，`0` 继续只作 null sentinel；最大深度在编译期限制为
  `1..64`
- query operands 仍是普通 Core scalar values；static descriptor 自己拥有 arity、geometry
  validation、canonical digest、minimum account count 与 read-only `EffectSummary`
- `ValKind` 与主 `loadVal` 只保留一个 generic `.accountStorage query` case；后续新增 bounded
  storage query 不再改 generic canonicalization、walk/min-account 或 emitter dispatch
- `AccountStorage.Emit` 原样拥有 data-length gate、index/bump envelope、parent→child
  reciprocity、color、cycle bound 与 scalar result store；不分配 visited Map 或 copied nodes
- source `accDataParentPathValid` 名称、canonical digest、assembly、ELF、IDL 与 runtime
  semantics 保持兼容

## verification

- guards 覆盖 query arity、one-based geometry、read-only effects、canonical spelling、malformed
  operand count、depth bound 与四档 Phoenix profile projection
- `PhoenixV1Profile` digest 保持 `e9966de4a1795a47`；assembly 4,652,144 B、ELF
  1,489,088 B、IDL 7,613 B 均不变
- `lake build Tests`、50 个 SVM build、Mollusk 230/230、Anvil 12/12 与 Surfpool 1.5.0
  transaction deployment 全量回归

## next migration

把 complete RB validators 的共同 account-data/base/index envelope 移入 Query；随后把
search/allocator/rotation/transplant/fixup 归并为 reusable mutation routines。业务动作只组合
这些例程并保留 Phoenix 语义，不再在主 emitter 添加完整树算法。

## non-goals

- 本切片不迁移 complete RB validator 或 mutation primitives
- 不开放 runtime geometry、unbounded walk、heap `Map`、persistent pointer 或 detached node
- 不改变 Phoenix wire ABI、matching/placement、remaining accounts 或 Token-2022 semantics
