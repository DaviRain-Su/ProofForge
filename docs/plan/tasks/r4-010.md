# R4-010 — Add bounded address code observations

## Goal

Complete the safe Solidity-shaped address observation subset with code size and code hash, while
keeping raw runtime code bytes and low-level memory APIs outside the default SDK.

## Delivered contract

- `Evm.Sdk.Address.codeSize (address : Address) : UInt64` binds EXTCODESIZE. EIP-170 code size is
  safely inside the scalar result type.
- `Evm.Sdk.Address.codeHash (address : Address) : Bytes32` binds EXTCODEHASH as source-order fixed
  bytes, not a numeric UInt256. Nonexistent accounts preserve the VM's all-zero hash result.
- Both queries take all three little-endian Address limbs through `Component.environment`. The
  target interpreter reconstructs the complete EVM address with the existing fixed 32-byte packing
  helper; it never truncates to an address low word.
- The four code-hash limbs share one opcode observation and are converted through the fixed-bytes
  projection contract before ABI return packing.
- No raw code-copy API, dynamic allocation, storage write, external call, top-level Ops/IR value,
  or main-emitter recipe was added.

## Evidence

- `Tests.EvmEnvironmentSpec` pins three-operand arity, limb bounds, production Component ownership,
  and exactly one EXTCODESIZE/EXTCODEHASH occurrence in emitted EvmCtx Yul.
- Anvil compares the deployed EvmCtx size/hash to `cast codesize` / `cast codehash`, then verifies a
  nonexistent address returns size 0 and hash 0.
- EvmCtx target IR digest: `937893f551c87688`.
- solc 0.8.34 / Cancun artifact: 2,415-byte deployment bytecode; Yul SHA-256
  `febe9d370c31963d820122db60bed6e4fc1a7ae2ecb30060e0f24bedc9088ce8`; bytecode SHA-256
  `6c5e4d91b24eaff1763b407181143fd38d20b2e2068444c808fdc086cac1c27c`.

Raw `address.code` bytes remain fail closed because exposing them requires a separate bounded-memory
contract rather than another scalar environment query.
