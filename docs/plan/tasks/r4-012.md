# R4-012 — Add full-width EVM transaction context

## Goal

Close two Solidity global-environment gaps through the stable Environment Component boundary,
without adding another top-level operation, IR constructor, or main-emitter recipe.

## Delivered contract

- `Evm.Sdk.Context.origin : Address` exposes the complete 20-byte `ORIGIN` value in the existing
  allocation-free three-limb address representation. Its API documentation explicitly directs
  access-control code to prefer `Context.caller`.
- `Evm.Sdk.Context.gasPrice : UInt256` exposes the complete effective `GASPRICE` word rather than
  an implicit UInt64 truncation.
- Each opcode is observed once per source result. The target-owned Environment interpreter reuses
  its wide cache to project the remaining address or numeric limbs.
- Production extraction emits only `Component.environment` queries. The slice adds no allocation,
  storage write, call, raw source opcode, top-level Ops/IR constructor, or main Emit case.

## Evidence

- `Tests.EvmEnvironmentSpec` pins arity, limb bounds, Component ownership, one-opcode emission, and
  the current registry digest. `Tests.EvmCtxSpec` pins the contract-facing SDK delegation.
- The EvmCtx Anvil gate compares `origin()` with the full funded sender address and invokes
  `gasPrice()` through `eth_call` with an explicit 2 gwei gas price.
- EvmCtx target-IR digest: `2fcc4e438e1c4da1`.
- solc 0.8.34 / Cancun artifact: 2,964-byte deployment bytecode; Yul SHA-256
  `90a06f42bb810c72c177a14c0739ac659a60b73a8afbb20705cd0b52562f9c3a`; binary SHA-256
  `e7027a600072e25bf59ebaf5b16bab63d7aa3d30c7357c40ce4efe83c46b3d6f`.

`msg.sig` and a bounded `msg.data` view remain separate fixed-bytes / bounded-calldata contracts;
this slice does not imply arbitrary calldata access.
