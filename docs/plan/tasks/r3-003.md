# R3-003 — SVM invocation-local transient SDK

## Goal

Expose bounded invocation-local memory as reusable SDK contracts without inventing another
allocator, scratch planner, lifetime, source collection, or protocol-shaped emitter operation.

## Delivered contract

- `Svm.Sdk.Transient.HeapBuffer` fixes capacity, alignment, and compute-budget frame geometry,
  delegates reservation/OOM to the official-shaped downward `Heap.State`, and never represents
  persistent account state.
- `FixedVec` binds a fixed element width and capacity to exactly one heap buffer; `ByteWriter`
  binds header/count geometry, record capacity, and flush-before-overflow decisions.
- `SignedCpiCodec` composes the existing `Scratch.InstructionPlan` and `SignerSeedTail`. It does
  not wrap `Scratch.Plan`, duplicate `Scratch.Lifetime`, or create a parallel stack allocator.

## Real consumers

- `BatchRecorder.Config.transientWriter` is the source of truth for recorder heap capacity and
  writer validation; the existing recorder emitter reads that shared descriptor.
- dynamic signed self-CPI obtains instruction and signer-tail offsets from `SignedCpiCodec`.

Both integrations preserve the emitted program bytes. There is no new Ops, IR, Component, main
Emit case, persistent pointer, heap `Map`/`Array`, or claim that transient memory survives an
invocation. Persistent queues/maps/allocators remain fixed account-byte structures in
`Svm.Sdk.Storage`.

## Evidence

- Focused transient SDK, BatchRecorder, and CPI Lean checks pass; the aggregate `Tests` gate
  contains 283 jobs.
- All 54 SVM programs build and all 162 assembly/ELF/IDL artifacts are byte-identical to R3-002.
- Ownership and whitespace gates pass. Mollusk and Surfpool are not repeated because every SVM
  machine artifact is unchanged; deployment qualification remains Surfpool-only.
