# L5-047 — Correct Phoenix market/order sequence domains

## Goal

Correct the official Phoenix-v1 sequence layout before adding order placement. Keep the protocol
fix within the existing source composition and stable adapter/component/storage boundary.

## Delivered

- Corrected `MarketHeader.market_sequence_number` to absolute account word 34 (byte 272).
  FIFO body `order_sequence_number` remains at word 106 (byte 848).
- Updated the profile sequence view and official tags 4–9 so each successful reduce/cancel route
  reads the pre-increment market sequence from word 34, writes its successor to word 34, and passes
  the same pre-increment value to the audit batch header.
- Kept word 106 immutable across reduce/cancel. It remains the initialized FIFO order-key source
  that placement will consume; the existing storage envelope still rejects an uninitialized zero
  order sequence before mutation or audit.
- Split the Mollusk fixture constants into `MARKET_SEQUENCE_WORD` and `ORDER_SEQUENCE_WORD`.
  Raw tag tests now assert both the market increment and preservation of the order sequence,
  preventing the two state domains from being conflated again.
- Changed no generic Ops, IR, CFG, main-emitter case, component vocabulary, account-storage routine,
  heap behavior, or persistent container representation.

The stable boundary remains:

```text
source semantics -> EntryAdapter protocol plan -> bounded Component Query/Call
                 -> component-owned validation/effects/emitter -> AccountStorage -> sBPF
```
