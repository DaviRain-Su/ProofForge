# L5-049 — Reuse bounded returns and static storage handles

## Goal

Close Phoenix tag 3's official one-element Borsh `Vec<FIFOOrderId>` return ABI without adding a
protocol opcode or main-emitter case. Make statically shaped scalar products and fixed-width return
codecs reusable, and move Phoenix's concrete account schema above the protocol-neutral SVM storage
layer while retaining Solana's fixed-memory execution model.

## Delivered

- Added one extractor-owned scalar-result flattener. Nested Lean `Prod` values are compile-time ABI
  shape only: every leaf must already lower to a target-neutral scalar. Scalar methods retain the
  historical `okState` shorthand; multi-leaf success emits the existing sequence of `returnU64`
  operations, which Core CFG already joins into `returnU64s`.
- Generalized method return-count inference across bounded branches and stateful methods. SVM raw
  projection still removes managed `State` and now accepts one or more bounded scalar results. No
  new Core/SVM Op, IR node, CFG exit, EntryAdapter instruction, Component variant, or main-emitter
  case was added.
- Added generic raw-entry `returnWidths` metadata restricted to 1/2/4/8-byte scalar leaves. The
  EntryAdapter serializer writes those leaves into fixed eBPF stack scratch and calls
  `sol_set_return_data` with the compile-time byte count; the existing 304-byte scratch bound
  rejects oversized tuples. There is no runtime `Vec`, `Map`, product allocation, allocator call,
  pointer return, or persistent pointer, and the main SVM emitter only delegates to this codec.
- Added an independent exact 17-byte raw-entry probe,
  `09 || left:u64 || right:u64`, returning `left || right` as 16 little-endian bytes. Lean guards
  pin source metadata, target projection, `retCount = 2`, generic CFG `returnU64s`, and the existing
  SVM syscall path. Mollusk covers both the pair result and the error branch.
- Added tag 10 as a protocol-neutral `[4, 8, 8]` codec probe. It returns the exact 20 bytes of a
  one-element Borsh `Vec<(u64, u64)>`: `length=1 || left || right`.
- Changed Phoenix tag 3 success to the official 20-byte one-element Borsh `Vec<FIFOOrderId>`:
  `length=1:u32 || price_in_ticks:u64 || encoded_order_sequence_number:u64`. Bid and ask storage,
  collateral, sequence, audit, and rollback behavior are unchanged.
- Added `ProofForge.Svm.AccountStorage.Source` as the reusable source facade for static fields,
  key4 maps, FIFO maps, and their bounded mutations. Contract code supplies compile-time handles
  plus dynamic keys/values; extraction erases the handles into the existing target-owned
  `AccountStorage` component calls without adding top-level Ops or runtime geometry.
- Located the concrete Phoenix 512/512/128 schema in `Examples/PhoenixV1Layout.lean`, not under
  `ProofForge/Svm`. `Examples/PhoenixV1Profile.lean` consumes its named handles; the extractor uses
  only the generic `@[pf_inline]` opt-in and contains no Phoenix namespace special case.

The ownership path remains:

```text
example protocol schema -> AccountStorage.Source -> static AccountStorage descriptors
source result shape      -> Extract scalar leaves -> existing CFG returnU64s
                         -> EntryAdapter fixed-width codec -> fixed SVM stack scratch
                         -> sol_set_return_data
```

## Next

Keep this return path fixed. Extend the EntryAdapter's bounded schema data from the current strict
PostOnly packet to the remaining official `OrderPacket` shapes, then introduce component-owned
matching semantics in slices. Unsupported packet variants, time-in-force behavior, matching,
eviction, and remaining-account geometry continue to fail closed until their own bounded plans are
implemented.
