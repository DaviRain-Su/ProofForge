# R3-001 — Compose the persistent SVM SDK foundation

## Goal

Stop encoding each queue, map, and allocator as another protocol-shaped low-level recipe. Expose a
reusable Lean-facing `Svm.Sdk` surface that binds static Solana account geometry once and composes
the existing checked account-storage effects. Persistent state must remain fixed-capacity account
bytes and one-based scalar indexes; no native pointer, Lean `Array`/`Map`, or invocation-heap object
may survive across instructions.

This is the persistent-container foundation of R3, not completion of the whole SVM SDK. Account,
Signer, PDA, System, Token/Token-2022, and bounded transient Scratch facades remain separate work
over the R2 Runtime contracts.

## Delivered contract

`Svm.Sdk.Storage` and `Svm.Sdk.Queue` provide:

- POD word fields over explicit fixed-stride account regions;
- fixed-capacity one-based Vec and FIFO ring handles;
- four-word-key and ordered-pair Map/RBMap composition;
- a one-based bump/free-list allocator whose cursor and links stay in account words;
- canonical initialization that clears reachability headers while allowing stale payload bytes to
  remain unreachable.

Every handle is compile-time descriptor data. Extraction erases operations to the existing checked
`AccountStorage.Source` loads, stores, tree walks, and allocator routines. Expected empty/full/
missing boundaries return the `0` sentinel without mutation; malformed geometry, undersized data,
foreign ownership, or missing writability still abort in the target-owned checked stubs. No Ops,
IR, Component, Runtime, or Emit constructor was added.

JobQueue and TicketLine are independent non-Phoenix consumers. Their source `State` is runtime
account 0, while SDK persistence is runtime account 1, preventing extracted source fields from
aliasing container headers. JobQueue uses 21 words / 168 bytes. TicketLine reserves the complete
332-word static extent of its 16 × 18-word registry stride, including unreachable tail padding.

## Extraction ordering hardening

Nested `@[pf_inline]` storage reads and writes exposed a shared extractor defect: a scalar effect
producer hidden below an inline helper could be substituted and evaluated again after a later
write. The extractor now detects nested SVM effects, sequences dependent scalar producers through
CFG locals, and leaves branch-local lambdas deferred until their application is decoded. Direct
account-write expressions retain their existing contract of returning the stored value. A focused
fixture locks this behavior, and PhoenixV1Profile confirms that deferred continuation writes are
not falsely classified as immediate effects.

## Coverage

- JobQueue exercises canonical Vec initialization, append/read/update/pop/full behavior, allocator
  live count, bump cursor, free-list reuse, invalid free, and separate source/storage accounts.
- TicketLine exercises canonical FIFO and map initialization, ring wraparound, POD fields, ordered
  map insertion/lookup/removal, duplicate rollback, complete static account extent, and separate
  source/storage accounts.
- Full Phoenix and PhoenixV1Profile builds and Mollusk tests remain in the regression manifest,
  proving the generic extractor change did not alter their application ownership boundary.
