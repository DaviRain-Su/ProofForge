# R3-002 — SVM SDK Account and Signer facade

## Goal

Move fixed-account, required-signer, and bounded remaining-account access behind reusable
compile-time SDK handles, so applications stop repeating raw Runtime leaves and physical account
indexes without adding convenience opcodes or target emitter recipes.

## Delivered contract

- `Svm.Sdk.Account.Handle` names one fixed physical account and exposes header flags, lamports,
  data length, key/owner/data words, and the existing owned-by-self result convention.
- `Svm.Sdk.Signer.Handle` names a fixed required signer; `key0` erases to the existing signer-key
  leaf and therefore retains the target's pre-execution signer gate.
- `Svm.Sdk.Account.View` directly aliases the target-owned bounded view plan instead of duplicating
  source geometry. It exposes read-only runtime selection inside static `base/capacity` bounds.
- Trio consumes the fixed Account/Signer handles; AccountView independently consumes the bounded
  view. The old `Svm.AccountView.Source` wrapper is removed rather than kept as a second API.

All handles contain compile-time indexes or bounds only. They contain no account-data pointer,
heap object, runtime-selected geometry, or persistent state.

## Extraction boundary

The fixed account leaves previously accepted only source-level numeric literals even though
account-storage and bounded-view plans already accepted compiler-proven static values. The shared
extractor now uses the existing `asStaticLit` path for fixed account/key/owner metadata, allowing
`pf_inline` handle projections while still rejecting runtime indexes and values outside the
64-account/four-key-word/data-word bounds. Ops, IR, Component, Runtime, and Emit are unchanged.

## Evidence

- Focused Account/Trio/view Lean checks pass; the aggregate `Tests` gate contains 281 jobs.
- Trio and AccountView Mollusk suites pass 22/22, including missing account, signer, owner,
  runtime capacity, short-data, and atomic state-hold failures.
- All 54 registered SVM programs build, and every assembly/ELF/IDL artifact remains byte-identical.
- Ownership and whitespace gates pass.
