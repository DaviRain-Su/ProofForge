# R5-022 — Checked wide-to-UInt16 casts

Date: 2026-08-31
Status: done

## Goal

Extend the shared allocation-free SafeCast boundary from UInt32 to UInt16 through the existing
generic fixed-scalar `Except` path, without adding a target opcode, runtime effect, storage
operation, allocation scheme, or width-specific lowering recipe.

## Delivered contract

- `Core.SafeCast.UInt128.toUInt16` first requires `w1 == 0`; `UInt256.toUInt16` first requires
  `w1 ||| w2 ||| w3 == 0`. Both then require `w0 < 2^16` before the explicit narrowing conversion.
  The shared policy names the first non-representable value once. The helpers return the caller's
  typed error and perform no allocation, terminal, effect, or state write.
- R5-021's generic fixed-scalar `Except` bind is reused unchanged. UInt16 does not receive a new
  Ops, IR, CFG, Component, Runtime, or Emit case, and ordinary let/state/effect normalization is
  unchanged.
- Existing consumers were extended instead of adding single-use fixtures.
  `EvmSafeCastAccumulator.setBatch` is permissionless UInt256→UInt16 replacement with independent
  width and zero-policy errors. `EvmSafeCastConfig.setThreshold` applies owner authorization first,
  then UInt128 narrowing, zero policy, and one literal UInt16 state update. Existing UInt64 and
  UInt32 methods remain available, and both new paths preserve their fields.
- This slice deliberately does not publish UInt8 or signed casts without a consumer. Saturating
  casts, wide-to-wide downcasts, and a common arithmetic-error vocabulary remain separate
  consumer-driven work.

## Evidence

- Focused Lean truth tables cover exact UInt16 max, the first low-word overflow, and every upper
  limb. Extraction guards prove every upper-limb test and the exact `w0 < 2^16` gate dominate the
  narrowed local bind, and pin both updated state layouts, ABI, and IR digests. The focused gate
  passes 179 jobs; the aggregate Lean gate passes 411 jobs.
- `EvmSafeCastAccumulator` digest is `e8c6d328d71a6df7`; Yul is 8,621 bytes and deployment bytecode
  is 1,249 bytes. `EvmSafeCastConfig` digest is `8f7a99eb6205af12`; Yul is 16,560 bytes and deployment
  bytecode is 2,499 bytes.
- Dedicated Anvil matrices cover the UInt16 exact boundary, low-word `2^16` overflow, every upper
  limb, authorization/application-policy ordering, preservation of the existing UInt64/UInt32
  fields, and raw-storage atomicity after rejected transactions. The clean EVM build validates all
  40 registered contracts against the actual artifact manifest, and aggregate Anvil runs 40/40
  with no skips.

## Boundary

The cast helper is target-neutral pure policy, not a shared physical ABI or storage contract. EVM
consumers use canonical Solidity wide calldata and named errors; a future SVM consumer must qualify
its own entry/result plan. UInt16 remains a fixed scalar value rather than a heap allocation, and
no pointer, dynamic Map, unchecked truncation, or duplicated numeric sentinel is exposed to
contract applications.
