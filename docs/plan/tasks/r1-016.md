# R1-016 — SVM bounded Borsh bytes / String binding

## Goal

Bind the shared bounded byte and UTF-8 string contracts to canonical Solana Borsh input without a
heap collection, persistent pointer, new Runtime effect, or type-specific branch in the main SVM
emitter.

## Delivered

- `Svm.EntryAdapter.BorshDecode.boundedBytes` owns `u32 length || active bytes`, fixed UInt8 scalar
  locals, zeroed inactive slots, capacity checking, payload bounds, and exact cursor consumption.
- BoundedBytes and BoundedString retain distinct plan identities even though Borsh uses the same
  length/payload geometry for `Vec<u8>` and `String`.
- The adapter-owned String decoder validates strict Unicode-scalar UTF-8 over the contiguous wire
  payload before source code observes the fixed frame. It rejects stray continuations, overlong
  forms, surrogates, truncation, and values above U+10FFFF.
- `Examples.RawEntry` is the application-level consumer; no Phoenix or protocol policy entered
  `ProofForge/Svm`.

## Architecture

This is a target codec-plan interpreter extension, not a VM effect. Core Ops, target Runtime/IR,
Component, and the main SVM Emit recipe set are unchanged. The source Vector is erased into fixed
stack scalar slots; no address or collection header enters account state.

## Verification

- Focused Lean extraction/CFG/assembly-plan tests pass.
- `pf build --target svm RawEntry` assembles a 21,768-byte sBPF ELF; digest is
  `f1e0b094d591bd61`.
- RawEntry Mollusk passes 17/17, including bytes capacity/truncation/trailing failures and the full
  UTF-8 positive/negative matrix.
- Surfpool 1.5.0 deploys the exact ELF through Loader-v3 with 22 writes and verifies the deployed
  ProgramData account.
