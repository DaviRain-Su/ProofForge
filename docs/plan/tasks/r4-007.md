# R4-007 — Emit generic source custom-error ABI metadata

## Goal

Keep ABI metadata synchronized with the zero-argument named reverts already emitted from source
`Except` error constructors, without adding an ABI special case for each contract or changing the
Runtime/IR/Yul instruction surface.

## Delivered contract

- The ABI emitter collects every `IR.Op.errorNamed name` from all runtime entries and renders the
  matching `{"type":"error","name":name,"inputs":[]}` item.
- One reusable structured-op name collector follows both `ite` branches and bounded `forBody`
  bodies, preserves first-use order, and deduplicates names across branches and methods. Existing
  event-name collection now shares that traversal, and built-in component error detection also
  follows bounded loop bodies.
- Selector and ABI identity stay aligned: Yul already emits `keccak256("name()")[:4]`, while the
  new ABI item describes exactly `name()` with no arguments.
- Closed parameterized errors (`Insufficient(uint256,uint256)`, `Unauthorized(address)`) retain
  their existing typed ABI entries. This slice's generic IR leaf carries a name only and does not
  claim parameterized source errors; the later target-neutral typed-frame contract is R4-016.

No new source API, Ops/IR/Component/Runtime case, Yul recipe, allocator, or runtime memory is added.
This is compiler metadata derived from the existing target-owned IR.

## Evidence

- `Tests.EvmLogErrorSpec` injects nested `ite` and bounded `forBody` named-error leaves and proves
  both ABI entries are present exactly once in first-use order.
- `Tests.EvmStorageVecSpec` proves the real EvmVecLog artifact exposes `malformed()`/`oob()` and the
  EvmVecStack artifact exposes `malformed()`/`empty()`.
- Rebuilt artifacts contain those error items while EvmVecLog/EvmVecStack deployed bytecode sizes
  remain 2,492 B and 1,369 B. Yul, bytecode, canonical IR, and registry digests do not change.
