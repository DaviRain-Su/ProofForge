# R3-009 — SVM bounded static Memo facade

## Goal

Replace the application-visible fixed `"ok"` Memo recipe with one honest reusable static payload
contract. Keep payload lifetime and bounds explicit without introducing runtime strings, vectors,
persistent pointers, a Memo opcode, or another emitter path.

## Delivered contract

- `Svm.Sdk.Memo.Ascii.write payload` accepts a compile-time seven-bit ASCII literal of at most 512
  bytes. `Memo.writeOk` remains only as a compatibility delegate.
- `Svm.Memo.Ascii.wellFormed` is the single policy consumed by the SDK, extraction, and target Ops
  verifier. The verifier applies it only to the exact one-account Memo CPI geometry; `.ascii` words
  in other generic CPI instructions retain their existing contract.
- `Examples.Memo` selects `"ok"` at application level. A separate `"proof-forge"` extraction fixture
  proves that the facade is not a renamed fixed literal.
- Non-ASCII and 513-byte fixtures fail before emission. The 512-byte boundary is accepted.

There is no new Runtime effect, Op/IR/Component/Emit variant, application magic account list,
dynamic account table, heap container, or persistent pointer.

## Lifetime and fail-closed boundary

The literal is compiler-owned source data copied into the existing bounded CPI instruction plan for
one invocation. It never survives as a pointer and does not change account state layout. Runtime-
selected bytes, arbitrary UTF-8, payloads above 512 bytes, alternate account geometry, and Memo
program-id authentication remain unavailable rather than being represented as dynamic Lean values.

## Evidence

- Focused Memo SDK, program extraction, target verifier, and extraction suites pass positive
  `"proof-forge"`/512-byte and negative non-ASCII/513-byte policy cases.
- Memo assembly, ELF, and IDL are byte-identical to the fixed-facade baseline. Their SHA-256 values
  remain `f0c72ad82de301c7cfc3b2cf7b4e460bf574424eae06f427f8352f92917aa715`,
  `12a75a4341cf43e58ec97a2df4bb1ac6071b65484b685eb91ab5b641e291643a`, and
  `cc252e788a313c21d585377b1280b5d62353d56c3223fd145ad2a0f5f75aa17a` respectively.
- The aggregate `lake build Tests` gate passes 300 jobs. Mollusk and Surfpool are not repeated
  because the deployed machine program is byte-identical; Surfpool remains the only deployment
  qualification environment.
