# R3-010 — SVM general Associated Token Account facade

## Goal

Complete the official static Associated Token Account instruction surface without adding another
Runtime wrapper, target operation, or emitter recipe. Application contracts should name account
roles while the SDK owns the official wire discriminants and account privileges.

## Delivered contract

- `AssociatedToken.CreateAccounts` and `RecoverNestedAccounts` bind application-owned concrete
  CPI-relative handles to official roles. Their `wellFormed` gates enforce the static transaction
  account-lock ceiling.
- `createWith`, `createIdempotentWith`, and `recoverNestedWith` lower those roles through the
  existing generic `Runtime.invoke` effect. Fixed-account `create`, `createIdempotent`, and
  `recoverNested` remain available for the established external-account layouts.
- Create and CreateIdempotent share payer / ATA / wallet / mint / System / selected-Token roles and
  emit official discriminants 0 and 1. RecoverNested emits discriminant 2 and preserves the
  official nested ATA / nested mint / destination ATA / owner ATA / owner mint / wallet / selected
  Token order, including signer+writable wallet privileges.
- The old `Runtime.ataCreateIdempotent` policy wrapper is removed. ATA composition now has one
  source owner in the SDK and reaches the target only through generic invoke.

Both Token program and ATA program are caller-selected static accounts. This supports classic Token
and Token-2022 without silently substituting one program id for the other.

## Resource and fail-closed boundary

The role records are compiler-erased values. They do not create a runtime account list, dynamic
vector, heap map, persistent pointer, or copied account data. The invoked ATA program validates all
three canonical derived addresses and Token account ownership. ProofForge still does not claim
canonical ATA/Token program-id authentication or expose derived-address helpers; runtime-selected
account geometry remains unavailable.

## Evidence

- Extraction fixtures pin all three official discriminants, account ordering, signer/writable
  flags, fixed geometry, caller-selected alternate geometry, and the 64-account static ceiling.
- The existing Ata canonical IR digest remains `574dc90c21ca9723`; its assembly, ELF, and IDL remain
  byte-identical to the pre-slice baseline. Their SHA-256 values remain
  `25176346ea293f639d6ec3b28a0e8e2ceae4de319f787db151295d01ab3dd713`,
  `b3115aa6ac3d4c00ba0436e39a6c0fa95da5f0a74f603e6e0162b56b8e93a51f`, and
  `f5208b994f2d2101ad3dd7007b8bb72b672033fd71ff4b3fb88a38839d119d28` respectively.
- Aggregate Lean, ownership, whitespace, and Markdown-link gates pass. Mollusk and Surfpool are not
  repeated because the existing deployed Ata machine program is byte-identical; Surfpool remains
  the only deployment qualification environment.
