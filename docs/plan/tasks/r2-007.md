# R2-007 — Stabilize SVM sysvar component boundary

## Goal

Move the existing Clock, EpochSchedule, and compile-time Rent lowering behind the generic SVM
Component query bridge, so future sysvar fields extend one target-owned module instead of adding
more top-level Ops/IR/main-emitter recipes.

## Delivered contract

- `Svm.Sysvar.Query` owns the supported Clock fields (`slot`, `epoch`, `unixTimestamp`),
  EpochSchedule `slotsPerEpoch`, and compile-time `rentExemption` geometry.
- `Svm.Sysvar.Emit` is the sole production interpreter for the three official host functions and
  their fixed stack representation. The query has no account effect, allocation, source-visible
  pointer, or persistent state.
- Extract now lowers the existing `Runtime` / `Sdk.Sysvar` source facade to
  `Val.ext (.component (.sysvar ...))`. Generic SVM Ops, target IR, CFG, and the main emitter only
  traverse their existing Component bridge.
- Historical top-level value constructors remain as Legacy Golden compatibility input, but both
  their emission and production Component emission delegate to the same target-owned interpreter.
- Canonical identities and assembly remain unchanged: Clock, Epoch, and Rent preserve their
  registered digests, assembly, IDL, and ELF byte-for-byte.

This is an ownership refactor, not a new syscall capability. Remaining Clock/EpochSchedule fields,
signed timestamp interpretation, sliced generic sysvars, and runtime-selected Rent geometry remain
fail closed until separately modeled.
