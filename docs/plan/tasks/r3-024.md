# R3-024 — Generic whole-value boundary for SVM SDK records

Date: 2026-08-30
Status: done

## Goal

Let a reusable compiler-owned SDK value use the same logical static-record boundary as an
application record, instead of teaching Extract or the SVM emitter another type name. The first
consumer is the allocation-free four-limb `Svm.Sdk.Pubkey`: it must cross a raw entry and return
boundary as one canonical 32-byte value, with exact Borsh input/output and no key-specific
Runtime/Ops/IR/Component/Emit vocabulary.

## Delivered contract

- `@[pf_boundary]` is a representation-free opt-in for compiler-owned structures/inductives.
  The shared extractor still derives the complete finite schema and applies its existing depth,
  recursion, polymorphism, inheritance and resource checks. The marker chooses no Borsh/ABI,
  account, storage, heap, pointer, or allocation representation.
- Generic projection discovery recognizes fields owned by an attributed value. A direct static
  record result is scalarized to the same fixed source-leaf frame as other static aggregates;
  each target remains responsible for leaf widths, wire offsets, canonical guards and result
  publication.
- Only an explicitly `@[pf_inline]` bounded helper may unfold to an attributed constructor during
  result decoding. This keeps the reusable SDK value compiler-erased without making arbitrary
  compiler definitions transparent or adding a type-name dispatch arm.
- `Svm.Sdk.Pubkey` opts into this contract once. `matchesKey` and `matchesOwner` use direct field
  projections, so fixed literals, account projections and boundary-supplied values follow the
  same allocation-free path.
- `Examples.RawEntry.echoPubkey` accepts and returns exactly one Pubkey under raw tag 26: one tag
  byte plus four little-endian UInt64 input leaves, and four output leaves. Truncation and trailing
  bytes fail before source execution.
- `Examples.Keys.peerKey` is an independent consumer: it projects account 1's complete key and
  returns exactly the canonical 32 bytes under its own raw tag 26. It has no allocation, CPI or
  Pubkey-specific emitter recipe.

The ownership path is:

```text
@[pf_boundary] finite logical structure
                  │ generic static schema/projection frame
                  ▼
       SVM EntryAdapter static Borsh policy
                  │ exact four × 8-byte leaves
                  ▼
          existing CFG / return-data emitter
```

## Boundary

This slice does not create a general runtime aggregate object. Values remain a compile-time fixed
scalar frame; recursive/polymorphic/inherited or over-budget schemas fail closed. Nested dynamic
values, constructed tagged/wide dynamic results, persistent pointers, runtime-selected account
geometry and arbitrary allocation remain unsupported. EVM may consume the same logical marker
through its own static ABI policy, but this slice adds no fake cross-target wire format.
