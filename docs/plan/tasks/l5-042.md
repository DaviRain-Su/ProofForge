# L5-042 — Stabilize a reusable bounded SVM component bridge

## Goal

Stop widening generic Ops, IR, CFG traversal, extraction, IDL inference, and the main emitter for
every new account container or protocol helper. Establish one target-owned lowering boundary for
bounded Queue/Map/Allocator/Recorder-style components while preserving the current wire ABI,
canonical digest, assembly, and runtime semantics.

## Delivered

- Added `Svm.Component.Query` and `Svm.Component.Call` as the only value/effect bridge visible to
  generic SVM plumbing. The first registered backend is `AccountStorage`; future bounded backends
  extend the component-owned sum rather than top-level `ValKind`, `OpExt`, `IR.Op`, and main Emit.
- Centralized query/call operand arity and traversal, monadic value mapping, well-formedness,
  minimum-account inference, transitive account effects, canonical spelling, and the shared fixed
  scratch boundary at the component layer.
- Added `Svm.Component.Emit.Context` and `Backend`. The main emitter supplies generic value loading,
  owner/header access, account count, and backend capabilities once; component-owned dispatch then
  selects AccountStorage query/mutation lowering.
- Migrated extraction preservation/normalization/escape analysis, target projection, CFG payloads,
  signer/account walk, IDL writable inference, and tests from `.accountStorage` to one `.component`
  case. Write-sensitive extraction now uses `call.effects.writes` rather than assuming every
  component mutates account data.
- Kept source helpers and canonical spelling unchanged. Component query emission is guarded to be
  byte-for-byte equal to direct AccountStorage emission, and source lowering is guarded to produce
  only `.component (.accountStorage ...)`.

The intended boundary is:

```text
source semantics
  → fixed-memory bounded Component Query/Call
  → component-owned validation/effects/emitter
  → sBPF
```

This is not an unrestricted dynamic object system. Persistent containers remain compile-time
fixed account regions with one-based indexes and zero sentinels. Invocation-local containers may
later use the official bounded downward bump heap, but their capacity/OOM behavior must be explicit
and no heap pointer may escape the invocation or be written to an account.

## Verification

- Target component/Ops/extraction/Phoenix guards pass, including direct metadata delegation,
  component-only IR lowering, and byte-identical query emitter delegation.
- `lake build Tests` passed all 202 jobs; all 51 registered SVM programs built.
- The full locked Mollusk suite passed 247/247; all 12 EVM programs built and passed Anvil 12/12.
