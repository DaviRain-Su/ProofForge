# R1-018 — SVM bounded Borsh return binding

## Goal

Bind top-level shared bounded values to canonical Borsh return data without assuming input cursor
geometry, creating a target collection, or adding collection recipes to Runtime, Ops, IR, or the
main emitter.

## Delivered

- `Svm.EntryAdapter.BorshReturnPlan` independently describes bounded-array and packed-byte output
  policy. Input `BorshDecode` plans remain unrelated and cannot alias output geometry.
- Extract projects returned `BoundedVec`, `BoundedBytes`, and `BoundedString` values to a fixed
  `UInt32 length + capacity slots` source frame. Both directly returned values and explicitly
  constructed bounded values use that one target-neutral representation.
- The target encoder publishes only canonical `u32 length || active prefix`, rejects lengths above
  capacity, and uses disjoint staging/output stack regions so expression scratch cannot corrupt
  returned bytes.
- String output runs the strict Unicode-scalar UTF-8 gate immediately before
  `sol_set_return_data`, independently of input validation.

## Boundaries

This slice supports top-level bounded returns whose element is one scalar limb. Nested dynamic
values, tagged dynamic returns, wide/aggregate elements, and generated aggregate ABI remain fail
closed. No host Vector, pointer, heap collection, or inactive-capacity bytes enter return data.

## Verification

- Lean extraction/IR/CFG/assembly guards cover all three plans, constructed bounded results,
  exact fixed-frame counts, fail-closed schema shapes, dynamic return lengths, and UTF-8 markers.
- RawEntry digest is `be5151d71eff6bba`; the Loader-v3 ELF is 43,520 bytes.
- Mollusk passes 19/19 RawEntry tests, including empty/partial/full values, exact UInt16 and byte
  prefixes, output-only valid String construction, over-capacity length, overlong UTF-8,
  surrogates, truncation, stray continuations, and values above U+10FFFF.
- Surfpool 1.5.0 deploys and invokes the exact RawEntry Loader-v3 artifact.

## Next

Implement EVM bounded dynamic output as an independent ABI output plan: standard offset/length,
active words or packed bytes, zero padding, fixed source frame, and output-side strict UTF-8.
