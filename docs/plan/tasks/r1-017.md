# R1-017 — EVM bounded ABI bytes / string binding

## Goal

Bind the shared bounded byte and UTF-8 string contracts to standard Solidity ABI input without
reusing Borsh geometry, allocating a target collection, or adding a protocol recipe to Runtime,
Ops, IR, or the main EVM emitter.

## Delivered

- `Evm.Codec.DynamicInputPlan` is the single target-owned extension boundary for dynamic ABI
  inputs. Its sum type prevents one parameter plan from claiming incompatible tail geometries.
- Packed Bytes v1 maps `BoundedBytes capacity` and `BoundedString capacity` to one canonical head
  offset plus `length || packed bytes || zero right-padding`, while source code sees only a fixed
  `UInt32 length + capacity × UInt8` local frame.
- The codec interpreter rejects noncontiguous offsets, over-capacity lengths, short/trailing tails,
  and nonzero ABI padding. String additionally validates strict Unicode-scalar UTF-8 before source
  execution.
- ABI selectors and JSON use the standard Solidity names `bytes` and `string`; bytes and String
  retain distinct canonical policy identities.

## Architecture

Core owns only bounded logical values and UTF-8 laws. EVM owns ABI offsets, words, packed bytes,
padding, and calldata cursor rules. `Examples.Evm.EvmBounded` is the application consumer; no
application policy entered `ProofForge/Evm`.

## Verification

- Focused extraction, IR-policy, Yul, ABI JSON, and cross-target plan guards pass.
- `pf build --target evm EvmBounded` passes through solc 0.8.34; digest is
  `5d657469be1ed0fd`, deployment bytecode is 1,421 bytes, and ABI JSON is 932 bytes.
- Anvil accepts empty/partial/full bytes and ASCII/2/3/4-byte/full-capacity UTF-8 String inputs. It
  rejects wrong offsets, over-capacity, short/trailing tails, nonzero padding, overlong UTF-8,
  surrogates, truncation, stray continuations, and values above U+10FFFF.

## Next

Keep dynamic constructors, bounded returns, nested dynamic values, and frames above 64 scalar
locals fail closed. The next codec slice should define bounded output policy independently rather
than assuming input-tail geometry is reusable.
