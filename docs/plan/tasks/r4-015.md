# R4-015 — Add Cancun blob environment observations

## Goal

Expose Solidity's Cancun blob context through the stable Environment Component boundary without
adding raw opcodes, top-level IR cases, or transaction-owned dynamic blob data to source programs.

## Delivered contract

- `Evm.Sdk.Context.blobBaseFee : UInt256` observes the full `BLOBBASEFEE` word once and projects
  its four allocation-free numeric limbs through the existing Environment cache.
- `Evm.Sdk.Context.blobHash (index : UInt64) : Bytes32` observes `BLOBHASH(index)` once and
  projects the result in source-order fixed-byte limbs. An absent/out-of-range transaction index
  preserves the VM's canonical zero hash.
- The runtime remains read-only: no allocation, storage, log, external call, calldata pointer, or
  blob payload enters source state. The existing solc 0.8.34 assembly path already pins Cancun.
- Generic Ops, target IR, CFG, and the main EVM emitter gain no blob-specific constructor; only the
  target-owned Environment query vocabulary/interpreter is extended.

## Evidence

- `Tests.EvmEnvironmentSpec` pins arity/limb bounds, Component ownership, and one opcode observation
  per four-limb result; `Tests.EvmCtxSpec` pins the SDK delegation and result shapes.
- The EvmCtx Anvil gate verifies positive `BLOBBASEFEE` and the exact zero `BLOBHASH(0)` for an
  ordinary non-blob call.
- EvmCtx target-IR digest: `b4a1d16740330566`.
- solc 0.8.34 / Cancun artifact: 3,802-byte deployment bytecode; Yul SHA-256
  `7b700df618d63fa343bd6cc22829e621c9f5acbb8776499dd58dbcb323be40a3`; binary SHA-256
  `7b9a57ddee06be7727dc4efac75f92ea2e3991faed43f575bc732163aaeaeec8`.
