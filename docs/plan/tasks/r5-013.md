# R5-013 — Integrate the bounded EVM ERC-721 core

## Goal

Finish integration of the already merged `Evm.Sdk.Erc721` slice so the aggregate EVM gate and
the authoritative Runtime/SDK plan describe what is actually available. Keep the supported
token-id and ABI surface honest rather than claiming full ERC-721 parity.

## Delivered contract

- `Evm.Sdk.Erc721` composes existing compile-time hashed-map handles for token ownership,
  per-token approval, operator approval, and per-owner UInt64 balances. Mint, transfer, and burn
  remain O(1); applications own authorization, pause, event ordering, and terminal policy.
- The current owner/approval maps reuse the three-limb Address key shape. A token id is therefore
  accepted only when its top UInt256 limb is zero. Views, authorization, and mutations reject an
  unencodable id before `tokenKey` truncation, preventing `id + 2^192` from aliasing a live token.
- Collectible and Badge are independent consumers. Together they cover owner mint, per-token
  approval, approved-spender transfer, operator approval/transfer, burn, duplicate mint, zero
  recipient, authorization failure, approval clearing, and balance movement.
- The aggregate Anvil runner now executes both contracts. The EVM aggregate is 26 registered
  builds and 26/26 Anvil cases; `lake build Tests` is 349 jobs.

## Ownership and resource boundary

No Runtime leaf, Ops/IR/Component/Emit recipe, runtime allocator, selector, topic, account offset,
or storage-slot magic was added. Every physical namespace comes from `Storage.Layout` and every
write remains an explicit existing hashed-map effect.

This is a bounded core, not a full ERC-721 claim. Standard Address-typed owner/approval returns,
full 256-bit token ids, typed standard events, metadata, and safe-transfer receiver callbacks
remain fail closed. R5-014 subsequently integrated a separate bounded single-id ERC-1155 core.

## Evidence

- `Tests.EvmErc721Spec` checks the encoding ceiling, key/address packing, disjoint map namespaces,
  and both live extraction digests.
- `runtime-tests/evm/anvil_collectible.sh` and `anvil_badge.sh` cover the two consumer matrices,
  including unencodable alias rejection.
- `lake build Tests`, `lake exe pf -- build --target evm --out build/evm`, and the aggregate
  `runtime-tests/evm/anvil.sh` pass on the integrated main workspace.
